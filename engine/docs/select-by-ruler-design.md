# 고르는 자 첫 판 — 비서 말투 (설계·판정식, 11-23 잠금)

사장님(11-23): *"판단만 하면 안 되구나 — 결정·선택도 해야지."* → 재고: `rulers-as-selectors.md`.
사장님 확정(11-23 14:0x): 글 갈래 · 싼 AI ×5 + 자가 고름 vs 비싼 AI ×1 · 이긴 것 = 말투 점수 ≥ 비싼 쪽 & 값 ≤ 절반 · 돈 1~2천 원.

## 물음

자(기계, 공짜)가 있을 때 **싼 AI 를 여러 번 부르고 자가 고르면** 비싼 AI 한 번을 이기나?

## 재료

`engine/tools/voice_live.mts` 의 사장님이 실제로 쳤던 말 8개 + 같은 일감(지금 사실) + `secretaryNote()`(비서 말투 지시·예시).
조건 B(비서 말투) 프롬프트 하나만 쓴다 — 지시문 효과는 10-26 에 이미 쟀다.

## 팔 셋 (말마다 3번 반복 → 각 24답)

| 팔 | 내용 |
|---|---|
| S1 | luna 1번 (기준) |
| **S5** | luna 5번 → `checkVoice` 로 어긴 칸이 가장 적은 답 하나. 같으면 먼저 온 것 |
| B1 | gpt-5 1번 |

- 모델: `gpt-5.6-luna`, `gpt-5`. 같은 provider(`createOpenAIProvider`, 구조화 출력 `{답}` 하나, maxTokens 16000).
- S1 은 S5 의 첫 답을 그대로 쓴다(따로 부르지 않는다 — 같은 분포, 돈 절약).
- 값: `costOf` 로 실제 토큰에서.

## 자 둘

1. **말투 자(고르는 자)** = `checkVoice` + `voiceScore`. 통과 = 어긴 칸 0.
2. **사실 자(감시 자, 고를 때 안 씀)** — 말투만 맞추고 내용이 빠지는 것을 잡는다. 일감에서 나오는 사실, 낱말 중 하나라도 있으면 맞음:
   - "연결 됨?" · "왜 안 됐어" → `laptop_jobs` 또는 `테이블`
   - "배포 됐어?" → `17`
   - "돈 얼마 썼어?" → `0.19`
   - "MCP 끝난 거 맞아?" → `16` 또는 `339`
   - "할 거 정리" · "뭐 해야 돼" → 손 셋(`SQL`/`schema_laptop_jobs`, `railway`, `시크릿`) 중 둘 이상
   - 잡담 → 못 잼(안 셈)
   - 자의 이빨: `--sabotage` 로 사실이 빠진 답을 넣어 떨어지는지 먼저 본다.

**한계를 먼저 적는다:** S5 는 말투 자로 골랐으니 말투 점수가 오르는 건 당연하다. 이 판이 보는 건
"고르는 게 비싼 모델을 대신할 만큼 싸고 충분한가" 이고, 자가 사람 눈의 "비서 같다" 를 대신하는지는 **못 잰다** —
그래서 고른 답 8개를 사장님이 읽을 수 있게 파일로 남긴다.

## 판정식 (잠금)

- **이김:** S5 말투 통과 수 ≥ B1 말투 통과 수 **그리고** S5 값 ≤ B1 값 × 0.5
- **덧붙인 지킴(내가 더함):** S5 사실 맞음 수 < B1 사실 맞음 수 − 2 이면 "말투만 이김" 으로 적는다(이김으로 안 적는다).
- 못 닿은 호출(오류)은 어긋남이 아니라 못 잼. 한 팔이라도 못 잼이 4개(1/6) 넘으면 그 판은 무효.

## 돈

어림 $0.5~0.6(luna 120번 ≈ $0.1, gpt-5 24번 ≈ $0.45). **상한 $1.4(≈ 2천 원) — 넘으면 다음 호출을 안 한다**(끄는 게 아니라 안전장치). `GENESIS_SPEND=i-approve` 필수.

## 순서

1. `--mock` 판(모델 0, 돈 0)으로 끝까지 돌아 판정식까지 나오는지.
2. `--sabotage` 로 사실 자가 떨어뜨리는지.
3. 사장님 OpenAI 충전 → 본판.

## 다시 잠금 (11-23 14:1x, 본판 전) — 싼 AI 만

사장님: *"싼 에이아이 쓰자"* → *"같이 하자"*. OpenAI 충전금 0, DeepSeek 잔액 $3.59. 비싼 팔(B1)을 뺀다.

- 싼 AI = **DeepSeek `deepseek-chat`**(10-26 voice_live 와 같은 길, temperature 0.7, max_tokens 700). 답은 글 그대로(구조화 안 함).
- 팔: **S1**(5번 중 첫 답) · **S5**(5번 → checkVoice 가 고름). 말마다 3번 → 각 24답. 사실 자는 그대로(고를 때 안 씀).
- **판정식:** S5 말투 통과 − S1 말투 통과 **≥ 6** (24 중 1/4) **그리고** S5 사실 ≥ S1 사실 − 2 → "고르기가 이김". 말투만 6 이상 오르고 사실이 3 이상 떨어지면 "말투만 이김". 나머지 "못 이김".
- 값: S5 는 S1 의 5배가 당연하다 — 숫자로 같이 적는다. 상한 $1.4 그대로.
- 무효: 한 팔이라도 못 잼 > 4. DeepSeek 이 이 기계에서 안 닿으면(예전 차단 기록) 판 전체를 "못 잼" 으로 적고 멈춘다.

## 다음 대상 정찰 — 두근도트 영어 첫 답 (11-23 21:5x 잠금, 돌리기 전)

사장님 "ㄱㄱ 2번". 쌓인 실제 답으로 찾은 후보(영어 답 한글 섞임 32%)는 **영어 기본(11-22) 전의 옛 답**이었다 — 그 뒤로는 0/6, 표본 7개라 못 잰다(`dot_oneshot_fails --since=2026-11-22`).
그래서 **운영과 같은 길로 새 답을 뽑아** 한 번 답이 기계 자에 얼마나 떨어지는지 잰다. 이건 고르기 실험이 아니라 대상 고르기다.

- 길: `prepareTurn`(운영 지시문 그대로, 개발자 링크 `무제한` — 하트·DB 쓰기 0, 새 손님 id 라 사이 1단계·지난 대화 0) → DeepSeek `deepseek-v4-flash`(운영과 같은 모델·json_object·생각 끔) → `tidyReply`(저장 전과 같은 손질).
- 재료: 공개 캐릭터 전부 × 영어 첫마디 3개(고정 목록, 도구 안에 적음). 캐릭터 10명이면 30답.
- 자: `dot_reply_rules.mts` 의 영어 자 그대로 + **첫 답에서 이름을 묻나**(지시문이 "이번 답에서 이름을 묻는다" 고 시킨다 — `?` 가 있고 name/call 낱말이 있으면 물음).
- **대상 고르는 식(잠금):** 떨어지는 비율이 **20% 이상**인 자 중 가장 높은 것 → 다음 고르기 판의 대상. 20% 미만뿐이면 "이 길도 천장" 으로 적고 고르기 판을 안 연다.
- 돈: 30번 ≈ $0.01. 상한은 위 $1.4 에 같이 센다.
