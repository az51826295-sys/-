# "엔진이 혼자 다 만든다"의 게이트 v0 (초안 — 사장님 승인 대기)

작성 2026-08-27 00:1x. 사장님 지시(00:1x):

> 일단 우린 아직은 안 만들 거야. **니가 생각했을 때 그 엔진이 혼자서 다 만들 수
> 있겠다 생각하면** 그때 새롭게 내가 2D 게임을 만들 거야. 솔직히 돈을 안 써서
> 그런지 2D 니가 뽑은 거 퀄리티는 낮아. 근데 아직 완성도 되지 않았으니까.

게임 제작은 **보류**다. 그리고 재개 조건이 **내 판단**이라면, 그 판단은 느낌이
아니라 **판정식**이어야 한다. 이 문서가 그 판정식의 초안이다.

## 0. 먼저 정직하게 — 퀄리티 지적이 맞다

지금 우리 심판은 **규격만** 본다. 통과율 0.98은 "격자·획 굵기·팔레트·크기를
지켰다"이지 **"보기 좋다"가 아니다.** 취향 심판은 두 번 다 NO-PROMOTE였고,
그 관문이 달성 가능한 숫자인지조차(천장) 아직 안 쟀다.

그러니 "퀄리티가 낮다"는 말에 우리 계기판은 **아무 대답도 못 한다.**
게이트의 절반은 이 구멍을 메우는 것이다.

돈 이야기도 같다. 우리는 **가장 싼 티어(claude-haiku-4-5)** 로만 뽑아왔고,
더 비싼 모델이 실제로 나은지 **한 번도 안 쟀다.** 이건 감이 아니라 실험으로
답할 질문이다(§3).

## 1. 다섯 층 (전부 통과해야 "혼자 만든다"고 말한다)

| 층 | 조건 | 지금 |
|---|---|---|
| **① 규격** | 자산 종류 **3종**(아이콘 SVG · 타일 PNG · 캐릭터 스프라이트)에서, 사람 손 0·후처리 0으로 반입 오라클 통과율 **≥ 0.80**(종류마다 호출 ≥ 20, 호출 단위 구간의 하한 기준) | 아이콘만 있음. 예시 3개일 때 0.909 [호출 단위 미측정] |
| **② 취향** | 취향 심판이 관문을 통과해 **승격**(현재 규격: 적중률 ≥ 0.75, 순열 p < 0.05). 그 전에 **천장(test–retest)** 이 0.75 이상 가능함을 확인 | **안 섰다.** 2회차 NO-PROMOTE, 천장 미측정 |
| **③ 세트** | 세트 12개가 획 굵기 분산 0 · 시각 무게 폭 ≤ 0.15 · 구조 중복 0 | 부분(획 굵기·중복만 구현, 시각 무게는 래스터로 잼) |
| **④ 조립** | 뽑은 자산이 게임에 들어가 **헤들리스 적재 오류 0** + 이동·충돌 스모크 테스트 통과 | 프로토타입은 돎(오늘 확인). 자동 조립·스모크는 없음 |
| **⑤ 지속** | 위 넷을 **개입 0**으로 유지한 채 세트 하나를 끝까지(설계도 → 자산 → 조립) 굴린다 | 없음 |

②가 서지 않으면 나머지가 다 서도 **"혼자 만든다"고 말하지 않는다.** 규격만
지킨 자산을 잔뜩 만드는 것은 오늘 이미 되고, 사장님이 낮다고 하신 건 바로 그
결과물이기 때문이다.

## 2. 이 게이트가 스스로 무너지지 않게

- 문턱을 결과를 보고 옮기지 않는다(`docs/measurement-rules.md` §4).
- 표본 단위는 **호출**이다(§1). "후보 100개 중 95개 통과"는 근거가 아니다.
- 후처리(스냅)를 켜면 통과율의 뜻이 바뀐다 — **①은 후처리 0 기준**이고,
  후처리분은 따로 센다.
- ②의 관문을 내가 낮추지 않는다. 천장이 낮게 나오면 **관문을 다시 등록**하되,
  그건 사장님 결정이다.

## 3. 그래서 밤·낮에 내가 밀 것 (게임을 만들지 않고)

| 순서 | 일 | 막는 것 |
|---|---|---|
| 1 | **모델 티어 비교** — 같은 스펙·같은 개념으로 haiku vs 상위 티어. 호출 단위, 통과율 + 위반 분포 | "돈을 안 써서 퀄리티가 낮다"가 참인지. **지출 상한이 풀려야 함** |
| 2 | **취향 천장(test–retest)** | ② 전체. 사장님 15분, 08-29 이후 |
| 3 | **타일·캐릭터 반입 오라클** 세우기 | ①의 나머지 두 종류 |
| 4 | **세트 층 계측 마감**(시각 무게) | ③ |
| 5 | **자동 조립 + 스모크 테스트**(Godot 헤들리스) | ④ |

①③④⑤는 내가 지출 없이 대부분 민다. **②만은 사장님 손이 필요하고, 그게 제일
크다.**

## 4. 내가 언제 "됐다"고 말할까

다섯 층이 전부 초록이고, 마지막에 **세트 하나를 개입 0으로 끝까지** 굴린 기록이
있을 때. 그때 이 문서에 그 기록의 경로를 적고 사장님께 보고한다.
그 전에는 "될 것 같다"고 말하지 않는다 — 오늘 밤 배운 것이 정확히 그거다.

## 5. 진척 스냅숏 (2026-08-27 10:0x) — 사장님 질문 "몇 퍼센트냐"

느낌으로 답하지 않기 위해 **층별로 근거를 붙여** 적는다. 이 표는 날짜를 달고
갱신한다(한 번 쓰고 마는 숫자가 아니다).

| 층 | 진척 | 근거 (측정된 것) | 비어 있는 것 |
|---|---|---|---|
| **① 규격 3종** | **40%** | 아이콘: 통과율 측정 완료(예시 0개 haiku 0.276 / sonnet 0.870 / opus 0.972, 호출 18씩 · 예시 3개 0.909). 타일·캐릭터: **자를 오늘 만들었다**(이음새·방향 일관성) | 타일·캐릭터의 **문턱 미동결**, 그리고 **생성 경로 없음**(PixelLab 발주 필요) → 통과율 미측정 |
| **② 선별이 굴러가는가** (14:1x 재정의: 옛 정의 "취향 심판 승격" = **15%**) | **70%** | ②-1 선별 기록(계약) **충족** · ②-2 기계는 안 고름(계약, 테스트 강제) **충족** | ②-3 **세트당 선별 시간 미측정**(문턱도 미동결). 취향 심판 자체는 **영구 human_gate**로 선언됨 — 장기 목표는 적중률 0.40(사람 천장), 현재 벤치 0.25 |
| **③ 세트 일관성** | **85%** (10:4x 갱신) | 아이콘 세트 판정 + **타일·캐릭터 세트 계측**(크기 균일 계약, 세트 팔레트·최악 이음새·캐릭터 키 폭) | 세트 색 상한·이음새 문턱 **미동결**(사장님 몫), 음악 세트는 그대로 |
| **④ 조립·스모크** | **100%** (11:0x 갱신) | 스모크 PASS + 아이콘 8/8 + **캐릭터 28/28 바이트 일치 확인** + 타일 크기 확인. 아이콘·캐릭터 어느 쪽이든 하나 빠지면 게임이 **FAIL** | (타일이 자리표시자라는 것은 ①의 문제이지 조립의 문제가 아니다 — 선언에 명시) |
| **⑤ 개입 0 완주** | **50%** (13:1x 갱신) | 여덟 칸 완주 시도 3회(목·haiku·opus). **opus에서 수리 0·미정 0**, 남은 개입은 승인 2 + 선별 1 | 선별(구조적, ②가 풀려야 함) · 8번 칸이 **새 자산을 넣지 않고 기존 것만 확인** · 1회차 |

**단순 평균 34%** → **③④** 47% → **②** 48% → **⑤** 58% → **②재정의 69%** (2026-08-27 14:1x).

> **69%를 읽는 법**: 마지막 11%p는 **정의가 바뀌어서** 올랐다(취향 심판 승격 →
> 선별이 굴러가는가). 옛 정의로 재면 여전히 58%다. 두 숫자를 같이 적는 이유는
> "언제 무엇 때문에 올랐나"가 나중에 답이 돼야 하기 때문이다.

> **주의**: 48%는 쌓인 일의 비율이다. 게이트는 논리곱이고 ②가 **중단**됐으므로,
> 지금 정의로는 **몇 퍼센트를 더 쌓아도 게이트가 닫히지 않는다.** 닫으려면
> ②의 세 갈래(2회차 실행 / 관문 재정의 / human_gate 선언) 중 하나를 사장님이
> 고르셔야 한다.

| 갱신 | 층 | 전 → 후 | 무엇이 바뀌었나 |
|---|---|---|---|
| 10:2x | ④ | 50 → **90%** | 아이콘 자동 조립이 붙었다. 선별 기록이 정한 8개가 PNG로 나가 게임에서 8/8 적재되고, 하나만 빠져도 스모크가 FAIL |
| 10:4x | ③ | 70 → **85%** | 타일·캐릭터를 세트로 재기 시작. 오디션 타일 세트 팔레트가 40색(낱장 상한 24)이라는 사실이 처음 보였다 |
| 11:0x | ④ | 90 → **100%** | 조립이 **선언**(data/game_assembly.json)에서 나온다. 캐릭터 28/28이 오디션 원본과 바이트까지 같다는 것이 증명됐고, 하나만 빠져도 게임이 FAIL |
| 11:4x | ② | 10 → **15% · 중단** | 재현율 0.40을 쟀다(무작위 0.167보다 높다 = 취향은 있다). 그러나 관문 0.75 달성 가능성은 미확정이고, 사장님 지시로 **여기서 멈춘다** |
| 13:1x | ⑤ | 0 → **50%** | 완주를 처음 시도했다. opus로는 **수리 0·미정 0**으로 게임 직전까지 간다. 막는 것은 **선별 하나**이고 그건 ②가 풀려야 사라진다 |
| 14:1x | ② | 15 → **70%** | 사장님 결정(C+A): 취향을 **영구 human_gate**로 선언하고 ②를 "선별이 굴러가는가"로 재정의. **오른 것은 능력이 아니라 정의다** — 옛 정의 기준은 여전히 15% |

### 그런데 이 34%를 그대로 읽으면 안 된다

게이트는 **다섯이 전부 초록이어야** 하는 논리곱이다. 그러므로 진척은 평균이
아니라 **가장 약한 고리**가 결정한다. 지금 병목은 ②(10%)와 ⑤(0%)다.

- ②는 **사장님 15분**(test–retest)이 없으면 아예 못 움직인다. 그 전에는 세 번째
  NO-PROMOTE도 심판이 아니라 계측 한계를 재는 것이 된다.
- ⑤는 ①~④가 서기 전에는 시도 자체가 의미 없다.

그래서 정직한 한 줄은 이것이다:

> **"규격·조립은 절반을 넘겼고, 취향은 아직 시작 못 했다. 34%는 쌓인 일의
> 비율이지 완성 확률이 아니다."**

### 이 숫자를 올리는 것 (효율 순)

| 무엇 | 올리는 층 | 비용 |
|---|---|---|
| test–retest 15분 | ② 10 → 40%대 | 사장님 15분, 지출 0 |
| 타일·캐릭터 문턱 동결 | ① 40 → 60%대 | 사장님 20분(실측값은 문턱표에 있다) |
| 자동 조립(아이콘 → 게임) | ④ 50 → 90%대 | 내 몫, 지출 0 |
| 타일·캐릭터 **생성** 1회차 | ① 60 → 80%대 | PixelLab 발주(외부 지출·승인) |
| 세트 하나 완주 시도 | ⑤ 0 → 측정 시작 | 위가 서야 의미 있다 |
