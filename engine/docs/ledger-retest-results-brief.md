## 1. 배경과 질문

Rookery 엔진은 GitHub 실제 이슈를 받아 모델 에이전트(도구 루프,
12스텝)가 버그를 고치고, 재현 테스트 fail→pass + 감사 불변식 통과
시 채택한다. 모델 계층은 fast(Haiku 4.5, 싸다)와 smart(Sonnet 5,
비싸다). 기본 라우팅은 "fast 1차 → 실패 시 smart 2차".

"경험 원장"은 과거 과제들의 결말(계층·채택 여부)을 기록해 두고,
**fast의 1차 성공률이 낮다고 측정되면(n≥8, 승률<0.5) 처음부터
smart로 보내는** 장치다. 프롬프트에는 아무것도 주입하지 않고 선택
(라우팅)에만 작용한다 (이전 시리즈에서 제안 측 정보 주입은 효과가
없었기 때문).

질문(월 3의 미결 항목): **원장은 같은 해결을 더 싸게 사는가, 아니면
fast가 이길 기회를 없애는가?** 보드게임 세계의 같은 실험은 천장
효과로 식별 불가였다. 이번엔 실전에서 다시 물었다.

## 5. 해석

fast의 실제 1차 승률은 1/13 = 7.7% — 시드(5.9%)의 예측은 맞았다.
그런데도 smart 직행이 이득을 못 본 이유는 **실패의 가격**이다.
이 코퍼스는 두 계층 모두 대부분 실패하는 대역(9/13)이라, smart
직행은 과제마다 fast 시도 비용($0.17)을 아끼는 대신 smart 두 번
($1.0~1.6)을 쓴다. 라우팅 규칙이 "fast가 이길 확률"만 보고 "fast가
져도 싸다"는 비대칭을 안 봤다. fast 시도가 smart 시도의 ~15%
비용이면 fast 승률이 ~13%만 돼도 fast 선행이 싸다 — 측정값 7.7%는
경계 근처.

부수 관찰: 하루에 세 번 런을 돌리며 원장·감사·위생 규칙이 잡아낸
것들(전부 사람 개입 없이 기록으로 남음): 에이전트 스크래치 파일
혼입 차단, 구문 파손 기각, 크레딧 소진의 정확한 시각과 호출. 판정
제도 쪽은 이번 날이 가장 큰 스트레스 테스트였고 버텼다.
