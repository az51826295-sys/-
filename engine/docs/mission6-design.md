# 실험 6 설계 — 프로토콜 발견 (사전 등록)

작성일: 2026-07-30. 상태: 사전 등록. 브랜치:
`experiment/mission6-protocol-discovery`. Series 1은 `mission-world-v1`
태그로 동결됨 — 이 실험은 시리즈 2의 시작이다.

핵심 질문 (사용자 확정):
> AI 개체 집단이 실패 경험만을 바탕으로, 인간이 직접 제공하지 않은
> 협력 프로토콜을 생성·채택·일반화할 수 있는가?

성공 기준은 성능 향상이 아니다. **생성 → 채택 → 인과 기여(제거 시
하락) → 일반화(미관측 seed·미관측 여유율)**의 4중 조건이며, 최종
판정문은 다음으로 고정한다:

> 인간이 직접 제공하지 않은 집단 조정 규칙이 실행 과정에서 생성되고,
> 집단적으로 채택되었으며, 제거 실험에서 성능 기여가 확인되고, 미관측
> 환경에도 일반화하면 프로토콜 발견에 성공한 것으로 판정한다.

## 1. 비교군

| 군 | 정의 |
|---|---|
| C | 자유 협력 (동결본 그대로). 학습·규칙 변경 없음 |
| I2 | 인간 설계 하강 문턱 프로토콜. **탐색 공간에 절대 넣지 않고** 결과 분석 시 상한 비교로만 사용 |
| J | 개별 정책만 수정 — 각 개체가 자기 규칙 목록을 진화시키고 집단 공통 규칙은 없음 |
| K | 집단 프로토콜 제안 가능 + **채택은 단순 투표** (각자 소표본 자체 평가 후 다수결 — 실험 1의 투표 경고를 제도 변인으로 재활용) |
| M | **핵심군.** 집단 프로토콜 제안 + **블라인드 평가 채택**: 제안자 정보 제거, 고정 검증 인스턴스 실행, protocol_score 최대안 채택, 악화 시 롤백 |
| L | M과 같되 제안 전담 개체 1 (탐색 상한군 — 성공해도 자발적 발생으로 해석 금지) |

K와 M의 차이는 **채택 제도**(투표 vs 블라인드 평가)다 — 규칙을 만드는
능력과 규칙을 검증·보존하는 제도를 분리해 측정한다.

## 2. 규칙 언어 (DSL)

```
RULE <id> : IF <cond> [AND <cond>] THEN <action> PRIORITY <n>
```

- 조건 지표 (개체 로컬에서 계산 가능한 것만):
  `remaining_budget_ratio, estimated_slack, public_candidate_count,
  my_best_gain, recent_share_gain, consecutive_low_gain,
  number_of_passes, round_index, my_threshold`
- 행동 (파일럿 축소 집합): `SHARE_BEST, PASS, RAISE_THRESHOLD,
  LOWER_THRESHOLD` (+프로토콜 파라미터 `init_threshold`).
  `TRANSFER_TURN, REQUEST_REEVALUATION, RESTART_ROUND`은 예약 —
  파일럿에서 실행기 의미론을 고정한 후 본실험 전 추가 여부 결정.
- 조건 최대 2개(AND), 규칙 수 상한 8, 우선순위 정수.

**금지·통제 (가장 중요)**:
- `global_argmax` 호출 불가, 타 개체 비공개 단서 조회 불가.
- **I2 규칙·"문턱 경매"·"하강 문턱" 개념을 초기 후보·프롬프트·연산자
  어디에도 제공하지 않는다.** 시조 프로토콜은 `ALWAYS → SHARE_BEST`
  (= C와 동일 행동) 하나뿐이다.
- 실행기·평가기·채택 절차는 개체가 수정할 수 없다 (고정 코드).
- 파일럿(결정론)에서 제안은 **무작위 규칙 생성 + 기존 규칙 변이**만
  사용한다 — 실패 요약은 로그로만 남기고 제안 생성에 쓰지 않는다
  (성능 신호는 오직 선택 단계에서만 작용). LLM 제안자는 이후 같은
  인터페이스 뒤에서 교체하며, 그때 실패 요약이 입력이 된다.

## 3. 학습 루프 (세대)

1. 현재 프로토콜로 훈련 인스턴스 수행 → 성공률·통신량·실패 시점 기록
2. 실패 요약 생성 (파일럿: 기록만)
3. 각 개체 최대 1개 규칙 연산 제안 (추가/변이/삭제/init_threshold 조정)
4. 후보 프로토콜들을 검증 세트에서 블라인드 평가
5. 채택: `protocol_score = success_rate − 0.02·(공유/예산 평균)
   − 0.20·미해결률 − 0.005·복잡도` (λ **동결**, 파일럿 전 고정)
6. 현직보다 나쁘면 롤백 (현직 유지)
7. 전 과정 계보 기록: 버전, 부모, 제안자, 연산, 점수, 규칙 발화 수

## 4. seed·여유율 규약 (완전 분리)

- 훈련: seed 2001~2020 / 검증: 2101~2120 / 시험: 3001~3040
- 훈련 slack {1.0, 1.25, 1.5} / 시험 동일 + **미관측 slack {0.9, 2.0}**
- 권장 규모: 20세대. 파일럿은 3세대·소규모로 **기계 검증만** 한다
  (규칙이 생성·채택·롤백되고 계보가 정확한가). 파일럿에서 성능을 보고
  하이퍼파라미터를 바꾸면 그 시점에 본실험 사전 등록을 갱신해야 한다.

## 5. 사전 등록 가설 (동률 처리 명시 — Series 1 교훈)

정확도 비교는 "평균 차 ≥ 0.02"를 우위로 정의한다 (동률·미세차는 무승부).

- **P20**: J는 C보다 개선되나 I2 미달.
- **P21**: K·M은 J보다 높은 시험 성능. K vs M 격차는 채택 제도 효과로
  별도 보고 (예측: M ≥ K — 실험 1 투표 경고의 재현 여부).
- **P22**: M은 시조에 없던 집단 조정 규칙을 1개 이상 생성·채택한다.
- **P23**: M 최종 프로토콜 제거(시조로 환원) 시 시험 성능 하락 ≥ 0.05.
- **P24**: M의 개선은 미관측 seed(3001~3040)에서 유지.
- **P25**: M의 개선은 미관측 slack(0.9, 2.0)에서 유지.
- **P26**: M 최종 프로토콜이 I2와 문법적으로 달라도, 기능 지표(약한
  공유 억제율·양보율·조정 충실도)에서 유사 기능 수행 여부를 별도 평가.
- **P27**: 훈련 성능만 오르고 시험 성능이 오르지 않으면 발견 불인정.

## 6. 절제 실험 (성능 향상의 3분해)

성능 향상 = 표현 공간 효과 + 탐색 절차 효과 + 발견된 규칙 효과.

1. 최종 규칙 개별 제거 / 2. 규칙 순서 무작위화 / 3. 파라미터 초기화 /
4. 동일 DSL·무학습 군 (무작위 프로토콜 동수 평가 — 표현 공간 통제) /
5. 발견 규칙을 처음부터 넣은 재실행 / 6. **다른 seed에서 처음부터
재발견 가능한가** (1회 발견 ≠ 재현 가능한 사회적 메커니즘).

## 7. 실패해도 가치 있는 결과 (사전 명시)

규칙 과잉 교체, 초기 규칙 고착, 인기 규칙이 좋은 규칙 구축(驅逐), 제안
다양·검증 부실, 투표-품질 괴리(K) — 이 패턴들이 관측되면 다음 연구
질문은 "규칙 발명"이 아니라 **규칙을 검증·보존하는 메타제도**로
이동한다 (제도 형성 연구).

## 8. 구현 순서

1. ~~브랜치 생성~~ 2. DSL 파서·안전 검증기 3. 프로토콜 버전·계보 저장
4. 실행기(고정) 5. M군 진화 루프 + J/K/L 6. seed 분리 7. 파일럿(기계
검증) 8. 하이퍼파라미터 동결 9. 본실험 10. 절제·일반화·재발견.
