## 0. 지금 서 있는 자리

오늘 하루로 고리가 이만큼 바뀌었다.

| | 어제 | 지금 |
|---|---|---|
| 고리의 끝 | 컴파일되면 끝 | **돌려 보고 떨어지면 다시 고친다** |
| 그 판의 합격 기준 | 아무도 안 눌러 봄 | **표로 옮겨 눌러 본다**(`unity_checks.py`) |

## 1. P0 전에 막힌 것 하나

**PlayMode 시험이 계속 0개 돈다.** 오늘만 여섯 번.

```
Test run completed. Exiting with code 2
duration="0.118"  testcasecount="6"  total="0"
```

여섯 개를 **찾아 놓고 0개를 돌린다.** 손으로 같은 명령을 치면 다섯이 다 돈다.
자물쇠도 치웠고, 두 번 해 보게도 했고, 로그도 프로젝트 밖으로 뺐는데 그대로다.

**이것이 P0 의 등뼈를 막는다.** P0 합격 기준 다섯 줄 중 셋째 —

> 하루를 넘긴다 → **물 안 준 것은 그대로다**

— 가 "이 게임이 모동숲인가" 를 재는 유일한 줄인데, PlayMode 가 안 돌면 그 줄을
못 잰다. 그러면 P0 는 다시 "컴파일은 됐고 사람이 봐야 한다" 로 끝난다.

**그래서 0번이 측정 복구다.** 게임을 짓기 전에 자를 세운다.

## 2. 순서

### 0. 측정 복구 — 값 0

`testcasecount=6, total=0` 의 원인을 찾는다. 아직 안 본 것:

- 유니티 종료를 안 기다리고 다음 실행이 붙는가(프로세스 종료 확인)
- `-runTests` 앞에 도메인 재적재가 필요한가(빈 실행을 한 번 넣어 본다)
- `EditorBuildSettings` 가 방금 바뀌어 씬 목록이 아직 안 굳었는가

**게임을 짓기 전에 한다.** 자가 없으면 지어 봐야 잰 것이 없다.

### 1. 새 프로젝트 — `RookeryFarm`

`RookeryGame` 은 "안 움직이는 마을" 을 고치느라 다섯 판이 겹쳤다. P0 는
**깨끗한 데서** 짓는다 — 무엇이 어느 판의 결과인지 알 수 없으면 판정이 무의미하다.

- 3D · `activeInputHandler: 1`(새 입력 전용)
- 패키지는 `setup_env.py --fix --add-packages` 가 레지스트리에 물어서 고른다
- 오늘 고친 자리라 **깨끗한 기계 경로를 한 번 더 지나가는 셈**이다

### 2. P0 한 판

로키에게 줄 문장(초안):

> 3D 생활 시뮬레이션의 첫 조각. 밭 한 뙈기에서 씨를 심고, 물을 주고,
> 집에 들어가 자면 하루가 지나고, **물을 준 것만** 자란다. 다 자란 것을
> 거두면 밭에서 없어지고 바구니에 쌓인다. 실패하거나 죽는 것은 없다 —
> 물을 안 주면 그냥 안 자란다.
>
> 상태는 숫자가 아니라 **물체로** 드러낸다. 거둔 것은 HUD 숫자가 아니라
> 바구니에 실제 물체로 쌓인다.

마지막 문단이 중요하다. 판정기가 아는 말은 "물체가 생긴다/없어진다/움직인다"
뿐이라, 숫자로만 드러난 상태는 못 잰다(09-03 에 그것 때문에 멀쩡한 게임이
어김으로 찍혔다).

값: **$2~3 · 30분** 어림. 오늘 판이 짧았던 것은 고치는 판이라서다.

### 3. 약속한 것을 눌러 본다

```
python tools/unity_checks.py --project "C:/Users/az518/RookeryFarm" \
    --session <판 id> --dim 3d
```

씬에서 이름을 꺼내고 → 기준을 표로 옮기고 → 눌러 본다. **셋째 줄이 이 판의
핵심이다.**

### 4. 사장님이 켜서 보신다 → 승인

화면의 **[봤고 좋다]** / **[봤는데 아니다]**. 반려에 한 줄 적으면 그것이 다음
판의 입력이 된다.

### 5. 자산 — 승인 뒤에만

메시는 Meshy, 소리는 ElevenLabs(09-03 확정, 유니티 AI 는 안 본다).
**Meshy 는 값 0 짜리 시험 키가 있어서** 배선 전체를 공짜로 끝내고 첫 크레딧을
쓴다. 승인 문(`unity_art.py`)은 벤더가 바뀌어도 그대로다 — 두 번째 문을 안 만든다.

## 3. 무엇이 먼저 깨질 것인가

미리 적어 둔다. 적어 두면 그때 원인을 찾는 시간이 준다.

| 예상 | 그때 볼 것 |
|---|---|
| "잠자기" 를 화면 어둡게만 하고 시간을 안 넘긴다 | 하루 카운터가 실제로 오르는가 |
| 물 준 것/안 준 것을 **한 물체**로 관리해 차이가 안 보인다 | 셋째 줄이 못 잼으로 나온다 |
| 수확물이 HUD 숫자로만 는다 | 표가 `countUp` 을 겨눌 물체가 없다 |
| 씬 빌더가 두 번 불려 밭이 겹친다 | 오늘 판에서 로키가 스스로 건 기준에 이미 있다 |

## 4. 사장님이 정하실 것 (설계 v2 §6 중 남은 것)

- **② 첫 작물이 무엇인가** — 이름·모양·자라는 단계 수. 창작이라 비워 둔다.
- **③ 마을 크기** — P0 는 밭 하나면 되지만, P1 에서 갈린다.
- **④ 실패가 정말 없는가** — 모동숲은 없다. 확인만.
- **⑤ 낚시·곤충·계절을 언제 넣나** — P3 이후.

②는 P0 를 돌리기 전에 있으면 좋지만, 없어도 "작물" 로 두고 프로토타입은 돈다 —
어차피 도형이고 그림은 승인 뒤다.
