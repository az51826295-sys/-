# Rookery 실험 3a 설계 — 실제 저장소 과거 버그 재현 (사전 등록)

작성: 2026-08-02. 상태: 초안 — 과제 채굴·검증 후 동결. 근거: 사용자
결정 (2026-08-02) + v1/v2/v2.1 보정 3회의 일관 결론 (자기완결 합성
과제 ≤ Haiku 원샷 능력).

핵심 질문 (v2에서 이식):

> 다양한 후보 + 기계적 중복 제거 + 숨김 검증 + 롤백이 **현실적인
> 코드 수정에서도** 단일 순차 에이전트보다 실패 복구를 잘하는가?

단계: **v3a** 통제된 실제 저장소 과거 버그 (제도 효과 인과 검증) →
v3b 저장소 간 일반화 → v3c 공개 벤치마크 부분집합 (외적 타당성).
SWE-bench류를 지금 쓰지 않는 이유: 저장소 크기·의존성·이슈 품질·
환경 구축이 한꺼번에 변해 제도 효과와 탐색 효과가 분리 불가.

## 1. 과제 구성 (버그 커밋 재현)

각 과제 = 실제 저장소의 과거 버그:
- 버그가 존재하는 **부모 커밋** 체크아웃 (작업 대상)
- 원래 **수정 커밋**은 정답 참고용 보관 — 실험 종료 전 비공개
- 부모 커밋에 이미 있던 관련 테스트 + 이슈의 재현 사례 = **공개**
- 수정 커밋에서 추가된 회귀 테스트 = **숨김** 핵심 + 변형 입력 1~3개
  (정답 복사형 부분 수정 방지) + 수정 파일 관련 기존 회귀 테스트 +
  필요시 metamorphic 테스트
- 원래 패치 내용·이슈 해결 설명은 proposer에게 비공개

숨김 테스트별 검증 의무 (미래 커밋 테스트 채택 조건):
버그 부모 커밋에서 실패 / 정답 수정 커밋에서 통과 / 현재 환경에서
재현 / 신기능 요구가 아닌 기존 사양 회귀임을 확인. API 사양 변경·
신기능·의존성 업데이트 의존 테스트는 제외.

## 2. 저장소·과제 선정 기준 (사전 등록)

Python 중심 / 로컬 테스트 1~3분 / 외부 서비스·DB·Docker 불필요 /
수정 파일 1~4개 / 정답 패치 5~50줄 / 재현 테스트 명확 (부모에서
실패, 수정에서 통과) / 라이선스 재배포 무해. 제외: 빌드 복잡성,
플랫폼 의존(비 Windows 전용 포함), flaky 테스트.

## 3. 최소 설계 (파일럿)

저장소 3개 × 과제 3개 = 9문제, 각 A/B 3회 반복, Haiku 고정, 모델
호출·토큰 예산 동일. 파일럿 목표: A군 첫 후보 완전 해결률 30~70%,
공개-통과·숨김-실패 표본 존재, 회귀 표본 존재, 환경 실패율 <10%.
범위 내면 본실험 18~30과제 확장.

## 4. 지표 (v2 이식 + 확장)

- 완전 해결 = 공개 ∧ 숨김 ∧ 관련 회귀 통과. 회귀율 = 기존 통과
  테스트 중 패치 후 실패 비율. 회복률 = 첫 후보 실패 과제 중 최종
  champion 완전 해결 비율.
- 추가: 테스트 실행 비용, 후보 수, 중복 패치율, 수정 파일 수, 패치
  크기, 불필요 변경률, 환경 실패율, wall-clock, API 비용.
- **실패 코드 분리 의무**: env_setup_fail / test_timeout /
  patch_parse_fail / patch_apply_fail / public_fail / hidden_fail /
  regression — 환경 실패는 모델 실패와 절대 합산하지 않는다.

## 5. A/B 공정성

- A(순차 단일): 후보 1개씩, 공개 테스트 결과 보고 재시도, 작업 트리
  상태 열람 가능. B(제도형): 라운드당 복수 후보, 독립 작업 트리,
  AST 중복 제거, 공개 테스트 선별, champion–challenger, 롤백. 숨김은
  validator 전용.
- 모델 호출·토큰 예산 동일. **테스트 예산은 별도 측정 + 상한** —
  완전 동일화는 제도의 장점(테스트 활용)을 인위 제거하므로, 대신
  "추가 테스트 비용 대비 성능 증가"를 의무 보고.

## 6. 천장 프로토콜

Haiku가 여기서도 원샷 80%+면 모델을 낮추기 전에 난이도 축 우선:
수정 파일 2~4개 / 이슈 설명 불완전 / 관련 테스트 일부만 공개 /
비국소 원인 / 패치 20~80줄 / 부분 수정이 공개 통과 / 탐색 필요.
그래도 천장이면 소형 모델 축 — 단, 질문이 "Haiku의 성능을 높이는가"
에서 "**제한된 proposer 능력을 제도가 보완하는가**"로 바뀜을 명시.

## 6.5 코퍼스 확정 및 선정·제외 로그 (2026-08-02)

**확정 9과제 (전부 기대 행렬 기계 검증 통과)**: more-itertools 4
(sliced 음수 / interleave 빈 입력 / numeric_range 역순 / running_
minmax 안정성) + tinydb 3 (LRU falsy / LRU set 갱신 / doc_ids 누락)
+ dateutil 2 (parse_isotime 24:00 / isoparse T24 롤오버).
등록된 3×3 대신 4/3/2 배분 — 사유는 아래 제외 로그.

제외 로그:
- **sortedcontainers**: fix 커밋 대부분이 오타·CI·문서 — 기준을
  충족하는 버그 수정 커밋 부족으로 저장소 탈락.
- **dateutil 0b773a5** (2017, parser 인덱스 체크): 라이브러리 자체가
  Python 3.12에서 구동 불가 (`collections.Callable` 제거) —
  env_setup_fail로 제외. 스위트가 아니라 라이브러리 수준 비호환.
- tinydb 환경 노트: pytest.ini가 --cov를 강제 → 러너가 `-o addopts=`
  로 중화 (전 저장소 공통 적용, 의미 변화 없음).
- dateutil du_isotime_midnight는 테스트-선행 커밋 패턴이라 저장소
  네이티브 테스트(test_isotime_midnight)를 공개 재현으로 사용 —
  가장 깨끗한 형태.

## 6.6 파일럿 1차 판정 및 개정 (2026-08-02, GPT 검토 결정)

1. **512토큰 런 제외**: 출력 절단 아티팩트 — 모델 비교에서 제외,
   "출력 토큰 예산이 패치 품질의 숨은 제약"이라는 운영 결과로만 기록
   (`*_512tok` 보존).
2. **4000토큰 런: A 89% / B 85% — 실질 동률, 천장 해석.** 단일 파일 +
   정확한 이슈 + 초점 코드 조건에서 제도 우위는 입증되지 않음.
3. **du_isoparse_t24_rollover (양군 6/6 회귀) = selector 문제**:
   공개 테스트만으로 champion을 고르면 회귀를 감지할 수 없다.
   → **개정 A/B**: selector가 공개 회귀 스모크(기존 regression id)
   까지 평가. 광역 회귀는 신설 `regression_hidden`으로 최종
   validator 전용. 숨김 테스트는 종전대로 validator 전용.
4. **난이도 축 우선순위**: ① 초점 창 제거(2단계 탐색 프로토콜 —
   1호출: 저장소 트리+이슈만 보고 조사할 파일·심볼을 JSON 요청,
   이후: 요청 발췌로 패치. 탐색 호출도 예산 차감) → ② 다중 파일
   실제 버그 → ③ 이슈 설명 불완전화. **모델 강등은 하지 않는다.**
5. 다음 목표: proposer가 아니라 selector·탐색 난이도를 키운 재보정
   파일럿.

## 6.7 탐색 파일럿 v2 판정 (2026-08-02)

개정 A/B(선택기 회귀 스모크) + 탐색 프로토콜, 하네스 수정 2건
(라이브러리 전 파일 패치 허용 — 테스트만 금지, 첫 후보 지표) 후:

- **A 67% / B 67% 완전 해결, 첫 후보 59%/63%** — 목표 분포(30~70%)
  정당 진입. 비용 누적 ~$7 (v3a 전체).
- **그러나 실패 구조가 퇴화 이봉(bimodal)**: 6과제는 양군 6/6 완전,
  3과제는 양군 0/6 — 과제 내 확률 변동이 없어 제도가 선택할 여지가
  없다. B의 중복 제거 38회 발화 = 후보들이 거의 동일하다는 증거.
- **3개 저항 과제의 실패 원형 (전부 상이)**:
  ① running_minmax — **오파일 고착**: 12/12 후보가 more.py에 패치
  시도, "recipes.py에 없음" 교정 피드백을 6회 받고도 반복 (모델이
  오류 관측을 활용하지 못함). ② isotime_midnight — 다형식 불완전
  수정 (8개 파라미터 일부만 통과). ③ t24_rollover — 부수 회귀
  (스모크가 선택 중 걸러도 전 후보가 동일하게 회귀 유발).
- **시리즈 연결 — 7D의 실업무 전이 확인**: 제도의 가치는 제안
  다양성에 상한된다. DSL 세계보다 실코드에서 Haiku의 제안 집중도가
  훨씬 높아, 온도 1.0로도 과제당 사실상 1가지 답만 나온다. 제도
  개선보다 **다양성 주입**(7D의 패딩/프롬프트 지터를 B 라운드에
  적용)이 다음 실험 후보 1순위.

## 6.8 다양성 기제 소실험 (2026-08-02 등록, 실행 전 동결)

**질문**: 동일 모델·총예산에서 후보별 프롬프트 변형이 구조적으로
다른 패치를 만들면, 중복 제거 + champion–challenger가 저항 과제
해결률을 높이는가? 1차 확인 사항은 "B가 이기는가"가 아니라 **"B에
실제 선택지가 생겼는가"**.

- **대상**: 저항 3과제만 (running_minmax·isotime_midnight·
  t24_rollover). 탐색 모드 유지. A군 없음.
- **군**: B0(현행 — 3후보 동일 프롬프트, temp 1.0) vs
  **B-diverse**(후보별 동결 템플릿: 슬롯1 기준 / 슬롯2 비의미 패딩
  ~800자 / 슬롯3 대안 가설 강제 — "첫 번째로 떠오르는 수정 경로와
  다른 원인 가설을 세우고, 다른 파일이나 호출 경로에서 원인을
  찾아라"). 서로 다른 다양화 **원리**를 슬롯에 하나씩 배치 (패딩
  3종 금지 — 원리 분리 목적). 반복 5회.
- **1차 지표 (다양성)**: 런당 고유 패치 서명 수, 후보 간 수정 파일
  다양성, 정답 파일 포함 후보 비율(측정용, 비노출), 중복률, 기존
  실패 원형과 다른 후보 출현률.
- **2차 지표**: 공개 통과 후보 존재율, 회귀 스모크 통과 후보
  존재율, 숨김 완전 해결률, selector 정답 선택률, 회복률.
- **판정 구조 (동결)**: 다양성 불변 → 조작 실패 / 다양성↑·해결
  불변 → 무용한 분화 / 다양성↑·정답 후보 존재·선택 실패 →
  selector 병목 / 다양성↑·정답 선택·해결↑ → 제도 효과 입증.
- **공정성**: 호출 수·후보 수·최대 출력 토큰 동일. 입력 토큰 차이는
  조작의 일부로 기록·보고 (비용 대비 효과 포함).
- **후속 규칙**: 효과 확인 → 저항 과제형 추가 채굴 + A vs B-diverse
  본실험. 3과제 모두 원형 반복 → 프롬프트 지터 부족 판정, 더 강한
  분화(역할 분리 proposer·이종 모델·탐색 전담 단계·반대 가설 강제)
  검토. 본실험 확대는 이 소실험 전에 하지 않는다.

## 6.9 다양성 기제 소실험 결과 (2026-08-02) — 판정 1단계 (조작 실패)

30런 (3과제 × B0/BD × 5반복, 180호출, ~$1.2):

| 지표 | B0 | BD |
|---|---|---|
| 런당 고유 서명 | 1.93 | 2.20 |
| 후보 파일 다양성 | 0.67 | 0.67 |
| 공개 통과 후보 존재율 | **0.00** | **0.00** |
| 완전 해결률 | 0.00 | 0.00 |

- 고유 서명 +14%는 표면 변이일 뿐, **수정 파일 다양성 불변·공개
  통과 후보 0/180·세 실패 원형 전부 그대로** — 동결 판정 구조의
  1단계("다양성 증가 없음 → proposer 조작 실패") 해당.
- **7D의 패딩 효과는 실코드 제안 다양화로 전이되지 않는다** (DSL
  표집 협착과 실코드 원인 추론 고착은 다른 병목).
- 등록된 후속 규칙 발동: 단순 프롬프트 지터 부족 확정 → 더 강한
  분화 구조 검토 단계로 이행. 후보: ① 파일 탐색 전담 단계 분리
  (running_minmax의 오파일 고착 직격), ② 반대 가설 강제(후보 간
  상호 배타 제약), ③ 역할 분리 proposer, ④ 이종 모델 혼합.

## 6.10 B-search 소실험 (2026-08-02 등록, 실행 전 동결)

**병목 재정의**: 샘플링 다양성이 아니라 **초기 원인 위치 추론의
고착** — 한 번 잘못 고정된 가정을 모든 패치가 공유한다.

**구조**: 관측 → **탐색 단계**(서로 다른 원인 가설 생성) → 기계적
검증·분화 → 가설별 패치 슬롯 배정 → 패치 → 공개·스모크 선택.
"다르게 생각하라"는 요청이 아니라, **각 후보가 다른 탐색 결과를
입력받게 구조로 강제**한다.

- **군**: B0(현행) vs **B-search** — 탐색 호출이 가설 ≥4개 생성
  (각: 의심 파일·의심 함수·호출 경로·이유·반증 조건). 기계적 중복

  성과로 전이되지 않았다.
- **코퍼스 정의에 주는 함의**: 채굴 프로브의 사건 규칙이 회귀형과
  불완전형을 **구분하지 않았다**. selector-측 질문에 유효한 것은
  회귀형뿐 — B군 재정의(B-regression) 시 mm_validationerror 1건만
  해당하며, 나머지는 다른 질문(패치 완전성)의 표본이다.

### 8.5 §8.3 확정 결론 및 selector 트랙 종결 (사용자 확정 2026-08-02)

1. **selector-측 IA는 기존 정상 동작을 깨뜨리는 회귀형 후보에서는
   작동했다.** 회귀형 표적 후보 4/4 배제, 과잉 탈락 0 — **회귀
   보호 기제 자체는 확인됨.**
2. **최종 성과 개선은 입증되지 않았다.** 표적 champion 채택률
   차이는 사전 문턱 미달, 양군 proposer 표집 차이 13 대 7의 영향을
   크게 받음, 과제별 최종 결과 동일.
3. **불완전형 후보는 selector-측 기존 테스트로 원리적으로 판별
   불가능했다.** 기존 동작은 안 깨뜨리고 새 요구사항 일부만 누락 /
   판별 테스트가 hidden이라 selector에 노출 불가 / **이는 selector
   결함이 아니라 정보 경계로 기록.**

**selector 연구 트랙 종결.** B-regression 과제를 추가 채굴해 같은
기제를 반복 검증하지 않는다. 회귀 보호는 연구 대상이 아니라
**제품 기본 계층**으로 이관 (`genesis/rookery/regression_guard.py`).

**다음 연구 주제: 패치 불완전성** — 단, 새 프롬프트 기제를 바로
실행하지 않고 코퍼스 정의와 기계적 사건 기준을 먼저 등록한다
(§9).

## 9. 불완전형 코퍼스 정의 등록 (2026-08-02 동결, 실행 전)

**대상 현상**: 후보 패치가 **기존 동작을 깨뜨리지 않으면서**
(회귀 아님) 새 요구사항의 **일부만** 충족한다. §8.4에서 9건이
관측됐고 selector로는 원리적으로 못 잡는 것이 확인된 부류.

**기계적 사건 기준 (INC-event, 전부 자동 판정)**: 부모 커밋 기준
부분 패치 P에 대해
- (a) 공개 재현 테스트 ≥1개 통과 **그리고**
- (b) 고정 스모크 전부 통과 **그리고**
- (c) 부모에서 통과하던 저장소-네이티브 테스트 **전부 통과**
  (= 회귀 없음 — 회귀형과의 배타 조건) **그리고**
- (d) 수정 커밋 유래 테스트 중 ≥1개 실패 (= 요구사항 미충족)
  **그리고** 그 테스트는 정답 패치에서 통과 (판별력 확인)

(c)가 회귀형(§8.3 mm 유형)을 배제하고, (d)가 단순 무효 패치를
배제한다. 사건은 **함수 단위 부분 적용 프로브**로 실증하되,
§8.2에서 기록한 그레인 한계(라인 수준 미탐지)를 그대로 승계한다.

**과제 적격 기준**: INC-event ≥1건 기계 실증 / 정답 패치가 전체
통과 / 환경 오류 0 / 재현 ≤ 60초 / 정답 함수 ≥2개 (부분 적용
공간 존재).

**진행 기준 (동결)**: 최소 4과제 확보 전 A/B 본실험 등록 금지.
부족 시 "불완전형 코퍼스 부족"으로 기록. **기존 저항 3과제·B군
3과제 재사용 금지** (다른 질문의 표본). 새 프롬프트 기제·가설
제안은 코퍼스 확보 전까지 보류.

**기존 자산 활용**: §8.4의 du_operators·mi_repeat는 INC-event
조건을 이미 만족할 가능성이 높으나, **§8.3 실험 표본으로 소진**
됐으므로 신규 코퍼스에 편입하지 않는다 (재사용 금지 원칙).

⑪ 서버 재부팅 후 자동 재개 ⑫ 하루 한 번 요약 보고.

**자동화 범위**: 격리 브랜치 내부의 수정·실험·채택·롤백은 사람
승인 없이 자동 / 검증된 결과는 자동 PR 생성 / **운영 브랜치 자동
머지는 Alpha에서 비활성화** / 위험 명령·비밀정보 접근·외부 배포·

## 8. 코퍼스 v2 채굴 (2026-08-02 등록 — 주 레인 전환)

**목표**: 성능을 억지로 낮추는 것이 아니라, **현재 질문을 실제로
관찰할 수 있는 과제**를 확보하는 것. 채굴 단계에서 모델 본실험
금지 — 과제별 **기계 검증 매니페스트**를 먼저 만든다.

**과제군 A — 위치-난제형** (§6.11 구조 가설의 검정용):
초점 파일·함수가 정답과 다름 / 실제 원인이 2개 이상 파일 또는
호출 경로에 걸침 / 첫 탐색에서 그럴듯한 오파일 존재 / 기존
테스트만으로 위치 가설 일부 반증 가능 / 정답 위치 적중률이
천장·바닥이 아닐 것.

**과제군 B — selector-사건형** (§6.16 재검정용):
공개 재현+고정 스모크를 통과하는 후보가 실제로 존재 / 그중 일부는
hidden 또는 광역 회귀에서 실패 / 같은 런에 회귀 없는 대안 후보
생성 가능성 / **selector가 실제로 선택을 바꿀 사건이 존재**할 것.
기계 대리 검증: 정답 패치의 부분 적용(헝크·파일 부분집합)이 공개
재현을 통과하면서 hidden·광역 회귀에서 실패하는 조합의 실존.

**필수 매니페스트**: 부모·수정 커밋 / 정답 변경 파일·함수 /
공개·스모크·hidden·광역 회귀 테스트 / 부모·수정 커밋 기대 행렬 /
정답 패치 크기 / 오파일·부분 수정 미끼 경로 / selector 표적 사건
존재 여부 / 환경 재현 시간과 실패율.
