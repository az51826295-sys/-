# 게임 설계 v1 — Ethra 룩 + 소울 전투 (2026-08-07 사용자 확정)

v0(2D 마을 RPG)를 대체한다. v0는 기록으로 보존 —
[game-design-v0.md](game-design-v0.md). 2D 자산·마을은 폐기가 아니라
보류 (PixelLab은 UI·아이콘·초상화 담당으로 계속 고용).

> 한 줄: **3D 도트(Ethra풍) 세계에서 구르고, 베고, 죽고, 화톳불에서
> 다시 일어나는 소울류.** 화면은 셰이더가 만들고, 재미는 전투
> 감각이 만들고, 둘 다 코드다.

## 1. 왜 이 조합인가

- 소울류는 화면 밀도를 요구하지 않는다 (Death's Door·Tunic —
  단순 조형 + 조명). **Ethra 룩의 "단순 3D + 렌더링 마법"이 소울류가
  요구하는 딱 그만큼**이다.
- 소울류의 본체 = 전투 감각·보스 설계 = 코드 반복 조정 = Claude가
  무한정 할 수 있는 영역.
- 렌더링 경로는 이미 실증됨: `poc3d/` — 320×180 직교 렌더 + 최근접
  4배 + 3밴드 톤 셰이딩 + 패턴 물 (2026-08-07 노트북 실행 확인).

## 2. 수직 슬라이스 (전체 게임이 아니라 이것부터)

**"섬 하나, 화톳불 하나, 보스 하나."** 이것이 나올 때까지 다른
콘텐츠(마을·NPC·성장 시스템) 금지.

## 3. 전투 설계 v0 (P0에서 캡슐로 검증)

- **스태미나**: 공격·구르기가 소모, 잠깐 쉬면 회복. 바닥나면 둘 다
  불가 — 소울류 긴장의 원천.
- **구르기**: 무적 프레임(i-frame) 있음. 방향 입력 + 버튼.
- **공격**: 선딜-판정-후딜 3박자. 연타 불가(후딜 캔슬 없음).
- **피격**: 경직 + 넉백 + 무적 짧게. 맞으면 아픈 게임.
- **록온**: 가장 가까운 적 고정, 카메라·이동이 적 기준으로.
- 판정 기준: **캡슐 상태로 "조작이 재밌는가"를 사용자가 판정.**
  그림을 입히는 건 재미 합격 후 (v0의 교훈: 보이는 것 먼저 —
  단, 전투 게임에서 "보이는 것"의 본체는 손맛이다).

## 4. 죽음 루프

화톳불 = 리스폰 지점 + 회복 + 적 부활. 죽으면 그 자리에 유산을
떨어뜨리고, 되찾으면 회수 — corpse run. 세부 수치는 P2에서.

## 5. 렌더링 — 남은 과제 (P1)

1. **외곽선 패스** — Ethra 특유의 또렷한 픽셀 윤곽 (포스트프로세스)
2. **픽셀 안정화** — 카메라·이동 시 지글거림 억제 (이 스타일 최고
   난이도, t3ssel8r의 본체)
3. 조형 개선 — 구·원기둥 → 손질된 로우폴리 (셰이더가 대부분 살림)

## 6. 애니메이션 경로 (P3)

2D의 PixelLab처럼, 3D는 **Mixamo**(무료 인간형 애니메이션 라이브러리
— 구르기·베기·피격 전부 존재)를 로우폴리 모델에 리타겟. "잘하는
도구에 맡긴다" 원칙의 3D판. 모델 소스는 무료 팩 → AI 3D 생성 순로
시험.

## 7. Genesis·Rookery 연결 (장기 후보, 지금 금지)

- **배우는 보스**: 플레이어의 회피·공격 패턴을 Genesis 경험 루프로
  학습해 다음 도전에서 대응이 달라지는 보스 — 이 게임만의 정체성
  후보. 수직 슬라이스 이후에만 (P4+).
- Rookery 야간 운영(버그 과제화·자동 수정)은 저장소가 자라면 연결.
- PixelLab(2D 직원): UI·아이콘·초상화·타이틀 아트.

## 8. 로드맵과 판정

| 단계 | 내용 | 합격 판정 |
|---|---|---|
| P0 | 캡슐 전투 (3절 전부) | 사용자: "조작이 재밌다" |
| P1 | 외곽선 + 픽셀 안정화 | 사용자: "화면이 Ethra 방향이다" |
| P2 | 보스 1기(패턴 3~4) + 화톳불 + 죽음 루프 | 사용자: 보스전 클리어까지 재도전을 자발적으로 함 |
| P3 | 모델 + Mixamo 애니메이션 | 화면·손맛 동시 유지 |

각 단계는 사용자 판정 없이는 다음으로 못 넘어간다 — v0에서 배운
규칙: **인정 없는 전진은 전진이 아니다.**
