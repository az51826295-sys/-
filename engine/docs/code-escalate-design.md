# 코딩으로 증거 만들기 — 싼 AI + 기계 확인 + 올려 보내기 vs 비싼 AI (설계, 11-23 22:4x 잠금 전 초안)

사장님(11-23): *"이제 그 수준을 올려야겠지"* → *"해"*. 메시지 "AI makes. Machines check. Director decides." 에 **코딩 숫자**를 붙인다.
지금 증거는 그림 45쌍 한 판(93.3% vs 91.1%, 값 31%)뿐이고, 에이전트가 제일 많이 하는 일은 코딩이다.

## 물음

테스트가 딸린 코딩 문제에서, **싼 AI 가 풀고 → 공개 테스트(기계)가 확인 → 떨어지면 비싼 AI 로** 가 비싼 AI 혼자만큼 맞히면서 훨씬 싼가?

## 재료

- LiveCodeBench `code_generation_lite` 의 `test6.jsonl`(가장 최근 문제, 134MB) — 표준입력·출력 문제만, medium·hard.
- 고정 씨앗으로 **40문제**를 뽑는다(뽑는 식은 도구 안에, 돌리기 전 커밋).
- 문제마다 **공개 테스트**(문제에 딸린 예시)와 **비공개 테스트**가 있다.
  - **기계 확인 = 공개 테스트만.** 에이전트가 실제로 볼 수 있는 것.
  - **채점 = 공개 + 비공개 전부.** 확인하는 자와 채점하는 자를 가른다 — 공개 예시만 맞추고 틀린 답이 걸러지는지가 이 판의 핵심.

## 팔

| 팔 | 내용 |
|---|---|
| C1 | `deepseek-flash` 생각 끔, 1번 |
| E1 | `deepseek-v4-pro` 생각 켬, 1번 (비싼 쪽) |
| **D** | C1 답 → 공개 테스트 통과면 그대로 / 아니면 E1 답을 쓴다 (로키 방식: 기계 확인 + 올려 보내기) |
| **D3** | flash 최대 3번, 공개 테스트를 처음 통과한 답 / 셋 다 떨어지면 E1 (고르기 + 올려 보내기) |

- D·D3 는 C1·E1 답을 다시 쓴다(같은 분포, 돈 절약). D3 의 둘째·셋째 flash 만 새로 부른다.
- 값: 실제 토큰 × 공시 가격(api-docs.deepseek.com/quick_start/pricing, 11-23: flash 입력 $0.3·출력 $1.2 / pro 입력 $1.32·출력 $3.96 per 1M, 오프피크 반값). 오프피크/피크는 호출 시각으로 센다.
- 코드는 하위 프로세스(`python -I`, 임시 폴더, 테스트당 10초)로 돌린다.

## 정찰 먼저 (천장 막기)

본판 전에 C1 만 40문제 돌려 **flash 가 비공개까지 통과하는 비율**을 잰다.
- 80% 이상이면 천장 → hard 만으로 다시 뽑는다(한 번만). 그래도 80% 이상이면 "이 재료도 천장" 으로 적고 멈춘다.

## 판정식 (잠금)

- **이김:** D 통과 ≥ E1 통과 − 2 (40 중) **그리고** D 값 ≤ E1 값 × 0.5
- D3 도 같은 식으로 따로 적는다(고르기를 더한 값이 있나).
- **지킴:** 공개 테스트는 통과했는데 비공개에서 떨어진 C1 답 수를 따로 센다 — 기계 확인이 놓치는 몫. 이게 크면 "기계 확인은 공개 예시로는 모자라다" 로 적는다.
- 못 잼(호출 오류·시간 초과로 답 없음)은 어긋남이 아니다. 한 팔이라도 못 잼 > 4 면 무효.

## 돈

어림: C1 40번 ≈ $0.1, E1 40번(생각 켬, 답당 출력 ~1만 토큰) ≈ $0.8~1.6, D3 추가 flash 최대 80번 ≈ $0.2 → **합 $1~2(오프피크면 그 절반쯤).**
상한은 사장님이 정한다. `GENESIS_SPEND=i-approve` 필수. 상한에 닿으면 다음 호출을 안 한다.
