# 오디오 세트 층 v0 — 사전 등록

작성 2026-08-26 15:0x. 상속: `judge-bench-v1.2`.
대상: 자산 심판 초안 §3 `layer_set.audio` — 규칙 다섯이 **문장만** 있고 도구가
하나도 없는 자리다. 그림 세트 층(`genesis/asset_set.py`)은 08-25에 섰는데
음악 쪽은 비어 있었다.

낱개가 전부 통과해도 세트는 망한다. 그리고 "일관되는가"는 취향이 아니라
**분산**이라 기계가 잘한다 — 그림 세트 층과 같은 근거다.

**계측기만 만든다. 문턱은 전부 미동결이고 판정하지 않는다.**

---

## 1. 다섯 중 셋을 잰다

| 초안 규칙 | v0 | 왜 |
|---|---|---|
| `loudness_alignment` (지역 내 LUFS 최대−최소) | **잰다** | 오늘 LUFS 계측기가 생겼다 |
| `transition_seam` (인접 곡쌍의 전환 불연속) | **잰다** | 루프 이음새 계산을 곡 사이로 옮기면 된다 |
| `duplication` (곡 간 유사도 — 같은 곡 재탕 방지) | **잰다** | 평균 스펙트럼 거리 |
| `tempo_dispersion` (BPM 변동계수) | **안 잰다** | 아래 §2 |
| `key_conflict` (조성 불협) | **안 잰다** | 초안이 이미 *"규칙표 별첨 필요"*라고 적었다. 없는 표를 내가 지어내지 않는다 |

## 2. `tempo_dispersion`을 일부러 비워두는 이유

BPM 추정에는 **배수 오검출**(150 ↔ 75)이 구조적으로 남아 있다. 같은 템포인 두
곡이 150과 75로 잡히면 변동계수가 크게 나오는데, 그건 곡이 흔들린 게 아니라
계측기가 흔들린 것이다. **오염된 입력으로 만든 분산은 분산이 아니다.**

그래서 `tempo_cv`는 값이 아니라 사유를 낸다. BPM 후보(0.5x·1x·2x)를 정렬해
배수를 정규화하는 방법이 있지만, 그건 새 추정이고 그 자체를 먼저 검증해야
한다 — v0에서 하지 않는다.

## 3. 정의 (동결)

**적격성**: 세트가 **5개 미만**이면 정렬 지표를 내지 않는다(`None` + 사유).
그림 세트 층의 `MIN_SET_N = 5`(초안 §5 E6)와 같은 값을 쓴다 — 내가 새로 고른
숫자가 아니다.

### 3-1. `loudness_spread`
세트에서 잰 LUFS의 **최대 − 최소**(LU). LUFS가 없는 파일(무음·미측정)은
평균에 0으로 섞지 않고 **빼고 세며, 몇 개를 뺐는지 같이 낸다.**

### 3-2. `transition_seam`
인접 곡쌍 (A → B)에 대해, 루프 이음새와 **같은 계산**을 곡 사이에 적용한다:

- 이음새 창 = A의 마지막 512 표본 + B의 첫 512 표본
- 기준 = A와 B **각각의 내부 창들**(합쳐서)
- 값 = 이음새 창의 평균 거리 ÷ 기준 창들끼리의 평균 거리

루프 이음새와 같은 이유로 **비율**이다. 세트 값은 인접쌍 중 **최대**와 쌍
목록을 같이 낸다(어디가 튀는지 감추지 않는다). 순서는 주어진 순서를 쓴다 —
재생 순서는 스펙이 정하는 것이지 우리가 정렬하지 않는다.

### 3-3. `duplication`
곡마다 내부 창들의 **평균 로그 스펙트럼**을 구하고, 모든 쌍의 거리를 잰다.
세트 값은 **최소 거리**와 그 쌍이다(가장 닮은 둘). 거리를 그대로 내고
0~1 유사도로 바꾸지 않는다 — 그 변환은 임의의 함수를 하나 더 얹는 일이다.

## 4. 검증 (동결 — 값을 보기 전에 적는다)

합성 시료로 이빨을 증명한다. 각 지표마다 **가르는 쌍**을 만든다.

| 지표 | 이빨 |
|---|---|
| `loudness_spread` | −23 LUFS 곡 5개 → ≈0. 그중 하나를 −10 dB 줄이면 **≈10** |
| `transition_seam` | 같은 주파수로 이어지는 곡쌍 vs 500 Hz → 3 kHz로 바뀌는 곡쌍: 후자가 **최소 2배** |
| `duplication` | 같은 곡을 두 번 넣으면 최소 거리 ≈ 0, 서로 다른 주파수의 곡들만 있으면 **뚜렷이 크다** |

2배·"뚜렷이"는 **검증용 기준**이지 판정 문턱이 아니다. 못 넘으면 숫자를 낮추지
않고 계측기를 고친다.

## 5. 하지 않는 것

- BPM 배수 오검출을 덮고 `tempo_cv`를 내는 것.
- 조성 불협 규칙표를 내가 지어내는 것.
- 거리·폭을 0~1 점수로 바꿔 "좋음/나쁨"처럼 보이게 하는 것.
- 세트 5개 미만에서 값을 내는 것.
- 문턱을 이 문서로 등록하는 것.

# 부록 A — 비WAV로 넓힌다 (2026-08-26 15:3x)

새 지표도 새 문턱도 없다. **같은 지표를 더 많은 파일에서** 낼 수 있게 하는
배관 작업이다.

## A1. 지금의 한계

세트 층 어댑터는 `asset_probe`(표준 라이브러리 층)로만 읽으므로 **16비트 PCM
WAV만** 본다. 그런데 게임 자산은 ogg/flac/mp3로 들어오는 게 보통이고,
`soundfile`이 깔린 기계에서는 그것들을 이미 열 수 있다(`audio_probe`가 쓴다).
읽을 수 있는데 안 읽고 있는 상태다.

## A2. 규칙 (동결)

**로더 하나로 모은다** — `genesis/audio_io.py`:

1. WAV는 표준 라이브러리로 먼저 시도한다(의존성 없이 도는 경로를 유지).
2. 표준 라이브러리가 못 여는 WAV(24비트·부동소수)와 비WAV는 `soundfile`로
   연다. 없으면 **값이 아니라 사유**를 낸다("디코더 없음").
3. 어느 경로로 읽었는지를 `backend`로 **항상 같이 낸다**. 같은 파일이 기계에
   따라 다른 경로로 읽힐 수 있으므로, 값만 보고 원인을 못 찾는 일이 없게.

**mp3에 대한 정직 조항**: mp3는 인코더가 앞뒤에 무음을 덧붙이므로, 디코드하면
원본에 없던 여백이 생긴다. 이건 우리 계측기의 오차가 아니라 **포맷의 성질**
이고, 앞뒤 무음·이음새 지표가 그만큼 달라진다. 값을 보정하지 않고 이 사실을
문서에 남긴다 — 보정하면 우리가 모르는 인코더 관례를 추측하는 셈이다.

## A3. 하지 않는 것

- 디코더가 없을 때 값을 0이나 근사로 채우는 것.
- mp3 패딩을 임의로 잘라내는 것.
- WAV 경로를 soundfile로 통일하는 것(의존성 없이 도는 경로가 사라진다).
