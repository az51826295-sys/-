# 4개월 계획 — 최종 완성본 (사용자 정본, 2026-08-13 접수)

> 아래 본문은 사용자가 확정한 계획 원문이다 (수정 금지). 실행
> 대조는 맨 아래 부록 — 실행이 원문의 "다음 행동" 시점을 이미
> 지나 있으므로, 이 문서의 살아있는 부분은 부록이다.

---

만드는 것: 모델을 더 크게 만드는 게 아니라, **어떤 개선이 진짜인지
판별하는 제도**. 중앙 AI는 계획하고 해결하며, 필요한 AI·도구에
실행을 위임한다. 판정은 실행 결과가 하고, 채택은 프로토콜이 한다.

**1개월차 — 기초 공사**: 장벽 재집계 정식화(호출 0)와 출처 헤더·
승격 레코드 구현. 주 레인 제거 실험은 병렬로 계속. → 닫을 것:
재집계 표, 출처 계약 가동

**2개월차 — 장부 세우기**: 보드게임 원로그 코딩, U_saved·U_calls
계산, 상태 장부 v0. → 이 달의 산출물은 숫자가 아니라 3개월차를
할지 말지의 답

**3개월차 — 장부가 이득인가**: 조건 1/2/2.5/3 실험. 1차 지표는
성공당 총호출. → 닫을 것: 장부의 이득 여부, 양·음 어느 쪽이든

**4개월차 — 위임과 무인**: 라우팅 규칙(실패에서 역산), 자동/승인
게이트, 48시간 드라이런 후 7일 무인 1차 시도. → 산출물은 성공
여부보다 중단 원인의 분류

전체를 관통하는 규칙 넷:
1. 매달 최소 1개는 닫는다. 0인 달이 나오면 새 가설 대신 열린
   것부터 정리
2. 집계·판정 코드는 골든 케이스 통과 전까지 숫자를 산출하지
   않는다. 이 프로젝트의 계측기 사고 3건이 전부 정상 실행 + 틀린
   숫자였다
3. 게이트에서 멈출 수 있어야 계획이 작동한다. 2개월차 임계 미달
   인데 3개월차를 돌리면 넉 달이 사라진다
4. 숫자를 보기 전에 기준을 박는다. 사전 등록, 지표 고정, 중간
   변경 금지

4개월 내내 하지 않을 것: V(x,b)·ε 착수(장부 판정 전), Mission 8,
보드게임 숫자로 코드 레인 상한 계산, 환경 복원 52건을 일정에 넣기

- **규칙 1 (매달 ≥1 닫기)**: 전 월 충족 — 1개월차 3, 2개월차 3,
  3개월차 1(좁은 실측), 4개월차 3+.
- **규칙 2 (골든 선행)**: 전 집계기 준수. 계측기 사고는 원문의
  3건에서 **6건으로 갱신** — max_tokens 절단, 스키마 힌트 불일치,
  전역<런내 모순 등 전부 "정상 실행 + 틀린 숫자"였고 전부 골든·
  불변식·채널 점검이 잡았다. 규칙 2가 이 계획의 최다 발동 규칙.
- **규칙 3 (게이트 정지)**: 실동 사례 — 조건 실험 파일럿 게이트가
  1차 파일럿을 기각시켰고(스키마 힌트 사고 적발), U_calls 게이트는
  통과로 3개월차를 열었다.
- **규칙 4 (사전 등록)**: 전 실험 준수. 3개월차의 천장 분기는
  **관측 전에 등록된 분기가 발동한 첫 사례** — ablation11의 판정식
  누락(4번째 오류)을 반복하지 않음.
- **하지 않을 것 4종**: 전부 준수 (V(x,b)·ε 미착수, Mission 8
  미착수, 보드게임→코드 레인 수치 이식 없음, 52건 복원 일정
  미편입 — 1단계 분류만 무지출로 수행).

## 게이트 수치 동결 (2026-08-15, 심판자 확정본 접수와 함께)

계획서의 재량 잔존 게이트 2개를 `U_calls < 2,560`과 같은 형태로
숫자화한다. **이미 소비된 판정에는 소급 적용하지 않는다** (규칙 4
— 숫자를 본 뒤의 기준 변경 금지). 향후 등록(장부 재검정, 코드
레인 장부, 5개월차)부터 적용.

- **재매칭 게이트**: "재매칭 되는 해상도 ≥ 1" → **재매칭률 ≥
  0.10인 해상도가 최소 하나**. 근거: c_k=8 낙관 관례에서 10%
  미만이면 U_calls 상한이 산식 오차와 구분되지 않는다. (기관측
  최저 full 0.333의 1/3 이하 — 소급 모순 없음.)
- **"분산에 묻힘" 조작화**: **부트스트랩 95% CI 폭(hi−lo)이
  점추정의 100%를 초과**하면 검정력 부족 = 분산에 묻힘으로
  분류한다. "차이 없음" 주장은 별도로 등가 마진 ε = k·σ의 등가
  검정을 사전 등록해야 한다 (우위 검정 단독으로 동등 주장 금지
  — 심판자 4층 규칙).
- 판정기 구현: `genesis/judge.py` (5층 파이프라인, 골든 5종
  통과), 기준 스펙 `criteria/*.yaml`
  (criterion_id+version+hash 고정, 탈출 레코드), 기준 개정
  프로토콜 = 개정 시 해당 실험 탐색적 강등 + 새 런 필수.
