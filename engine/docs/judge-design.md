# 판단자 v1 — 심판대(judge bench): 문장이 아니라 이빨로 검증한다

**등록: 2026-08-25.** 구현 전에 판정 기준을 먼저 동결한다(상시 규율).
대상: 연출가 AI 설계도 엔진(docs/director-ai-vision.md)의 판단자 층.

> **다른 심판자와 헷갈리지 말 것.** `genesis/judge.py`는 *실험 증거*를 등록된
> 기준(criteria/*.yaml)으로 판정하는 심판자(5층·미정의 반환·골든 5종)다.
> 여기 `tools/judge_bench.py`는 그 아래 층이 아니라 **옆 층**이다 —
> 능력 원자가 들고 있는 심판이 심판 구실을 하는지 심판하는 **심판대**.
> 전자는 "실험이 통과했나", 후자는 "이건 애초에 심판인가"를 묻는다.

## 1. 지금 판단자가 약한 지점 (부검)

설계도 엔진 v0에서 "심판이 있나"를 정하는 것은 **세 군데의 자기 신고**뿐이다.

1. `data/capability_atoms.json`의 `verdict: "real"` — 사람이 손으로 적은 라벨.
   아무도 검증하지 않는다.
2. `check` 필드 — "…- 결정적" 같은 **한국어 문장**. 실행되지 않는다.
   문장 끝에 "결정적"이라고 쓰면 그게 곧 심판이 된다.
3. `promote_proposal(verdict="real")` — 게이트는 `check.strip()`이
   비어있지 않은지 하나뿐. `check="됨"`도 통과한다.

즉 **판단자는 라벨 조회기다.** 이건 이 프로젝트가 반복해서 적발해온
Goodhart 형태 그대로다 — 심판의 문구를 만족시키는 것이 심판을 통과하는
것과 같아진다. 연출가 AI의 상품성 전체가 "구성에 맞나를 기계가 잰다"에
걸려 있으므로, 여기가 가장 비싼 약점이다.

## 2. 강화 원리 — 심판은 반례를 거절할 수 있어야 심판이다

엔진에서 이미 증명된 패턴을 그대로 가져온다: fix 핸들러의 fail→pass 오라클,
test_add의 변이(mutation) 이빨, auditor의 종류별 불변식. 공통 구조는 하나다.

> **통과 사례를 통과시키는 것만으로는 심판이 아니다.
> 자기 반례를 거절할 수 있어야 심판이다.**

그래서 `real` 원자는 문장 대신 **실행 가능한 심판 명세(`judge`)**를 등록한다:

```json
"judge": {
  "kind": "numeric_delta",
  "params": {"before": "measured.bytes_before", "after": "measured.bytes_after",
             "min_delta": 1},
  "positive": {"measured": {"bytes_before": 900, "bytes_after": 100}},
  "negatives": [
    {"note": "정리했다면서 용량이 그대로", "mutate": {"measured.bytes_after": 900}}
  ]
}
```

심판대(`tools/judge_bench.py --audit`)가 이걸 **실행한다**:
- positive를 넣어 통과하지 못하면 → 실패(이빨 없음).
- negative를 넣어 거절하지 못하면 → 실패(이빨 없음).
- 둘 다 만족해야 `teeth`. 이때만 그 원자는 기계 체크리스트에 들어간다.

## 3. 반례 짚기(straw-man) 방지

반례를 아무렇게나 쉽게 등록하면 이빨은 다시 가짜가 된다("negative = 빈 입력").
그래서 반례는 **positive에서 한 곳만 바꾼 변이**로 등록하는 것을 정본으로 한다
(`mutate: {"<점 경로>": 값}`). 전체 샘플을 직접 쓴 반례도 허용하되
`straw_risk: true`로 표시해 감사에 남긴다. 정직 조항: **이 심판의 이빨은
등록된 반례만큼만 날카롭다** — 반례 수(`teeth`)를 항상 같이 보고한다.

## 4. 심판 종류(kind)는 레지스트리다 — 이름으로 분기하지 않는다

원자 이름으로 `if`를 치지 않는다(고용 아키텍처 규율과 동일). 종류를
`@kind("...")`로 등록하고, 원자는 종류 + 파라미터만 지정한다. v1 종류:

| kind | 재는 것 |
|---|---|
| `set_membership` | 보고 목록 == 입력 ∩ 규칙 목록 (권한 스캔·피싱 대조) |
| `numeric_delta` | 전후 측정 차이 ≥ 임계 (캐시 정리 회수량) |
| `threshold_desc` | 모든 항목이 임계 초과 + 내림차순 (§7.5의 threshold_match로 대체됨) |
| `hash_pairs` | 보고한 쌍의 내용 해시가 실제로 동일 (중복 파일) |
| `tag_cover` | 후보 태그가 설계도 요구 태그를 덮는가 (그림·음악 선별) |
| `forbidden_absent` | 금지 제약 위반이 없는가 (스토리 선별) |
| `all_tests_pass` | 명세 테스트 전부 통과 (게임 기능) |
| `human_gate` | **기계 심판 없음을 명시적으로 선언** (정직한 미분해) |

`human_gate`는 실패가 아니라 **정직한 신고**다. 감출 바에 선언한다.

## 5. 판정 기준 (숫자 보기 전 동결)

원자별 심판대 판정:
- `teeth` — positive 통과 ∧ 모든 negative 거절 ∧ 반례 ≥ 1 ∧ 결정적(2회 동일).
- `toothless` — 심판 명세는 있으나 위 조건 미달.
- `missing` — `real`인데 `judge` 명세 자체가 없음.
- `human_gate` — 사람 눈 게이트로 선언됨.
- `unknown_kind` / `error` — 명세 오류.

레지스트리 판정: **`verdict == "real"`인 원자는 전부 `teeth`여야 한다.**
`tools/judge_bench.py --audit --strict`가 이걸 종료코드로 강제하고, 테스트가
이 게이트를 상시 건다. 즉 **앞으로 심판 없는 원자는 real이 될 수 없다.**

설계도 판정: 체크리스트는 `teeth`인 항목만 담는다. 나머지는 `human_gate`
목록으로 분리하고, **기계 심판 커버리지**(teeth 항목 / 전체 범위)를
설계도에 숫자로 박는다. 비전 문서의 "분해가 많을수록 AI가 혼자 오래
굴러간다"를 처음으로 재는 계기다.

## 6. 하지 않는 것 (범위 동결)

- LLM에게 "이거 심판 가능해?"라고 묻지 않는다. 모델 주장은 v0에서
  이미 격리했고(`suggested_*`), 여기서도 신뢰 경로가 아니다.
- 심판 자체를 자동 생성하지 않는다. 사람이 명세를 등록하고, 기계는
  **그 명세가 이빨이 있는지만** 판정한다.
- 주관적 품질을 재려 하지 않는다. 재지 못하면 `human_gate`로 정직하게 남긴다.

# §7 어댑터 — 심판을 실제 산출물에 물린다 (등록: 2026-08-25 22:2x, 구현 전)

## 7.1 남은 구멍

v1의 심판은 **사람이 손으로 적은 샘플 dict**만 채점한다.
`{"output": {"bytes_before": 940000}}`의 940000은 아무도 잰 적이 없는 숫자다.
심판대는 "이 심판이 심판인가"를 증명했지만, **그 심판이 실제 파일을 채점할 수
있는지**는 아직 증명하지 않았다. 이대로면 설계도 체크리스트는 종이다.

## 7.2 네 이름공간 — 누가 말한 값인가 (2026-08-26: `observed.*` 추가, v1.2)

샘플의 모든 값에 **출처 등급**을 부여한다. 경로 접두사가 곧 등급이다.

| 접두사 | 뜻 | 신뢰 |
|---|---|---|
| `spec.*` | 설계도 — 사장님이 정한 것(요구 태그, 금지어, 임계) | 규칙이므로 신뢰 |
| `measured.*` | 어댑터가 **산출물에서 직접 잰 값**(바이트, 해시, 픽셀, 파일 내용) | 기계 측정 |
| `observed.*` | **제3의 모델(추출기 G)이 보고 보고한 값** — 후보가 만든 것도, 우리가 잰 것도 아니다 | 등록 전에는 판정 불가 |
| `claim.*` | 후보(생성 AI)가 **스스로 낸 보고** | 안 믿는다 |

Proposer/Validator 경계의 연장이다. 제안을 격리했듯, **보고도 격리한다.**

`observed.*`는 2026-08-26 사장님 승인(C)으로 신설했다(상속 문서 §3의 권고 →
규격 `judge-bench-v1.2`). 붙는 조건 둘:

1. **null 통제 전에는 판정 자체를 하지 않는다.** `data/observed_controls.json`에
   통제 통과로 등록된 필드만 쓸 수 있고, 미등록·미달이면 fail이 아니라
   **undefined**(`judge_bench.observed_gate`). 지금 등록된 필드는 0건이다.
2. **G 3회 다수결은 값 생산 규칙이지 심판이 아니다**(`tools/extractor_g.py`).
   과반이 아니면 값을 내지 않고, 미결정 필드는 키 자체를 만들지 않는다.

## 7.3 증거 등급 판정 (판정식, 숫자 보기 전 동결)

심판이 실제로 읽은 경로(= `params`의 값)를 접두사로 갈라 판정한다:

- `measured` — 결정적 입력에 `measured.*`가 하나 이상 있고, `claim.*`가
  있다면 그것이 측정값과 대조되는 구조다. → **기계 심판으로 인정.**
- `claim_only` — 결정적 입력이 `spec.*` + `claim.*` 뿐. 후보가 자기 성적표를
  써낸 것을 그대로 읽는다. → **통과해도 `pass_on_claim`**, 기계 체크리스트가
  아니라 사람 눈 게이트로 흐른다.
- `observed` — 결정적 입력에 `measured.*`가 없고 `observed.*`가 있다. 제3자
  관찰이라 자기신고보다는 낫지만 **자율 근거가 아니다**. 등급이 `measured`인
  심판이 observed도 읽는 경우는 `reads_observed`로 따로 드러낸다.
- `unbound` — 아직 이름공간에 물리지 않은 심판(v1의 `input.*`/`output.*`).
  이행 전 상태이며, 자율 근거로 세지 않는다.
- 이빨(§5)과 증거 등급은 **독립**이다. 이빨 있는 심판도 재료가 자기신고면
  자율 근거가 못 된다. 둘 다 통과해야 "혼자 굴러가는" 항목이다.

## 7.4 어댑터 = 레지스트리 (이름 분기 금지)

`@adapter("...")`로 등록하고, 산출물 경로를 받아 `measured.*`를 채운다.
읽기 전용·결정적·모델 호출 0. v0 종류:

| adapter | 재는 것 |
|---|---|
| `dir_files` | 디렉터리의 파일별 크기·내용 해시 |
| `dir_bytes_pair` | 전/후 두 디렉터리의 총 바이트 |
| `text_file` | 텍스트 파일의 실제 내용 |
| `image_probe` | 이미지의 실제 폭·높이·색 수(Pillow 있을 때만) |

## 7.5 새 심판 종류: `threshold_match`

"후보가 보고한 목록"과 "측정값에 규칙을 적용해 나온 목록"이 **정확히 일치**하나.
누락(놓침)도 과잉(부풀림)도 실패. 선언을 측정으로 대조하는 정본 형태다.

## 7.6 이 작업으로 드러날 것 (예상, 판정 아님)

기존 원자 9개 중 일부는 `claim.*`만 읽는다 — 특히 **그림·음악 선별**이
그렇다(후보가 붙인 태그를 그대로 읽는다). 그 수가 바로 "연출가 AI가 아직
자기신고에 기대는 정도"이며, 비전 문서가 말한 **주관 분해의 잔여 난제**를
숫자로 만든 것이다. 줄이는 것은 다음 작업이고, 이 작업의 결과물은 **정직한
숫자**다.

## 7.7 하지 않는 것

- 태그를 LLM에게 물어 `measured`로 승격시키지 않는다. 모델이 붙인 태그는
  영원히 `claim`이다.
- 어댑터가 산출물을 고치지 않는다(읽기 전용). 생성·수정은 다른 층의 일.
