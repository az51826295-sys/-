# 참피크(dBTP) v0 — 표준 라이브러리로 옮긴다 (사전 등록)

작성 2026-08-26 14:4x. 상속: `judge-bench-v1.2`.
대상: `audio.mechanical.true_peak`(초안 규칙 *"≤ −1.0 dBTP, 클리핑 fail"*).

**이미 재고 있다** — `genesis/audio_probe.py`가 librosa의 리샘플러로 4배
오버샘플해서 낸다. 문제는 그 값이 **librosa가 깔린 기계에서만** 나온다는 것이다.
`asset_probe`(표준 라이브러리 층)는 여전히 표본 피크만 내고, 이름도
`sample_peak_dbfs`로 정직하게 구분해 놓았다.

이 작업은 새 능력이 아니라 **같은 값을 의존성 없이** 내는 것이다. 그래야
서버·데스크톱·노트북 어디서든 같은 판정이 나온다.

---

## 1. 무엇을 구현하나 (동결)

BS.1770-4 부록 2의 참피크 추정:

1. **4배 오버샘플** — 표본 사이를 보간해 표본 사이에 숨은 봉우리를 찾는다.
   보간은 **윈도우드 sinc**(폴리페이즈 FIR): 위상당 탭 **32개**, 카이저 창
   β = 8.0.
2. 오버샘플된 신호의 절대 최대값을 dB로: `20·log10(peak)`.
3. 무음이면 값이 아니라 사유(−inf를 값처럼 쓰지 않는다).

탭 32·β 8.0은 **내가 고른 필터 설계값**이지 판정 문턱이 아니다. 다만 값이
달라질 수 있으므로 고정하고 리포트에 같이 낸다(측정 관례 표기 규율).

## 2. 정답 검증 (동결 — 값을 보기 전에 적는다)

여기는 외부 기준이 **둘** 있다. 해석적 정답과, 이미 있는 librosa 경로다.

| 시료 | 기대 | 근거 |
|---|---|---|
| 1 kHz 사인, 진폭 0.5 | −6.02 dBTP ± 0.05 | 봉우리가 표본에 거의 걸린다 |
| **표본 사이에 봉우리가 숨은 사인** (주파수를 표본율의 정수 약수에서 비껴 놓음) | 표본 피크보다 **크다** | 이게 참피크의 존재 이유다 |
| 0 dBFS 사인 | ≥ 0 dBTP | 오버샘플하면 1.0을 넘을 수 있다(정상) |
| librosa 경로와 같은 파일 | **± 0.3 dB 이내** | 같은 것을 재는가 |

**이빨**: 두 번째 줄이 핵심이다. 표본 피크와 **같은 값이 나오면 이 구현은
쓸모가 없다** — 오버샘플이 실제로 표본 사이를 보고 있다는 증거가 그 차이다.
차이가 0.1 dB 미만이면 필터가 일을 안 하는 것이므로 숫자를 낮추지 말고
**구현을 고친다**.

## 3. 하지 않는 것

- 표본 피크를 dBTP라고 부르는 것(지금 정직 조항이 막고 있는 바로 그것).
- 문턱(−1.0 dBTP)을 이 문서로 등록하는 것 — 규칙은 초안에 있고 동결은 별건이다.
- librosa 경로를 지우는 것. 두 경로가 **서로의 검증**이 된다(§2 넷째 줄).
- 무음에서 −inf를 값으로 내는 것.
