## 0. 한 줄 요약

실제 저장소 9과제에서 단일 에이전트와 제도형은 천장에서 동률이었으나
(89%/85%), 저항 3과제를 분리해 기제를 파고들자 병목의 사슬이
드러났다: **샘플링 다양성(프롬프트 지터)은 실코드에서 무효 → 원인
가설의 구조적 분화(탐색·패치 역할 분리 + 기계 검증 + 부정 증거
차단)가 처음으로 선택 공간을 열었다** (공개 통과 후보 0%→20%, 오파일
고착 최초 돌파). 남은 병목은 패치 완전성이다.

| 지표 | B0 | B-search |

| 후보 파일 다양성 | 0.73 | 1.27 |
| 정답 파일 포함 런 | 0.67 | 0.80 |
| 공개+스모크 통과 후보 존재율 | 0.00 | 0.20 |
| 완전 해결 | 0/15 | 1/15 |

과제별: running_minmax(오파일 고착) no_patch 5/5 → **public_only
2/5** (고착 최초 돌파, 숨김만 실패). isotime(다형식) 완전 해결 1/5.
t24_rollover(부수 회귀) regression 5/5 그대로.

운영 발견 2건: ① v1에서 모델이 함수 필드에 자유 텍스트를 써서
기계 검증기가 **정답 가설을 형식 문제로 탈락**시킴 (심볼 정규화로
수정) — "검증기의 입력 관용도가 곧 제도의 병목". ② 부정 증거
레지스트리 11회 차단 — 7D의 기억-모방 문제를 우회하는 제도적 대안
확인.

## 3. 시리즈 원리 갱신 (6→7D→Rookery)

1. 검증·선택·롤백 제도는 후보가 다양할 때만 가치를 갖는다 (6·7D).
2. DSL에서는 표집 자유도(패딩·온도)로 다양성이 열렸다 (7D).
3. **실코드에서는 표집 조작이 무효** — 병목은 표현이 아니라 초기
   원인 가설의 고착이며, **가설 자체를 구조적으로 분화**시켜야
   한다 (§6.8 기각 → §6.10 입증).
4. 다양성의 세 병목 계층: 표집 → 원인 가설 → (현재) 패치 완전성.

## 4. 다음 갈래 (결정 필요)

1. **A vs B-search 본실험 승격** — 저항형 과제 추가 채굴(오파일·
   다형식·회귀 위험 3원형), 총 API 비용 동일화(탐색 비용만큼 패치
   슬롯 축소), 18~30과제.
2. **패치 완전성 병목 공략 먼저** — t24류(회귀 회피)와 다형식
   커버리지를 위한 기제 (예: 후보에 회귀 스모크 결과를 관측으로
   제공, 완전성 체크리스트 없는 순수 관측형).
3. 여기서 Rookery 1차 동결 + 통합 논문화 (Series 1·2와 함께).

## 5. GPT와 논의할 질문 후보

1. 본실험 승격 시 비용 동일화 방식 — 탐색 1 + 패치 2 (총 비용 ≈
   A의 6패치)가 맞나, 아니면 wall-clock 기준?
2. 저항형 과제 채굴 기준을 "3원형"으로 사전 등록할 때의 선택 편향
   위험 — 원형별 최소 표본은?
3. 패치 완전성 병목은 proposer 문제인가 관측 설계 문제인가 —
   실패 관측에 "어떤 숨김 차원이 남았는지"를 노출하지 않으면서
   완전성을 유도할 수 있는 관측이 존재하는가?
4. running_minmax의 public_only 2건 — 숨김 실패의 내용이 "부분
   수정"인지 "과적합"인지 부검 가치.
5. 시리즈 동결 시점 판단 — 지금까지의 6→7→Rookery 아크만으로도
   "제도-다양성 공진화" 논문 한 편 분량인가.
