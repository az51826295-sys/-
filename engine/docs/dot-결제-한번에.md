## 순서 (내가 한다)

### 0. 먼저 잰다 — 짐작하지 않는다

```
npx tsx engine/tools/dot_pay_ready.mts
```

이게 **어느 칸까지 왔는지** 말해 준다. 여기 안 나온 것을 "됐다" 고 적지 않는다.

### 1. 업로드 키가 유효해졌나

Play Console → **테스트 및 출시 → 설정 → 앱 서명**.
"요청 처리 중" 이 사라지고 새 인증서가 보이면 된 것이다. 아니면 **기다린다**(앞당길 수 없다).

### 2. AAB 올리기

> 테스트 및 출시 → **내부 테스트** → 새 버전 만들기 → `dot-1.0.9-signed.aab`

거절당하면 **지문을 읽는다.** 10-28 에 기대 지문이 `upload_certificate.pem`(= `upload-new.keystore`,
비밀번호 모름)이라 막혔었다. 그때 `upload-2026.keystore` 로 다시 서명해서 뚫었다.

### 3. 구독 상품 만들기 — **1.0.9 가 올라가야 메뉴가 열린다**

> 수익 창출 → **구독** → 구독 만들기

| 칸 | 값 |
|---|---|
| 제품 ID | `menhera_sub` — **코드와 글자 하나까지 같아야 한다**(`src/lib/dot/money.ts`). 만든 뒤엔 못 바꾼다 |
| 이름 | 멘헤라 모드 |
| 설명 | 무제한 대화 · 선톡 · 집착 연출 · 블랙 타로 덱 |
| 요금제 ID | `monthly` · 자동 갱신 · 1개월 · **₩4,900**(대한민국) |

만든 뒤 **활성화**를 누른다. 안 누르면 앱에서 `상품없음` 이 뜬다.

### 4. 서버가 구글에 물어볼 열쇠

이게 없으면 서버가 "진짜 샀니" 를 못 물어서 **일부러 결제를 안 열어 준다.**

1. Google Cloud Console → 서비스 계정 → **키 → JSON**
2. Play Console → 사용자 및 권한 → 그 서비스 계정 초대 → 권한 **"재무 데이터 보기"**
3. Railway `dot-web` 환경변수에 **한 줄 JSON** 으로 `PLAY_VERIFY_KEY`
   같이: `DOT_PACKAGE=azcom.example.myapp` (`app/build.gradle` 의 `applicationId` 와 같아야 한다 —
   다르면 구글이 404 를 주고 우리는 그걸 "안 샀다" 로 읽는다)

### 5. 끝나고 재는 것

```
npx tsx engine/tools/dot_pay_ready.mts        # 막는 것이 0개인가
npx tsx engine/work/probe/dot-play-test.mts   # 순서(서버 확인 전에 안 닫는다) 16/16
```

그리고 **진짜 시험 구매 한 건.** 라이선스 테스터로 넣고 산다.

- 구독이 켜지나 (`dot_entitlements.menhera_until`)
- **승인(acknowledge)까지 갔나** ← 제일 중요하다

> 승인이 안 되면 구글이 **사흘 뒤에 돈을 돌려주고 구독을 거둬 간다.** 그때는 아무 오류도
> 안 나고 조용히 꺼진다. 코드는 넣었지만 **진짜 구매로는 아직 못 쟀다.**
