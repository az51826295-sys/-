# 제거 실험 사전 등록 — §6.11 구조 귀속 검정 (동결안 v1.1)

> 1개월차 1주차 등록. 실행은 2주차부터. 숫자 확인 전에 동결한다.
>
> **v1.1 수정 (2026-08-08, 데이터 관측 전)**: v1.0의 "라운드 상한
> 5"는 기존 §6.11 B-search 정의(= [가설 1 + 패치 3] × 2라운드 =
> **사례당 8호출 고정**)와 어긋난 오기였다. 제거 대상 구조를
> 있는 그대로 검정해야 하므로 실행 단위를 §6.11 정의에 정합화하고,
> "5"는 **사례당 반복(rep) 수**로 정정한다. 총호출 상한 산식은
> 18 × 2조건 × 5반복 × 8호출 = **1,440 불변**. 지표·최소 효과
> 크기·중단 규칙 변경 없음. 어떤 API 호출도 일어나기 전의
> 수정이다.
> 병목 지도의 유일 생존 후보 "탐색→가설→기계 검증→분화 배정
> 구조"(§6.11)가 성과의 원인인지, 동일 예산의 비구조 탐색으로도
> 같은 수치가 나오는지를 가른다. §6.12(레지스트리 제거)와 달리
> 이번엔 구조 자체를 제거한다.

## 조건 (2)

- **BS(구조)**: §6.11 그대로 (`run_arm_bsearch`, use_registry=True)
  — 라운드마다 가설 생성(1호출) → 기계 검증·선별 → 선별 가설별
  패치 제안(3호출) → champion 선택, ×2라운드 = 8호출.
- **BF(무구조)**: 가설 호출·가설 유래 focus·부정 레지스트리를
  제거. **8호출 전부 패치 제안**(기본 발췌 focus), 후보 중복
  제거와 공개 테스트 champion 선택·최종 검증은 유지 — 선택
  제도는 §6.11 이전부터 있던 기반이므로 제거 대상이 아니다.
  예산·모델·온도·과제·프롬프트 재료 동일. 차이는 구조 하나.

## 사례·라운드·예산 (숫자 먼저)

- 사례: **미소진 적격 과제 18건 전수** (classify_inc.candidates()
  산출, 2026-08-08 기준 동결 목록 — boltons 1, dateutil 2,
  marshmallow 10, more-itertools 1, sortedcontainers 1, tinydb 3).
  단 기계 입회 검사(selfcheck: repro가 parent에서 fail·fix에서
  pass, smoke가 parent에서 pass)를 통과 못 하는 사례는 실행 전
  제외하고 제외 사유를 기록한다 — 입회 검사는 §8.3 계측기 정지
  전례의 표준 절차다.
- 반복: 사례·조건당 **5 rep** (v1.1 정정 — §6.12의 rep 수와 동일).
- 실행 단위: §6.11 B-search 그대로 **사례당 8호출 고정**
  ([가설 1 + 패치 3] × 2라운드, 공개 통과 시 조기 종료).
- **총호출 상한 = 18 × 2조건 × 5반복 × 8호출 = 1,440**
  ≤ 월 예산 3,000의 60% = 1,800. ✓ 사례 축소 불필요.
- 조기 종료로 실사용은 상한보다 작다. 상한 초과는 불가(호출
  상한이 기계 강제).

## 지표

1차 (5종, §6.11과 동일 정의):
오파일 재방문률 / 정답 파일 포함률 / 고유 파일 수 /
기계 검증 통과율 / 공개 통과 후보 수.

2차: 사례당 성공률, 사례당 라운드 수, 사례당 총호출.

최소 효과 크기 (동결): 재방문률 차 ≥ 0.10, 정답 파일 포함률 차
≥ 0.15, 검증 통과율 차 ≥ 0.10. 미달이면 "동등" 기록 — §6.14의
전례대로 동등 판정도 닫힌 항목이다.

## 중단 규칙

1. 호출 예산 60%(864호출) 소진 시점에 완료 런이 절반 미만이면
   중단하고 사례 수 축소 재설계. 반쯤 돈 데이터로 집계하지 않는다.
2. 집계 코드는 골든 케이스(손으로 만든 소형 로그) 통과 전 실로그
   적용 금지. 골든 실패 = 즉시 중지.
3. 실행 중 지표 추가·프롬프트 수정 금지. 수정이 필요해지면 그
   시점까지의 런을 폐기하고 재등록한다.

## 판정

- BS가 1차 지표에서 최소 효과 이상 우위 → §6.11 구조 귀속 확정.
- 동등 → 구조의 고유 기여 없음으로 §6.11 가설 기각 (닫힌 항목).
- 혼재(지표 간 방향 불일치) → 해석하지 않고 설계 결함으로 기록,
  재등록 전 검정력 분석 선행.

## 계측기 정지 사례 1 (2026-08-08, 1차 시도 무효)

1차 본실험(13:45 시작)을 약 20런 시점에 중단 규칙 2로 정지했다.
채널 점검에서 **가설 라운드 24회 · 생성 0**이 발견됐고, 원인은
provider 초기화가 §6.x 실행부의 max_tokens=4000을 빠뜨려 기본
512로 돈 것 — 가설 JSON·긴 패치가 절단되고 파서가 조용히 빈 값을
반환했다. BF의 parse_fail 26%도 동일 원인 의심. 오염 원자료는
`data/ablation11_invalid_maxtok512/`에 격리 보존(약 130호출 지출,
월 예산에 정직 계상). 수정 후 재시작(14:01)의 첫 가설 라운드는
생성 5·선별 1로 채널 정상. 부수 수리: 가설 원시 응답이 로그에
남지 않던 관측 사각지대를 메움(`hypothesis_call(log=)`, 파싱 행동
불변). 교훈: **조용히 빈 값을 내는 파서는 계측기 사고의 표준
형태다 — 러너 가동 직후 채널 점검(생성·선별 카운트)을 표준
절차로 한다.**

## 판정 (2026-08-08, 본실험 완주 — 160/160런, 852호출/상한 1,280)

집계: 골든 통과된 `analyze_ablation.py`, 원자료
`data/ablation11_verdict.json`.

| 1차 지표 (후보 수준) | BS(구조) | BF(무구조) | 최소 효과 | 발동 |
|---|---|---|---|---|
| 오파일 재방문률 | **0.225** | **0.009** | 0.10 | **역방향 발동** |
| 정답 파일 포함률 | 0.75 | **0.95** | 0.15 | **역방향 발동** |
| 기계 검증 통과율 | 0.678 | 0.771 | 0.10 | 미달 (0.093) |
| 공개 통과 후보/런 | 0.375 | 1.075 | — | 역방향 |
| (2차) full률 | 0.238 | 0.375 | — | 역방향 |

- **판정: §6.11 구조 귀속 가설 기각 — 닫힌 항목.** 발동한 지표
  전부가 같은 방향(BF 우위)이므로 혼재 분기가 아니다. 동등을
  넘어 **음의 기여**: 이 코퍼스(실저장소 채굴 18과제)·예산(8호출)
  ·모델(Haiku)에서 가설-선행 구조는 자유 제안보다 측정 가능하게
  나빴다.
- **판정식 설계 누락 정직 기록 (P10·P16 계열)**: 등록서 3분법은
  "BS 우위 / 동등 / 혼재"만 정의했고 **일관된 역방향 우위** 분기가
  없었다. 기각 조항("동등 → 고유 기여 없음")의 강화형으로
  판정하되, 분기 누락 자체를 판정식 오류 이력에 남긴다.
- 기제 관찰 (판정 아님, 사후): ① 구조는 8호출 중 2회를 가설에
  쓰므로 후보가 적다(292 vs 428) — 제도의 정의된 비용. ② BS의
  가설 수준 재방문은 레지스트리가 실제로 막았으나(0.007) **후보
  수준 오파일 재방문은 0.225** — 잘못 지목된 가설 focus가 후보를
  오파일에 반복 결박한다. 레지스트리는 가설을 막고, 가설은 후보를
  가둔다. ③ §6.12(BS≈BSN)와 합치면: 살아남았던 유일 후보 §6.11의
  가치는 v3a 소코퍼스 3과제에서의 관측이었고, 18과제 채굴 코퍼스
  로 옮기자 사라졌다 — 코퍼스 의존성.
