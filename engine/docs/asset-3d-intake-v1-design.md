# 3D 자산 반입 규격 v1 — v0 에서 바뀐 것과 그 이유

2026-09-05 16:55. v0(`asset-3d-intake-v0-design.md`)로 실제 메시 둘(보물상자·마네킹)을
재고, 시행착오 학습 2회차(`gamedev-lessons-v0.md` §E)를 읽은 뒤 쓴다. v0 의 숫자는
v0 문서에 그대로 남는다. 여기는 **무엇을 왜 바꿨는가**다.

## 1. 바뀐 것

| # | v0 | v1 | 이유 |
|---|---|---|---|
| M1 닫힘 | FAIL 규칙 | **정보만**(재되 종합에 안 섞음) | 닫힘(watertight)은 3D 프린팅 기준이다. 실시간 게임 메시는 열려 있어도 렌더·콜라이더에 문제없다(polycount·sloyd·meshlib). 우리 두 판이 전부 여기서 떨어졌는데 그것은 **자가 엉뚱한 것을 잰 것**이었다 |
| 프로필 | 캐릭터 하나 | **character / prop** 둘 | 보물상자가 S1(높이)·A1(위 축)에서 떨어졌다. 소품은 낮고 옆으로 길다. v0 문서가 "소품은 v1 에서 따로" 라고 미리 적어 두었다 |
| S1 (prop) | 0.5~3.0 m | **0.05~10 m** | 소품 크기 범위. 컵부터 마차까지 |
| A1 (prop) | 가장 긴 축 Y | **정보만** | 소품에는 위 축 규칙이 없다. 상자는 옆이 길다 |
| B1 본 | 리깅 요청 시 ≥10 | 같음 + **Meshy 리깅 결과(GLB)를 잰다** | v0 에서는 리깅 API 를 안 붙여 요청해도 항상 0 이었다 |

바뀌지 않은 것: T1(2,000~40,000), T2(≤8), M2(법선), U1(UV), X1(텍스처), character 의 S1·A1.

## 2. 프로필은 누가 정하나

Vox 의 발주서(`wantRig`)가 참이면 character, 아니면 prop. 사람이 "소품" 이라고 하면
prop. 애매하면 character(더 엄격한 쪽) — 관대한 쪽으로 기울면 통과가 늘고 판정이 준다.

## 3. 리깅 (Meshy `POST /openapi/v1/rigging`)

- 입력: `input_task_id`(이미지→3D 작업 id), `height_meters`(기본 1.7). 5 크레딧.
- 조건: **휴머노이드만**, 텍스처 있어야, 얼굴이 +Z 를 봐야, 30만 면 이하.
- 출력: `rigged_character_fbx_url`/`_glb_url`, `walking_*`, `running_*`.
- 유니티: FBX 를 Rig → Humanoid. 걷기·달리기 FBX 가 같이 온다.
- 실패하면 5 크레딧은 돌아온다. **비인간형은 안 된다** — Box 처럼 팔다리가 표준이
  아니면 여기서 막힌다(사장님 게임 FUNCTION 의 Box 가 그 경우, 별개 트랙).

## 4. 바꾸지 않는 것

- v1 숫자는 다음 메시들을 본 뒤에 안 바꾼다. 바꾸면 v2 로.
- 판정기는 거르기만 한다.
