# 자산 심판 v0 — 아이콘 심판 해부와 상속 (2026-08-25 22:50)

초안 [asset-judge-v0-draft.md](asset-judge-v0-draft.md) §10의 배정 항목
**"inherits_from: 아이콘 심판 규격 ID — 해부 후 기입"**과 체크리스트 5번
**"아이콘 심판과의 규격 차이 목록화"**에 대한 답이다. 문턱(THRESH_*) 동결은
여기서 하지 않는다 — 사장님 결정 대기 항목이고, 원칙 ①이 걸려 있다.

## 1. 답: `inherits_from: judge-bench-v1.2`

아이콘 심판은 하나의 파일이 아니라 **세 겹**으로 돼 있다. 상속 대상은 그 겹의
계약이지 아이콘 스펙(`icon-24-line-v1`)이 아니다. 그래서 규격 ID를 여기서 명시한다.

| 규격 ID | 무엇 | 어디 |
|---|---|---|
| **`judge-bench-v1.2`** ← 상속 대상 (08-26 승인 전에는 v1.1) | 심판이 심판인지 판정하는 계약(이빨·증거등급·어댑터 결합·3값) | docs/judge-design.md, tools/judge_bench.py, tools/artifact_adapter.py |
| `icon-24-line-v1` | 아이콘 **자산 스펙**(문턱값 묶음). 상속 대상 아님 | data/icon_specs/icon-24-line-v1.yaml |
| `example-ab` 등 | 실험 증거 판정 기준(genesis/judge.py용). 다른 계보 | criteria/*.yaml |

`judge-bench-v1.2`가 보장하는 것(v1.1의 넷 + observed 관문):

1. **이빨**: 심판은 자기 반례를 거절할 수 있어야 등록된다(반례는 positive에서
   한 곳만 바꾼 변이). 문장으로 쓴 기준은 심판이 아니다.
2. **증거 등급**: 심판이 읽는 경로를 `spec.*`(설계도) / `measured.*`(기계가 잰 값)
   / `claim.*`(후보 자기신고)로 갈라, 자기신고만 읽는 심판은 통과해도
   `pass_on_claim`(자율 근거 아님)으로 내린다.
3. **어댑터 결합**: `measured.*`라고 **쓰기만** 한 것도 자기신고다. 그 값을 낼
   어댑터가 실제로 등록돼 있는지 대조한다(bound / no_tool / key_gap).
4. **3값**: 판정은 pass / fail / **undefined**. 문턱이 동결되지 않았거나 사람 눈
   게이트면 undefined다 — 초안 §6 `never`(문턱을 산출물 본 뒤 조정 금지)를
   코드가 강제한다. 08-25 22:47에 구현했다.
5. **종류 레지스트리**: 심판·어댑터는 이름으로 분기하지 않고 등록으로 늘린다.

## 2. 규격 차이 — 초안이 아이콘 심판보다 더 요구하는 것

초안은 아이콘 심판의 상위집합이다. 상속만으로는 안 되는 칸이 넷 있다.

| 초안 요구 | 아이콘 심판 | 차이 / 필요한 일 |
|---|---|---|
| 역할 분리에 **추출기(G)** 존재, 모델 호출 허용 | 없음(측정이 전부 순수 계산) | **새 층.** G는 심판이 아니라 증거 생산자 → 산출은 `claim.*`이 아니라 새 등급이 필요하다(§3) |
| 추출기 **독립성 계약**(원 스펙·파일명 금지) | 해당 없음 | 새 게이트 E3. 파일명 누출까지 막으려면 어댑터가 경로를 G에 넘기지 않아야 한다 |
| **골든 케이스 3종**(positive/negative/**null**) | 반례 변이(이빨)만 | 이빨은 심판 명세의 자기검증, 골든은 **실물 표본** 검증. 둘 다 필요하고 겹치지 않는다 |
| **3값 중 undefined의 사유 분류**(적격성 E1~E6) | undefined는 있으나 사유 구분 없음 | E1~E6을 등록 가능한 게이트로 구현해야 집계(`undefined_n`)가 의미를 갖는다 |
| 세트 층 | 아이콘은 중복·획 통일만 | 색상 분산·명도/채도 이탈·이상치 격리는 미구현 |

**같은 것**(그대로 상속): 탈락 기반 자세, 문턱 등록 후 실행, 합산 금지(필드별
독립 판정), 경계값은 `<=`로 통일, hidden 규칙 마스킹, 못 재는 항목의 명시적 신고.

## 3. 추출기(G) 등급 문제 — 상속만으로 안 되는 지점

초안의 G는 모델이다. `judge-bench-v1.1`의 등급 체계에서 모델 출력은 `claim.*`
(자기신고)인데, G의 출력은 **후보 자신의 주장이 아니라 제3자 관찰**이라 성질이
다르다. 그렇다고 `measured.*`도 아니다 — 재현되지 않고 신뢰도가 미측정이다.

권고: **`observed.*`를 넷째 등급으로 신설**하고, 다음 조건을 붙인다.

- `observed.*`만 읽는 심판은 **null 통제(초안 §7)를 통과하기 전까지 undefined**.
  통과 후에만 판정 자격을 준다. 초안 `status_unbuilt.mood_roundtrip_calibrated`가
  말하는 그 조건을 등급 규칙으로 박는 것이다.
- G 3회 호출 다수결(E4)은 `observed.*` 생산 규칙이지 심판이 아니다.

~~이건 **권고**이지 결정이 아니다.~~ **2026-08-26 사장님 승인(C).** 규격을
`judge-bench-v1.2`로 올렸다: `observed.*` 신설 + null 통제 관문
(`data/observed_controls.json`, 등록 0건) + G 다수결(`tools/extractor_g.py`).
자율 가능 비율은 여전히 `measured` 기준이며 observed는 세지 않는다.

## 5. 문턱 추천 — 동결 아님, 고르시라고 내는 것

원칙 ①과 UX 원칙(추천하고 사장님이 고른다)에 따라 **잴 수 있는 항목만** 추천한다.
못 재는 항목의 문턱을 추천하는 것은 숫자 놀음이다.

| THRESH | 추천 | 근거 |
|---|---|---|
| `THRESH_PAL` (팔레트 밖 픽셀 비율) | **0.005** | 안티에일리어싱 경계가 0.1~0.5% 나온다. 0이면 정상 자산도 떨어진다 |
| 경계 알파(초안이 이미 0.05로 박음) | 그대로 | 초안 값 유지 |
| `THRESH_DUR` (길이 오차) | **±0.5초** | 루프/전환 기준으로 사람이 못 느끼는 폭 |
| `THRESH_SIL` (앞뒤 무음) | **0.10초** | 루프 자산에서 0.1초는 이미 들린다 |
| true peak | 초안 −1.0 dBTP 유지, 단 **표본 피크로 대체 판정 시 −1.0은 느슨함** → 대체 시 **−1.5** 권고 | 표본 피크는 실제 피크를 과소평가한다 |
| `THRESH_SEAM` (이음새) | 시간영역 대체값 **0.02**(정규화 진폭 점프) | 스펙트럼 측정이 붙기 전까지의 대용. 붙으면 재등록 |
| 나머지 12개 중 BPM·조성·LUFS·세트 색상/명도/채도·이상치·중복 | **추천 없음** | 잴 도구가 없다. 도구가 생긴 뒤 표본을 보고 정하되, **표본을 보기 전에** 등록하는 순서는 유지 |
