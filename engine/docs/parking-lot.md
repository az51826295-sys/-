## 09-22 두 생각에 대한 메모 (만들 때 걸릴 것)

### 로키가 앱 안에 같이 들어가서 일한다

**내 읽기**: 사장님이 어떤 앱(브라우저·편집기·게임 엔진 등)을 열면 로키가 그 안/옆에서 화면을 보고
같이 손을 대는 것. 틀렸으면 그때 고친다.

- 09-17 에 만든 **손**([[rookery-hand]])과 09-18 주차장의 **폰판 손**(안드로이드 접근성)이 같은 줄기다.
  새로 시작하는 것이 아니라 그 줄기를 잇는 일이다.
- **제일 큰 문제는 "본다" 가 아니라 "누른다"** 다. 화면을 읽는 것까지는 이미 해 봤고,
  대신 누르는 것은 되돌리기 어려운 행동이라 **무엇을 사람이 확인해야 하는지 선을 먼저 그어야** 한다.
- 09-21 에 광고에서 그은 선과 같은 모양이 될 것이다: **기계가 할 것과 사람이 정할 것을 먼저 가른다.**

### 자동 메일 보내기

- **보내기는 되돌릴 수 없다.** 한 번 나가면 회수가 안 된다.
- 그러므로 **사람이 매번 확인하는 칸이 있어야 한다** — 적어도 처음에는. "자동" 의 뜻을
  *"로키가 알아서 보낸다"* 로 두면, 잘못 보낸 메일 하나가 사장님 이름으로 나간다.
  `초안까지 자동, 보내기는 손가락 하나` 가 안전한 첫 판이다.
- **사장님은 미성년자**다([[user-is-high-school-senior]]). 계약·결제와 마찬가지로 바깥으로 나가는 것은 더 조심한다.
- 이건 5단계(남에게 준다)와 붙어 있다 — 친구 다섯 명에게 줄 때 안내 메일이 필요해진다.

## 09-22 아침 — MCP 같은 구조 · 자동 업데이트

### MCP 처럼 만들기

MCP(Model Context Protocol) = **AI 에게 도구를 꽂는 표준 규격**. 서버가 "내가 할 수 있는 일" 을 정해진 형식으로
내놓으면 AI 쪽은 무슨 서버든 같은 방식으로 불러 쓴다. (이 대화도 MCP 로 돈다 — 브라우저·터미널이 그것이다.)

**세 갈래로 읽힌다. 고르기 전에는 못 만든다:**

| | 무엇 | 크기 |
|---|---|---|
| ㉠ **로키가 도구를 꽂아 쓴다**(손님) | Dev 가 바깥 도구를 골라 쓴다. **머리가 "어느 AI" 를 넘어 "어느 도구" 까지 정한다** | 큼 |
| ㉡ 로키를 도구로 내놓는다(서버) | 클로드 데스크톱 등에서 로키를 불러 쓴다 | 작음 |
| ㉢ 직원·기술을 꽂고 빼게 | 직원 추가가 지금은 코드 등록. 그걸 규격으로 | 중간 |

**내 짐작은 ㉠** — 북극성("AI 를 잘 다루는 AI")과 제일 가깝다. 사장님 확인 필요.

### 자동 업데이트 — **갈래마다 위험이 다르다**

| | 무엇 | 위험 |
|---|---|---|
| ㉮ **새 모델·도구가 나오면 알아서 갈아탄다** | 눈이 이미 매일 목록을 본다. 갈아타기만 사람 손 | 낮음. 잘못 갈아타도 되돌리면 된다 |
| ㉯ **로키가 자기 코드를 고쳐 스스로 배포** | 지금은 사장님이 `railway up` | **높음** |
| ㉰ 사장님 앱이 최신판을 받는다 | 안드로이드 로키·두근도트 | 낮음 |

**㉯ 는 따로 적어 둔다.** 지금 규율은 *"무인 판 중에는 배포도 안 한다"* 이고, 개입하면 그 회차가 끝난다.
스스로 배포하면 **로키가 자기를 망가뜨려도 아무도 안 막는다.** 09-22 아침에 배포를 안 해서 새 칸이
안 찍힌 일이 있었는데, 반대로 잘못된 것을 자동으로 올렸으면 그대로 돌았을 것이다.
만든다면 **되돌리기(한 판 전으로)와 사람 문**을 먼저 만들고 그다음이다.

### 둘 다 공통

**하기 전에 "무엇이 되면 된 것인지" 를 먼저 잠근다.** 09-21 에 세운 규율 그대로다.
MCP 는 특히 *"도구를 꽂았다" 와 "도구를 잘 골랐다" 가 다르다* — 앞은 기계가, 뒤는 사람이 본다.
