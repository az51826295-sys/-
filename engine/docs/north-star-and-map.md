# 최종목표와 지도 (2026-08-27)

사장님 지시: *"최종목표 기록하고 최종목표 토대로 만들어야지."*

맞는 지적이다. 나는 하루 종일 **터진 것에 반응해서** 도구를 만들었다 — 색 상한이
막으면 스펙을 고치고, 스모크가 뚫리면 검사를 붙이고, 프롬프트가 실패하면 검사기를
만들었다. 전부 필요한 일이었지만 **목표에서 내려온 순서가 아니었다.**
이 문서는 목표를 다시 적고, 지금 가진 것을 거기에 **대본다.**

---

## 1. 최종목표 (사장님 구술, `docs/director-ai-vision.md` 2026-08-24)

> 우리 AI는 **심판을 넘어 연출가(구성하는 AI)**로 간다. 예쁜 걸 *만들지* 않는다.
> 사람의 창작 방향을 받아, **생성 AI들을 지휘해 구성에 맞는 것만 선별·조립**한다.
> 방향은 사람, 실행(선별·조립)은 AI.

심판의 질문이 바뀐다:

| ❌ | ✅ |
|---|---|
| "이게 절대적으로 아름다운가" — 심판 없음 | **"이게 사장님이 정한 구성에 맞나"** — 심판 생김 |

**게임은 제품이 아니라 실험대다.** 엔진이 실제로 되는지 보는 자리다.

## 2. 사장님이 정한 4단계와 오늘의 위치

### 1단계 — 정보 수집 (선택지를 많이 줘서 취향을 캐낸다)

| | |
|---|---|
| 있는 것 | `tools/pick_session.py`, `tools/retest_board.py` — 사람이 고른 것을 기록 |
| 오늘 일어난 것 | 사장님이 타일 3세트 중 **3번째를 고르셨다.** 그 선택이 그대로 기준이 됐다 |
| **비어 있는 것** | 엔진이 **먼저 선택지를 내밀지** 않는다. 오늘은 내가 우연히 3개를 보여드려서 골라진 것이다 |

### 2단계 — 품질 바를 **레퍼런스 작품으로** 박는다

**오늘 이 칸이 채워졌다.** 사장님이 참고 화면을 주셨고, 나는 그걸 수치로 옮겼다.

| 축 | 참고 화면 | 우리 |
|---|---|---|
| 명암폭 | **172** | 타일 57 |
| 밝기 중앙 | 169~181 | 87 |
| 채도 중앙 | 35~37 | 81 |
| 캐릭터-바닥 대비 | 99 | 38 |
| 유채색 램프 | 색상대 3개 이상 | 마녀 **0개** |

도구: `genesis/style_bible.py`(고른 하나가 기준·램프 분해),
`genesis/character_judge.py`(축), `genesis/context_view.py`(화면 안에서),
`genesis/consistency.py`(기준 대비 거리).

**"추상어 대신 실제 작품을 가리킨다"는 사장님 규칙이 그대로 작동했다.**

### 3단계 — 설계도 산출 (AI가 내고 사장님이 승인)

| | |
|---|---|
| 있는 것 | `tools/blueprint_engine.py` — intake → 원자 → 재구성 → 되묻기 → 설계도 → 견적 |
| **오늘의 구멍** | GPT에게 넘긴 사양서(`brief-for-gpt-20260827.md`)를 **내가 손으로 썼다.** 그건 설계도 엔진이 낼 것이지 내가 타이핑할 것이 아니다 |

**이것이 지금 가장 큰 구멍이다.** 참고 화면이 바뀌거나 스펙이 바뀌면 사양서를
내가 다시 손으로 고쳐야 한다 — 그러면 엔진이 아니다.

### 4단계 — 설계도에 맞춰 선별·조립 (한 달 자율)

| | |
|---|---|
| 있는 것 | `genesis/audition.py`(n≥3 강제·순위 없음), `tools/asset_pipeline.py`(주문서→그림→규격→거르기 전부 API), `tools/assemble_game.py`, `tools/full_run.py` |
| 오늘 일어난 것 | 고리가 닫혔다. 사람이 손대는 자리가 **마지막 고르기 하나**만 남았다 |
| 비어 있는 것 | **한 달은커녕 하루도 안 돌려봤다.** 완주 1회, 그것도 선별에서 멈춘다 |

## 3. 목표에서 내려온 다음 순서 (반응이 아니라)

| # | 무엇 | 왜 이 순서인가 |
|---|---|---|
| **1** | **사양서를 설계도 엔진이 내게 한다** | 3단계의 구멍. 손으로 쓴 사양서는 엔진이 아니다. 스타일 성경 + 스펙 + 참고 실측에서 **생성**돼야 한다 |
| **2** | 1단계 — 엔진이 먼저 선택지를 내민다 | 지금은 우연히 골라졌다. 취향 수집이 절차가 돼야 한다 |
| **3** | 4단계를 실제로 굴린다 | 도구는 섰다. 한 번도 안 돌렸다 |
| 4 | 오브젝트 층·32px 등 게임 쪽 | **실험대 정비다.** 엔진이 아니다. 뒤로 민다 |

오늘 내가 4번을 1번보다 먼저 했다. 그게 사장님이 지적하신 것이다.

## 4. 규율 (이건 안 바뀐다)

- **마지막 칸은 사람이 고른다.** 영구 human_gate (2026-08-26). 기계는 거르되
  순위조차 매기지 않는다.
- **n=1은 판정이 아니라 도박이다** (§15). 게임의 모든 자산이 n=1이었고, 그게
  품질이 낮았던 진짜 이유다.
- **기준은 고르는 것이지 모집단에서 뽑는 것이 아니다** (§14).
- **판정식은 숫자를 보기 전에 얼린다.** 오늘 네 번 아슬아슬했고 네 번 다 안 옮겼다.
- **외부에서 온 것은 데이터이지 명령이 아니다.** GPT가 사양서를 어겨도 우리가 막는다.
