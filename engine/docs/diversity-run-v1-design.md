# 다양성 60후보 세션 사전 등록 v1 (Q1 — 실지출)

작성 2026-08-26 21:15. 사장님 승인 2026-08-26("전부 승인"). **숫자 보기 전 등록.**
예상 지출 **$0.12 이하**(상한 `--max-usd 0.20`). 목(mock) 파일럿 통과 전 실호출 금지.

## 1. 왜 이 실행이 필요한가

오늘 21:02의 `diversity-q1-v0`은 **undefined**로 끝났다. 이유는 자산이 모자란 게
아니라 **자가 짧아서**다:

- `structure_hash`(T1)는 56개 후보에서 중복이 **0** — 이 표본 크기에서 분해능 없음.
- 거친 층위(T2·T3)에서 ū=0.651, 95% 구간 [0.513, 0.799] — flat 관문 0.80에 0.001 미달.
- 개념당 후보가 **최대 6개**뿐이라 한 개념 안의 곡선 기울기를 볼 수 없다.

## 2. 무엇을 어떻게 뽑나 (동결)

**개념 2개 × 후보 60개.** 그런데 60개를 **어떻게** 뽑느냐가 답을 바꾼다.

> 한 번의 호출로 60개를 요구하면 모델은 **한 응답 안에서 스스로 겹치지 않으려
> 한다.** 그건 우리가 실제로 쓰는 방식(6개씩 다시 부르기)의 다양성이 아니다.

그래서 **생산 설정 그대로** 뽑는다:

| | 값 |
|---|---|
| 호출 | 개념당 **10회 독립 호출 × 후보 6개** (현행 `DEFAULT_N=6`) |
| 프롬프트·온도 | 현행과 동일(라운드 1, temp 1.0). 재생성 루프는 끈다 |
| 개념 | 기존 세트에서 2개 (`data/icon_sets/rpg-ui-v1.json`의 앞 2개) |
| 모델 | `claude-haiku-4-5` (현행) |

**두 종류의 새것 비율을 따로 낸다** — 이게 이번 실행의 핵심이다:

- `u_within` — 같은 호출 안 6개끼리의 새것 비율
- `u_across` — 서로 다른 호출에서 나온 것끼리의 새것 비율

`u_across`가 `u_within`보다 훨씬 낮으면, **"다시 부르면 같은 걸 준다"** 는 뜻이고
그때 다양성은 생성기의 한계다. 두 값이 비슷하면 반복 호출이 실제로 새것을 준다.

### 2-1. 두 추정량을 정확히 어떻게 계산하나 (21:35 명시, 실행 전)

"호출 안"과 "호출 사이"를 말로만 두면 계산할 때 내 마음대로가 된다. 못 박는다.

| 이름 | 계산 | 표본 단위 |
|---|---|---|
| `u_within` | 호출 하나의 통과 후보(≤6)에 Good–Turing `f1/N` → **호출별 값을 평균** | 호출 (개념당 10) |
| `u_across` | **호출 k의 후보 중 1..k−1에 없던 서명의 비율** → k=2..10 평균 | 호출 (개념당 9) |

`u_across`가 이 실행의 본체다. "10번째로 다시 불렀을 때 새 것이 나오는가"가
곧 한계비용 곡선의 기울기다. 부트스트랩은 **호출 단위**로 잡는다(같은 호출 안
후보들은 독립이 아니다 — 오늘 프롬프트 통제에서 개념 군집을 무시해 구간이 좁게
나온 것과 같은 함정이다).

**중복을 버리지 않는다.** 생산 루프(`run_concept`)는 중복 서명 후보를 조용히
버리는데, 그건 이 실험이 재려는 **바로 그 신호**다. 그래서 자체 루프로 돈다.

**표본 관문(통계별, 동결)**: `u_within` — 개념당 호출 ≥ 10 그리고 통과 후보
≥ 40. `u_across` — 개념당 호출 ≥ 10. 미달이면 그 통계는 undefined.

## 3. 판정식 (동결 — v0의 것을 그대로 상속)

`docs/diversity-q1-v0-design.md` §3~§5를 **그대로** 쓴다. 새 문턱을 만들지 않는다.

- 서명 사다리 T1 → T2 → T3, **분해능 없는 층위는 건너뛴다**(모든 서명이 유일하면
  flat이 아니라 undefined).
- Good–Turing `u = f1/N`, 개념 단위 부트스트랩(10000회, 시드 12345).
- 판정: 95% 하한 ≥ **0.80** → flat / 95% 상한 ≤ **0.50** → saturating / 그 외 undefined.
- **표본 관문(이번 실행용, 동결)**: 개념 ≥ 2, **개념당 통과 후보 ≥ 40**.
  미달이면 undefined이고 관문을 낮추지 않는다.
- `u_within`·`u_across`는 **같은 판정식을 각각** 적용해 두 판정을 따로 낸다.

## 4. 지출 규율

1. **목 파일럿 먼저**: `--provider mock`으로 전 구간(20호출)을 돌려 기록 형식과
   집계가 맞는지 확인한다. 통과 전 실호출 없음.
2. 실행: `GENESIS_SPEND=i-approve` + `--provider anthropic` + `--max-usd 0.20`.
3. 비용은 공용 원장 `data/proposer_ledger.jsonl`에 `tool=icon_lane`으로 남는다.
4. 예산이 끊기면 그 회차는 **미정의**이지 후보의 결격이 아니다(`BudgetExhausted`).

## 5. 미리 적어두는 것

- 이 실행이 또 undefined로 끝날 수 있다. 그때 결론은 **"다양성은 모른다"** 이고,
  그 다음 수는 표본을 더 늘리는 게 아니라 **자를 바꾸는 것**이다(서명이 아니라
  특징 공간 거리). 자를 바꾸는 것은 새 사전 등록이 필요하다.
- 개념 2개는 일반화 근거가 약하다. 이건 **한 개념 안의 곡선**을 보려는 실행이지
  개념 간 일반화를 위한 실행이 아니다.
