# 게임 트랙 v0 — "제도가 운영하고, 주민이 학습하는 도트 RPG"

작업명: **둥지마을** (가칭, 언제든 교체). 2026-08-06 사용자 확정:
아이디어 ①(자가 성장 게임) + ④(학습하는 NPC) 결합.

> 한 줄 비전: 개발자가 잠든 사이 게임이 스스로 패치되고(Rookery
> 제도), 플레이어가 노는 사이 마을 주민이 스스로 배운다(Genesis
> 경험 루프). 둘 다 이미 실증된 코드를 재사용한다 — 새로 발명할
> 것은 게임뿐이다.

## 1. 두 축과 그 출처

### 축 A — 제도가 운영하는 게임 (Rookery Alpha 재사용)

- 플레이어 버그 제보·크래시 로그 → **intake 5게이트** → 과제 →
  엔진이 밤에 수정 → 검증·감사 통과분만 → 아침 패치.
- 밸런스 수치(드랍률·데미지·경제)는 **기계 판정 가능한 영역**만
  자동 조정 대상으로 한다. "재미"는 사람 몫 — §2.3 정보 경계 준수.
- 에셋 공급: ComfyUI 파이프라인(도트화 후처리 포함)이 아이콘·
  몬스터·초상화를 야간 양산, 규격 검사(크기·투명배경·팔레트)
  통과분만 자동 반입.

### 축 B — 학습하는 주민 (Genesis 경험 루프 재사용)

- `genesis/` 미로 세계의 검증된 루프를 이식: **관찰 → 예측 → 행동
  → 예측오차 비교 → 경험 저장 → 세계모델 갱신**. 모델 호출 0원,
  결정론적, 오프라인.
- 주민은 플레이어의 행동을 관찰 대상으로 삼는다: 플레이어가 뭘
  사는지, 어디로 다니는지, 몬스터를 어떻게 잡는지 → 주민의 세계
  모델이 갱신되고 행동(가격, 동선, 대화, 경계심)이 바뀐다.
- **전 플레이어에 걸친 축적**: 서버가 경험을 모으면 마을 전체가
  함께 배운다. 밤(현실 새벽)마다 스냅샷 정리 = 인게임 서사로는
  "주민이 꿈을 꾸며 하루를 정리한다".

## 1b. 아트 품질 기준 (2026-08-07 사용자 확정)

**기준 게임: 스타듀 밸리.** 선택 이유: 1인 개발로 실제 도달된
최고점 — 목표가 증명된 좌표다. 이전 시도의 실패 원인은 에셋팩
혼용(일관성 붕괴)으로 진단됐고, 이번 구조에서는 생성원 단일화 +
규격 오라클로 구조적으로 차단한다.

**도출 규격 (동결)**
- 타일 16×16, 캐릭터 16×32, 아이콘 16×16 (전부 스타듀 규격)
- 뷰포트 640×360 + 2배 확대 = 화면상 타일 32px (스타듀와 유사 체감)
- 에셋당 색 수 ≤ 24. 전역 마스터 팔레트는 스타일 확정 화면에서
  추출해 동결
- 반입 오라클: 크기·색 수·투명배경·격자 정합을 기계 검사, 불합격은
  게임 폴더 반입 불가 (`tools/artgen/pixelize.py --check`)

**품질 사다리 (정직한 역할 분담)**
- 주인공·주요 NPC·핵심 몬스터: AI 다량 생성 → 선별 → Aseprite
  손질 마무리 (화면의 급은 영웅 에셋이 결정한다)
- 아이콘·타일·군중·배경: 파이프라인 순수 자동
- 걷기 애니메이션: AI에 약속시키지 않음 — 템플릿/수작업 병행

**0단계 = 퀄리티 대결 (데스크톱 준비 후 최초 작업)**: 같은 주제
3종(상인 캐릭터·마을 타일·검 아이콘)을 (a) SDXL+도트 LoRA,
(b) 도트 전용 모델(Retro Diffusion 계열)로 생성, 스타듀 스크린샷을
기준자로 3자 비교 → 승자 채택 → 후처리 통과본으로 합격 화면 1장
완성 → 규격 최종 동결.

## 2. MVP 범위 (P0)

작게. 판정 가능하게. 미로 세계가 그랬듯이.

- 마을 1개 (Godot 4, 2D 타일맵, 상하좌우 이동)
- 플레이어: 이동, 대화, 아이템 줍기/사기, 간단 전투 1종
- **학습 주민 1명** (상인): 플레이어의 구매 패턴을 관찰해 진열·
  가격을 조정. 성공 지표 = 예측오차 하강 (미로 세계와 동일 지표)
- 위 지표가 실제로 내려가는지 = P0 합격 판정. 재미는 아직 안 묻는다.

## 3. 기술 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 엔진 | Godot 4 + GDScript | 무료·2D 최적·코드는 Claude가 작성 |
| NPC 학습 | Genesis 루프를 GDScript로 이식 | 게임 안에서 0원·결정론 실행. Python 사이드카는 배포 복잡성 때문에 기각 |
| 경험 저장 | SQLite (Godot 내장) | Genesis와 동일 개념, 스냅샷·리하이드레이션 패턴 재사용 |
| 에셋 | ComfyUI API + 도트화 후처리 + 규격 검사 | tools/artgen 파이프라인 확장 |
| 운영 수정 | Rookery Alpha (이 저장소) | 게임 저장소를 대상 repo로 등록 |

## 4. 로드맵

- **P0 (데스크톱 준비 후 즉시)**: Godot 뼈대 + 걷는 마을 + 학습
  상인 1명. 판정: 예측오차 하강 곡선.
- **P1**: ComfyUI 설치 → 그림체 확정 → 도트 LoRA → 에셋 자동
  파이프라인 (규격 오라클 포함).
- **P2**: 게임 저장소를 Rookery Alpha에 등록 — 버그 과제화 →
  야간 수정 → 아침 패치 루프 가동.
- **P3**: 주민 확장(2~5명, 역할 분화), 공개 데모. "이 게임은
  AI 제도가 운영합니다" 페이지에 일일 보고 공개 (투명성 = 마케팅).

## 5. 정직한 경계 (선언)

- 재미·기획·서사는 자동화 대상이 아니다 (판정 불가 영역).
- 걷기 애니메이션 스프라이트는 AI 약점 — 공개 템플릿/수작업 병행.
- "주민이 학습한다"는 주장은 예측오차 곡선으로만 말한다. 곡선
  없이 말하지 않는다 (미로 세계 규율 유지).
