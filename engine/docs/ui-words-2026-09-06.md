## 읽은 것

- **토스 라이팅 원칙 8개** ([toss.tech](https://toss.tech/article/8-writing-principles-of-toss)). 우리 화면에 바로 걸리는 셋:
  - *말하기 쉬운 표현*: 입으로 읽어 자연스러운 말. 한자어·전문어 피함. → "판정", "산출물", "증거" 탈락.
  - *모두가 이해하는 표현*: 특정 업계만 아는 말 금지. → "자(ruler)", "못 잼", "판" 탈락(내가 만든 말).
  - *예측 가능한 힌트*: 버튼은 누르면 무슨 일이 나는지 그대로. → "고쳐 말하기"(무슨 뜻?) 탈락, "품질 판"(뭐가 나오나?) 탈락.
  - 그리고 **해요체**, 능동형, 긍정형. 앱인토스 가이드([링크](https://developers-apps-in-toss.toss.im/design/ux-writing.html))는 다이얼로그 왼쪽 버튼을 "닫기"로 통일.
- **남들이 같은 것을 부르는 말** (한국어 화면 기준):
  - 버전: 구글 문서 "버전 기록 · 이 버전 복원하기"([고객센터](https://support.google.com/docs/answer/190843?hl=ko)), 피그마 "버전 기록 · 이 버전 복원", v0·Lovable 은 "v1, v2 … / History / Restore".
  - 결과 보기: Rosebud·Lovable·v0 전부 "Preview"(미리보기). 대화 옆 칸의 이름이다.
  - 검사: GitHub 는 checks 를 한국어로 "검사", 결과는 "통과 / 실패 / 건너뜀".
  - 초안: 구글·네이버·브런치 모두 "초안" 또는 "임시 저장". 갓오브워 보라색 캐릭터 = 초안.

## 내 판단

내가 만든 말이 문제였다. "판·자·판정·증거·못 잼·산출물"은 심판 문서(judge-bench)의 말을 화면에 그대로 옮긴 것이다.
문서의 말과 화면의 말은 다르다. 화면의 말은 **처음 온 사람이 입으로 읽어 바로 아는 말**이어야 한다.

규칙 셋(우리 것):
1. **남들이 이미 쓰는 말이 있으면 그 말.** 버전·미리보기·복원·초안·검사·통과·실패.
2. **버튼은 누르면 생기는 일.** "시작", "수정 요청", "이 버전으로 복원", "고화질로 만들기".
3. **직원의 말은 해요체.** 사람이 말하는 것처럼. 라벨은 명사.
