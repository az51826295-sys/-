# 4단계 **최소판** — 완주 기준 (켜기 전에 잠금, 2026-09-21)

목적: **미끄러져도 손에 남는 것 하나.** 웹 게임 하나를 끝까지 완주한다.

## 이건 비교 시험이 아니다

2단계·3단계는 "둘 중 뭐가 나은가" 였고 그래서 띠·힘·멍청한 비교군이 필요했다.
이건 **한 번 되느냐**의 문제다(사장님 09-21). 그러니 신뢰구간도 힘 점검도 안 쓴다.
쓰는 것은 **짧은 통과 목록 하나**뿐이다.

## 통과 조건 (넷 다 만족)

1. **브라우저에서 열린다** — 파일을 열면 화면이 나온다. 빈 화면이 아니다.
2. **한 판이 끝까지 돈다** — 시작부터 끝(승리 또는 패배)까지 도달한다.
3. **기계 스모크 테스트를 통과한다** — 헤드리스 창에서 돌려(`appBuild/run.ts`)
   콘솔 오류 0 · 시작 시 빈 화면 아님 · 입력에 반응함.
4. **사장님이 5분 직접 해 본다** — 그리고 "이건 게임이다" 라고 하신다.

## 이 판이 **아닌** 것

- 재미있는가, 잘 만들었는가는 **안 잰다.** 완주만 잰다.
- 유니티·3D 는 안 간다. 웹 한 파일이다.
- **새 도구를 만들지 않는다**(사장님 09-21): *"목적이 '손에 남는 것 하나' 니까, 만들다가 계측 장치가
  또 늘어나면 그 목적에서 멀어져요."* 있는 파이프라인(`appBuild` + 고리)으로만 만든다.

## 기한

10월 중순까지. 미끄러지면 3단계가 아니라 **이것을 살린다**.
