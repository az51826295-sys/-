# 접근 토큰 건 — 기록과 **정정** (2026-09-21)

## 결론부터

- **폐기했다.** 401 로 확인했다(사장님이 supabase.com 에서 Revoke).
- **폐기 판단은 맞았다.** 값이 대화에 한 번 붙었기 때문이다.
- **그러나 내가 처음 말한 이유는 틀렸다.**

## 정정 — 내가 뭐라고 했고 실제는 무엇이었나

| | 내가 말한 것 | 실제 |
|---|---|---|
| 노출 위치 | **"커밋 이력에 들어 있습니다"** | **이 대화뿐이다** |
| 파일 | "스크립트 셋에 박혀 있다" | 그 줄은 자리표시자 `SUPABASE_PAT=sbp_...` 였다 |
| 디스크 | (확인 안 함) | 빌드 캐시·`.env.local` 포함 **어디에도 없었다** |

원인: `sbp_` **접두사**가 파일과 커밋에 있는 것을 보고 **값이 있다고 읽었다.**
전체 이력에서 토큰 값(`git log --all -S`)을 찾으면 **한 건도 안 나온다.**

## 그래서 무효가 된 확인

> *"토큰이 든 커밋은 `origin/main` 의 조상이 아니다"*

**이 확인은 아무것도 잰 게 아니다.** 그런 커밋이 애초에 없었다. 없는 것을 대상으로 "원격엔 없다" 를
확인한 셈이다. 같은 이유로 *"다음 푸시가 곧 유출"* 도 내가 만든 **거짓 경보**였다.

## 그래도 남은 것 (헛수고가 아니었던 부분)

- 공개 이력을 **길이 문턱 없이** 다시 훑었다 → 일곱 패턴 모두 실제 값 0건(커밋 363개).
- `pre-commit` 과 `pre-push` 훅을 걸고 **심어서 쟀다**. 진짜 `git push` 가 멈추는 것까지 봤다.
- 로컬의 큰 숫자들이 무엇이었는지 글자로 확인했다(아래).

## 세는 단위를 적는다 (사장님 규칙)

같은 것을 두 번 셌는데 숫자가 달랐다. **단위가 달랐기 때문이다.**

| 언제 | 세는 단위 | sk-ant | tvly | dodo_ |
|---|---|---|---|---|
| 처음 | `git grep -l` → **(커밋, 파일) 쌍** | 740 | 400 | 291 |
| 나중 | `git grep -o \| uniq -c` → **나온 횟수** | 742 (400 + 342) | 406 | 297 ×2 |

잡힌 글자는 `sk-ant-REPLACE-ME`(자리표시자), `sk-ant-`·`tvly-`(접두사만),
그리고 `dodo_probe.mts`·`dodo_env_push.mts` — **파일 이름**이었다.
즉 나는 **파일 이름을 열쇠로 세고 있었다.**

## 오늘 배운 한 줄

**재는 것보다 적는 데서 더 많이 샜다.** 오늘 틀린 여섯 군데 중 둘은 이미 재 놓고 보고에 안 적은 것이었고,
이 건은 **접두사를 값으로 읽은 것**이 출발점이었다. 숫자를 적을 때는 **무엇을 세는 단위인지**를 같이 적는다.
