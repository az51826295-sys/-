# 4단계 기준의 **알려진 한계** (2026-09-21)

이 글은 **기준을 바꾸지 않는다.** 개정판 4(`37492aad4dea5812`)는 그대로다.
읽는 사람이 통과의 무게를 스스로 판단할 수 있게 한계만 적어 둔다.

## ① 덧붙이기가 싸다 — 옆에 새로 짓는 방식은 문턱을 피할 수 있다

분자를 `추가 + 삭제` 로 세고 분모를 `2 × 전체 줄` 로 잡으면, **지우지 않고 옆에 붙이는 것**은
같은 크기의 고쳐 쓰기보다 절반 값이다. 그래서 **옛 코드를 남겨 둔 채 새 구현을 덧붙이면
거의 절반 크기의 재작성도 문턱을 안 넘는다.**

> 사장님: *"이걸 막으려고 규칙을 또 고칠 필요는 없습니다. 매 회차 원문과 diff 가 남으니 사람이 보면 드러납니다."*

그래서 **규칙을 더 고치지 않는다.** 대신 회차마다 남는 **요청 원문과 diff** 가 이 한계를 드러낸다.
통과를 읽을 때 "죽은 코드가 늘어난 통과인가" 를 같이 본다.

## ② 판정자와 주문자가 같은 사람이다

쉬운 고침 다섯 개로도 통과할 수 있다. 막지 않는다 — 대신 **요청 원문**이 회차마다 남는다(2판 ④).

## ③ 2·3번은 사람 칸이라 사람 시간이 든다

매 회차 뒤에 처음부터 클리어까지 한 번 해 봐야 한다. 다섯 회차면 다섯 번이다.
이건 비용이지 결함이 아니다 — 09-21 에 기계만 보고 통과시켰다가 못 넘는 발판을 놓쳤다.
