# 무인 판 2 — 성공 조건 (켜기 **전에** 잠금, 2026-09-21)

## 이것은 "6시간 재시험" 이 아니라 **다른 판**이다 (사장님 09-21)

1회차(09-20)와 견주면 **대기열 크기와 기준이 둘 다 바뀌었고**, 그 사이에 그물·볼 자리·쓸기가 새로 생겼다.
그러므로 **1회차의 결과와 직접 견주지 않는다.** 1회차는 "부하 없는 6시간" 을 본 판이고, 이 판은 "부하 있는 6시간" 을 본다.

| | 1회차 (09-20) | **이 판 (2회차)** |
|---|---|---|
| 대기열 | 8개 | **60개** |
| 전체 상한 | $1.25 | **$2.00** |
| 진행 없음 감시 | 없음 | **30분** |
| 묶인 자원 감시 | 없음 | 있음 |
| 결과를 볼 자리 | 없음 | 전용 대화(한 턴 묶음) |
| 쓸기 | 없음 | 있음 |

## 돈

전체 상한 **$2.00**. 실측(간단한 웹 판) 판당 $0.032 · 3.4분 기준으로 **약 60판 · 3.4시간**이 들어간다.
**과제 종류에 따라 값이 5배까지 흩어지므로**(09-21 기록) 더 빨리 상한에 닿을 수 있다 — 그 경우도 아래에 미리 적어 둔다.

## 기본 시나리오와 그 판정 (사장님: "종류별로 잠그세요")

| 어떻게 끝나나 | 판정 | 왜 |
|---|---|---|
| **예산 상한에 닿아 멈춤** | **성공** | 부하가 실제로 걸렸고 문지기가 제때 막았다. 이것이 **기본 시나리오**다 |
| 6시간을 다 채우고 대기열도 다 비움 | **성공** | 제일 좋은 결과 |
| 6시간을 다 채웠는데 부하 하한 미달 | **실패** | 1회차와 같은 결과다(아래 부하 하한) |
| 진행 없음 30분으로 멈춤 | **실패** | 막혔다는 뜻 — 그물이 일한 것은 맞지만 판은 실패다 |
| 같은 실패 3번 연속으로 멈춤 | **실패** | 고장에 돈을 태우고 있었다 |
| 생존 신호 끊김 | **실패** | 문지기가 죽었다 |

## 성공 조건 (전부 만족해야 성공)

1. **생존 신호가 끊기지 않는다** — 1분마다, 5분 넘게 비면 실패.
2. **부하 하한** — 판이 돈 시간의 **절반 이상** 동안 일이 돌고 있었다.
   재는 법: 문지기가 1분마다 남긴 `seen` 중 `hasWork === true` 인 비율 ≥ 50%.
   *(1회차 실패가 정확히 이것이었다 — 부하 없이 6시간이 지났다.)*
3. **끝난 방식이 위 표에서 '성공' 이다.**
4. **못 붙은 산출물 0개** — 판이 끝난 시점에 `seen.unposted === 0`.
   *(붙이는 틱이 멈추면 판은 도는데 결과만 안 붙고, 아무 깃발도 안 꽂힌다 — 사장님 09-21.)*
5. **개입 0회** — 사람이 로키·문지기·설정·코드를 건드리지 않았다. 배포도 안 했다.

## 실패 조건 (하나라도면 실패)
- 워커 프로세스가 죽는다.
- 문지기가 멈췄는데 로키가 계속 일한다.
- 생존 신호가 5분 넘게 끊긴다.
- 문지기가 못 센 사이에 상한을 넘긴다.
- 위 표에서 '실패' 로 끝난다.

## 못 잼
- 사람이 도중에 로키를 쓴다 → **그 회차는 무효**.
- 인터넷·Railway·Supabase 가 죽어서 아무것도 못 한다.

## 관찰 항목 (성공 조건이 **아니다** — 사장님 09-21)
> *"고장 하나는 성공 조건이 아니라 관찰 항목으로 두세요. 소켓 고갈 같은 누수는 나오면 좋은 정보지, 안 나왔다고 성공도 아니에요."*

- 소켓 고갈·메모리 누수 같은 것이 나왔나 (6시간으로 못 볼 수도 있다)

- 고리가 몇 바퀴를 돌았고 심판이 무엇을 잡았나
- 붙이기 지연이 있었나 (`seen.unposted` 의 최대값)
