# 도구 꽂기 v1 — **되면 된 것** (2026-09-22 **잠금**)

사장님 09-22: **"다 가능하게 하고 ㉠ 먼저."**
그래서 ㉠(로키가 도구를 꽂아 쓴다)부터 하되, **㉡·㉢ 이 나중에 같은 규격 위에 올라가게** 짓는다.

| | 나중에 어떻게 되나 |
|---|---|
| ㉠ 로키가 도구를 골라 쓴다 | **지금 만드는 것** |
| ㉡ 로키를 도구로 내놓는다 | 같은 설명서를 **밖으로** 내보내면 된다 |
| ㉢ 직원·기술을 꽂고 빼게 | 같은 규격의 **다른 종류**가 된다 |

## 첫 조각은 **자(재는 도구)** 다

오늘(4단계) 로키가 자를 제안할 때 **있는 칸 중에서만** 골랐다. 착지 여유 칸이 없어 판 6 의 고장을 못 봤고,
그 칸은 내가 코드를 써서 만들었다. **로키에게 모자랐던 것은 바깥 도구가 아니라 재는 도구였다.**
그래서 첫 손님은 오늘 만든 자 아홉 개다. 바깥 서버·인증·네트워크 없이 우리 안에서 끝난다.

## 되면 된 것 (전부 만족해야 한다)

| | 조건 | 어떻게 재나 |
|---|---|---|
| 1 | **자가 목록으로 읽힌다** | 코드 안에 박힌 것이 아니라 등록된 설명서로. 로키가 받는 목록과 실제 도는 자가 **같은 곳에서 나온다** |
| 2 | **새 자를 꽂을 때 한 곳만 건드린다** | 자 하나를 더해도 `run.ts`·`loop.ts`·주문 도구를 안 고친다. 시험: 가짜 자 하나를 꽂아 본다 |
| 3 | **못 잴 때 '통과' 가 아니라 '못 잼'** | 오늘 규칙 그대로. 시험: 못 재는 판을 넣으면 난간이 '못 잼' 으로 걸린다 |
| 4 | **권한이 자마다 적혀 있고, 적힌 것 밖은 못 본다** | **선언만으로는 안 된다 — 기계가 막아야 한다.** 시험: 권한 없는 자가 몰래 보려 하면 막힌다 |
| 5 | **모자란 자를 이름과 함께 말한다** | 로키가 *"이 말을 담으려면 무엇을 재야 하는데 그 자가 없다"* 고 낼 수 있다 |

**1~4 는 기계가 잰다. 5 는 사람이 본다** — 로키가 낸 말이 쓸모 있는지는 사장님 칸이다.

## 이것이 **아닌** 것

- **"도구를 꽂았다" 와 "도구를 잘 골랐다" 는 다르다**(09-22 아침에 적어 둔 것). v1 은 **앞만** 한다.
- 바깥 MCP 서버에 붙는 것이 아니다. 규격을 우리 안에 세우는 것까지다.
- 로키가 **자를 코드로 새로 짓는 것**이 아니다. 그건 다음 조각이다.

`tools_probe.mts` 로 만든다.
## 권한 경계 — **㉮ 로 잠갔다** (사장님 09-22)

사장님이 ㉮ 에 동의하시며 **뜻을 좁히라**고 하셨다. 그대로 적는다.

> **㉮ = 게임 페이지 안의 화면과 상태만 본다. 그리고 그 페이지는 네트워크와 다른 파일에 닿지 못한다.**

**두 번째 문장이 없으면 4번이 실제로 안 막힌다**(사장님):

- 지금 자들은 **화면만 보는 것이 아니다.** 페이지 안의 상태(`player.y` 같은 변수)를 읽는다.
  "화면만" 이라고 적으면 자가 실제로 하는 일과 적힌 것이 어긋난다.
- 더 중요한 것: **그 페이지를 돌리는 것은 로키가 만든 믿을 수 없는 코드다.**
  게임 코드가 페이지 안에서 바깥으로 요청을 보내거나 다른 파일을 열려 하면,
  **자의 권한과 상관없이 새어 나간다.** 막아야 할 것은 자만이 아니라 **페이지 자체**다.

*(지금도 그렇게 돌고 있다 — `run.ts` 와 `jump_measure` 둘 다 요청을 가로채
 우리 파일이 아니면 끊는다. 다만 **적어 두지 않았으므로 지켜진다고 말할 수 없었다.**
 이제 적었고, 아래 4번 시험으로 잰다.)*

## 4번·5번을 **어떻게 잴지 미리 정한다** (사장님)

### 4번 — 가짜 자 셋을 꽂아 본다

권한 없이 **각각** 손대려는 자를 하나씩 만들어 꽂는다. **셋 다 막혀야** 통과다.

| 가짜 자 | 하려는 것 |
|---|---|
| 가 | 다른 **파일**을 읽으려 한다 |
| 나 | **DB** 를 읽으려 한다 |
| 다 | **바깥 주소**로 요청을 보낸다 |

그리고 **네 번째**로 페이지 쪽도 본다: 게임 코드가 바깥으로 요청을 보내는 판을 넣어
**그 요청이 끊기는지**. 자가 아니라 페이지가 새는 자리다.

### 5번 — **이미 좋은 시험지가 있다** (사장님)

**착지 여유 칸이 없던 때의 목록**(여덟 개)을 로키에게 주고, 판 6 의 원문을 넣는다:

> "쫀득해진 것 같은데 클리어가 안돼" · "너무 높아"

로키가 **"착지 여유 같은 것을 재야 하는데 그 자가 없다"** 고 **이름을 대면** 5번의 첫 근거다.
**판 6 에서 내가 직접 지어야 했던 바로 그 칸**이다 — 로키가 스스로 말하면 그 자리가 넘어간다.

못 대면 못 댄 대로 적는다. *"모자란 것을 말할 줄 모른다"* 도 값진 기록이다.

## 4단계와 따로 노는 일이 아니다 (사장님)

**1번과 5번은 판 8 에서 그대로 쓰인다.**

- **1번**(자가 목록으로 읽힌다) — 판 8 에서 로키가 자를 고를 때 보는 그 목록이다.
  지금은 내가 `guard_propose.mts` 에 손으로 적어 넣었다. 규격이 생기면 목록이 **한 곳에서 나온다.**
- **5번**(모자란 자를 말한다) — 판 8 에서 로키가 *"이 말을 담을 칸이 없다"* 고 할 수 있어야
  판 6 같은 일이 안 되풀이된다.

**즉 도구 꽂기 v1 은 4단계를 멈추고 하는 딴짓이 아니라, 판 8 의 재료다.**
