# 우리가 부르는 이름이 다른 모델로 넘어간다 (2026-09-21)

## 잰 것

토큰 1개짜리 호출로 **응답이 스스로 말한 이름**을 받아 봤다(값 거의 0).

| 부른 이름 | 응답이 말한 이름 |
|---|---|
| `deepseek-v4-flash` | **`deepseek-flash`** |
| `deepseek-chat` | **`deepseek-flash`** |
| `deepseek-flash` | `deepseek-flash` |
| `deepseek-v4-pro` | `deepseek-v4-pro` |

**우리가 쓰는 이름 둘이 별칭**이고 같은 모델로 넘어간다. 목록 API 가 둘만 보여 주던 이유도 이것이다.

## 원장으로는 못 잡는다

`model_usage.model` 은 **우리가 부른 이름**이지 응답이 돌려준 이름이 아니다(`meter.ts` 의 `result.model`
이 요청 변수다). 그래서 *"124건의 model 칸을 날짜별로 세면 바뀐 날이 보인다"* 는 **안 된다.**
바뀐 날을 보려면 응답의 이름을 원장에 남겼어야 했다.

## 그래서 못 아는 것 (중요)

**별칭이 가리키는 모델이 언제 바뀌었는지 모른다.** 조사한 날짜로는 DeepSeek V4.1 Flash 가 09-10 에
나왔고, 우리 표본은 09-19(옛 고침 10판)와 09-21(오늘 2단계)이다. 둘 다 09-10 이후라 **한 모델일
가능성이 높지만, 기록이 없어 확인할 수 없다.** "높다" 로 적고 "확인됨" 으로 적지 않는다.

2단계 판정에 미치는 범위: 그 비교는 **자리 고르는 방식**(머리가 고름 vs 섞음)이지 모델끼리가 아니다.
다만 섞는 쪽이 이 별칭을 집을 때가 있으므로, **섞은 팔의 구성이 중간에 바뀌었을 가능성**은 남는다.
판정은 어차피 "모름" 이므로 결론은 안 바뀐다.

## 알림이 끊긴 원인 — **추정**

09-18·19 에는 *"쓰는데 사라졌다"* 알림이 떴고 09-20 부터 안 뜬다. 이름 가족 맞추기가
`deepseek-v4-flash` 를 `deepseek-flash` 의 가족으로 쳐서 삼킨 것으로 **보인다.**
맞추기 코드가 그대로였는지, DeepSeek 목록이 그날 바뀌었는지는 **안 봤다.** 그래서 **추정**이다.

## 다음에 할 일 (오늘은 안 고침)

1. **응답이 돌려준 이름을 원장에 남긴다.** 지금은 우리가 부른 이름만 남아 별칭 이동을 영영 못 본다.
2. 눈이 보는 곳을 넓힌다 — Gemini 는 열쇠가 있는데 안 본다. 영상 모델도 목록에 안 잡힌다.
3. 옮겨 갈지 정할 때는 **회사 공식 변경 기록**에서 한 번 더 본다. 오늘 날짜는 모아 보는 사이트에서 왔다.

## 이어서 (2026-09-22 새벽) — 칸을 만들었다. 다만 **어디까지 쟀는지**를 정확히

새 토큰으로 `model_usage` 에 두 칸을 더했다: **`answered_by`** 와 **`answered_fingerprint`**.

### 왜 두 칸인가

이름 하나로는 부족하다 — **같은 이름 뒤에서 모델이 바뀌면 이름은 그대로다.** 실제로 확인했다:

| 부름 | 응답이 말한 이름 | 지문 |
|---|---|---|
| `gpt-5.6-luna` (OpenAI) | `gpt-5.6-luna` | **없음(null)** |
| `deepseek-v4-flash` (DeepSeek) | `deepseek-flash` | **`aeb56401…`** |

정작 알고 싶은 것이 DeepSeek 별칭인데 **DeepSeek 은 지문을 준다.** 그래서 지문 칸을 같이 만들었다.

### 어디까지 쟀나 (사장님 09-22)

| | 상태 |
|---|---|
| 공급자가 응답 이름을 들고 온다 | **확인**(OpenAI 로 진짜 호출) |
| DeepSeek 이 이름·지문을 준다 | **확인**(직접 호출) |
| 계량기를 거쳐 **원장에 찍힌다** | **미확인** |
| DeepSeek 호출이 **우리 공급자 길로** 이름·지문을 싣는다 | **미확인** |

시험 호출은 회사 범위가 없어 원장에 안 적힌다. 그래서 **다음 실제 판에서 DeepSeek 행 한 줄을 눈으로 확인**해야 한다.
그 전에는 "원장까지 흐른다" 고 적지 않는다. (내가 한 번 그렇게 적었고, 그건 잰 것보다 앞선 말이었다.)

### 이미 쌓인 것은 여전히 모른다

새 칸은 **앞으로 생기는 행**에만 찬다. 이미 있는 124건은 비어 있다.
그러므로 **09-21 에 못 알아낸 "별칭이 언제 넘어갔나" 는 지금도 모른다.** 이제부터의 변화만 잡을 수 있다.
