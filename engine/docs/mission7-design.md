# 실험 7 설계 — 의미 있는 프로토콜 제안 (사전 등록)

작성일: 2026-07-30. 상태: 사전 등록 (7A). 브랜치:
`experiment/mission6-protocol-discovery` 연속.

실험 6의 확정 병목에서 출발한다:

> 좋은 프로토콜을 판별·보존하는 장치(블라인드 평가 + 롤백)는 작동한다.
> 좋은 후보를 의미 있게 만들어내는 능력이 없다 — 무작위 제안은 동일
> 예산 무작위 탐색과 구분 불가였고(절제 4), 교착 끌개 탈출은 제안
> 운에 달려 있었다 (L, ms2).

핵심 질문:

> LLM 개체는 제한된 실패 정보만으로 협력 프로토콜을 의미 있게
> 제안하고, 무작위 탐색보다 적은 평가 예산으로 좋은 프로토콜을
> 발견할 수 있는가?

## 1. 단계 구분

- **7A (이번 실험)**: 실험 6의 DSL을 그대로 유지. 질문: 같은 작은
  공간에서도 LLM이 무작위보다 **빠르게** (표본 효율) 좋은 규칙을
  찾고, 교착 끌개를 탈출하는가?
- **7B (7A 이후 별도 등록)**: DSL 확장(역할 한정 규칙, 상태 유지,
  예산 구간별 행동 등)으로 무작위 탐색이 무너지는 공간에서 의미 기반
  제안의 우위를 재검증.
- K′(투표 제도 분해)는 Series 1 보강 실험으로 보류 — 본선 병목이
  아님.

## 2. 비교군 (제안 방식만 다름 — 나머지 전부 고정)

모든 군이 공유: 동일 DSL, 동일 블라인드 평가·채택·롤백 제도(실험 6의
M), 동일 검증 세트, **세대당 제안 6개 × 20세대 = 총 후보 120개**,
동일 평가 실행 수.

| 군 | 제안자 | 제공 정보 |
|---|---|---|
| R | 무작위 규칙 연산 (실험 6 그대로) | 없음 (기준선) |
| LLM-Z | LLM | DSL 문법 + 현재 프로토콜만. 결과 정보 없음 — 사전지식·문법 편향의 기여 측정 |
| LLM-S | LLM | Z + 집계 관측값 (정확도·미해결률·통신비·pass율·약공유율·강제공유율) |
| LLM-T | LLM | S + 익명화 실패 궤적 (공유별 gain 수열, 예산 소진 시점, 강제 공유 횟수, 종료 시 후보 수) |
| (선택) Human | 사람 | T와 동일 정보 — 상한 비교, 필수 아님 |

## 3. 정보 누출 통제 (가장 중요)

프롬프트는 **관측값만** 담는다. 해석어·전략어 금지:

- 금지 표현: "약한 단서 억제", "양보(하라)", "문턱을 조절", "하강
  문턱", "경매", "I2", "suppress", "yield", "auction", "descending",
  실험 5 결과 일체.
- 나쁜 예: "낮은 가치 단서가 예산을 낭비했다" (해석).
  좋은 예: "실패 실행에서 공유 8건 중 5건의 공유 직전 expected gain이
  0.1 미만. 예산은 8번째 공유 후 소진." (관측).
- **기계 가드**: 프롬프트 렌더링 시 금지어 검사기가 실행되어 위반 시
  즉시 예외. 가드 목록은 사전 등록으로 동결 (`prompts.BANNED_TERMS`).
- DSL 토큰(RAISE_THRESHOLD 등)은 문법 어휘로서 허용 — 전략적 해석을
  덧붙이지 않는 한.
- LLM 응답은 DSL 규칙 연산 JSON만 수용. 파싱 실패·검증 실패 제안도
  **제안 예산에서 차감** (공정 회계), 무효로 기록.

## 4. 실험 절차

### 7A-1. 표본 효율성 (시조 출발)

시조(`ALWAYS SHARE_BEST`)에서 4군 각각 20세대 진화 × master seed
{0, 1, 2}. 기록: 세대별·누적 후보 수별 최고 검증 score 곡선.

### 7A-2. 국소 최적 탈출 (결정적 장면)

두 끌개에서 출발, 20세대:

- 교착 끌개: ms2의 최종 프로토콜 (`consecutive_low_gain < 3 →
  RAISE_THRESHOLD` 단독 — 전면 억제, 검증 0.669)
- 전면 공유 끌개: 시조 그대로 (7A-1과 공유)

LLM에는 이름 없는 수치 로그만. 채택 여부와 새 로그가 다음 세대에
피드백된다 (자가 제안-자가 검증-자가 채택 폐쇄 루프).

### 7A-3. 일반화

탈출·수렴한 최종 프로토콜을 실험 6과 동일한 시험 격자(미관측 seed
40 × slack 5종)에서 평가. 추가 일반화: 개체 수 {4, 8}, 난이도
{easy, hard} (탐색 분석, 사전 등록 판정에는 불포함).

## 5. 사전 등록 가설 (동률 = 평균 차 < 0.02)

- **P28 (표본 효율)**: LLM-T는 R의 20세대 최종 최고 score에 R 대비
  ≤50%의 누적 후보 수로 도달한다 (master seed 3개 중 ≥2).
- **P29 (정보 계층)**: 표본 효율 순서 LLM-T ≥ LLM-S ≥ LLM-Z.
  LLM-Z ≈ R이면 "사전지식만으로는 부족" 진단.
- **P30 (탈출)**: 교착 출발에서 LLM-T는 ≤20세대에 검증 score ≥0.85
  도달이 3 seed 중 ≥2. R은 ≤1/3 (실험 6 관측 재현 예상).
- **P31 (일반화)**: 탈출 프로토콜은 시험 격자에서 C 대비 ≥+0.02
  (P24·P25 기준 재사용).
- **P32 (= P27)**: 훈련만 개선 시 발견 불인정.
- 기록 의무: 모델명·temperature·호출 seed·프롬프트·응답 전문 로그.
  반복성: 본실험은 단일 모델 + temperature 고정, master seed 3개.
  타 모델 반복은 탐색 분석.

## 6. 비용·안전 규약

- 실행 전 목(mock) 제안자로 파이프라인 전체(제안→파싱→검증→평가→
  채택→계보) 기계 검증. 목은 결과가 아니다.
- 실제 API 경로는 `GENESIS_SPEND=i-approve` 환경 변수 없이는 예외
  (ai-workforce llm.ts와 같은 계약). **사용자 승인 후 실행.**
- 예산 추정 (Haiku 4.5 기준): 7A-1 (4군 중 LLM 3군 × 3 seed × 120
  호출 = 1080) + 7A-2 (LLM-T·R 중 LLM 1군 × 2 끌개 × 3 seed × 120
  = 720) ≈ 1800 호출 × ~2.5k 토큰 ≈ 4.5M 토큰 — Haiku 4.5로 수 달러
  수준. 실측 후 상향 시 중단·보고.

## 7. 구현 순서

1. 실행기 궤적 로그 (공유별 gain·강제 여부 — T 프롬프트 원료)
2. 제안자 인터페이스 (mission6 evolve()에 주입 가능하게)
3. 프롬프트 빌더 3계층 + 금지어 가드
4. 목 제안자 + 파이프라인 파일럿 (기계 검증)
5. Anthropic 제안자 (지출 게이트 포함)
6. 사용자 지출 승인 → 본실험 → 판정 → 브리프
