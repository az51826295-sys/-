## 1. 오늘 처음 일어난 일

**로키가 만든 게임이 컴파일을 넘어서 판정됐다.**

```
210초 · 통과 4 · 떨어짐 0 · 못 잼 0
  씬이 열리고 예외가 없다      ← 꺼진 입력 API 를 잡는 자리
  카메라와 보이는 것이 있다
  그림이 코드가 아니라 파일에서 온다  ← 초록 사각형을 잡는 자리
  입력을 주면 무언가 움직인다    ← 시작 이후 계속 미확인이던 자리
```

마지막 줄이 제일 크다. 어제까지 "조작은 못 쟀다, `SendKeys` 가 유니티에 안 닿아서
'안 움직인다' 와 '내 입력이 안 갔다' 를 구분할 수 없다" 였다. **이제 구분된다.**

3D 판에서도 다섯 중 넷이 통과하고 하나가 **못 잼**으로 나왔다(스프라이트가 없는
게임이라 잴 대상이 없다). 통과로 세지 않은 것이 중요하다 — 3D 게임마다 공짜
통과가 하나씩 붙었을 자리다.

## 2. 컴파일러가 못 보던 자리 셋을 막았다

| 자리 | 증상 | 막은 법 |
|---|---|---|
| **꺼진 입력 API** | 컴파일 통과, 키 눌러도 무반응 | 켜진 입력 방식을 프롬프트에 싣는다 |
| **없는 그림 참조** | 씬은 지어지고 화면만 빔 | 만든 것을 쓰는 판에 싣는다(어제) + 이름으로 입히기(오늘) |
| **3D 조명 없음** | 전부 검게 나옴 | 시험지에 항목 추가 |

`activeInputHandler: 1`(새 입력 전용)인데 생성 코드가 전부 `Input.GetAxisRaw` 였다.
**컴파일은 통과하고 실행할 때 던진다.** 어제 "조작을 못 쟀다" 의 원인이 하나가
아니라 둘이었고, 하나는 안 보이는 자리에 있었다.

## 3. 3D 와 순서 바꾸기

**3D 자리를 열었다.** 규칙을 잘라내지 않고 조립한다 — 잘라내기는 한 글자만
어긋나도 조용히 아무것도 안 지우고, 그러면 3D 프롬프트에 2D 규칙이 그대로 남는다.
그건 오류가 아니라 **잘못된 통과**다. 그리고 `route.ts` 가 따로 들고 있던 규칙을
한 벌로 합쳤다.

**프로토타입 우선으로 바꿨다.** 사장님 한마디가 열려 있던 둘을 같이 닫았다:
⑤(FAIL 인 그림을 어떻게 하나 — 판정 전에 승인이 오므로 없어짐), ⑦(vibe 경로가
승인 밖에 있다 — 고리가 그림을 안 쓰니 승인 문이 유일한 길이 됨).

첫 3D 게임이 나왔다: 모동숲 구조 그대로다. 나무를 흔들면 열매가 떨어지고, 줍고,
상자에 넣고, 배치 미리보기(유효 녹색·불가 빨강)가 따라다니고, **20초 기다리면
광원이 돌며 낮↔저녁이 바뀐다.** 합격 기준 11개. 31.8분, 26.4분 두 판.

## 4. 벽에 이름을 붙였다

**SNI 차단.** 심부름꾼이 `[SSL: WRONG_VERSION_NUMBER]` 세 줄만 남기고 죽었다.
같은 IP·같은 포트인데 **ClientHello 의 SNI 에 우리 호스트 이름이 있을 때만** 악수가
깨진다(빼거나 다른 이름을 넣으면 성공, 인증서도 온다). 브라우저는 되는데 크로미움이
ECH·HTTP/3 를 쓰기 때문이다. 우리가 고칠 수 있는 것이 아니라서 **이름을 붙였다** —
이름 붙은 벽은 사장님이 도메인을 바꾸든 길을 바꾸든 정할 수 있다.

`*.up.railway.app` 전체가 막힌다. **판정기도 거기 있어서 그림 판정이 UNDEFINED 가
된다.** 벽 하나가 두 곳을 막고 있다.

## 5. 유니티 AI — 다리는 놨고 관문이 남았다

패키지 안에 **문서화된 공개 API** 가 있었다(`AssetGenerators.GenerateAsync`).
`unity/UNITY-AI.md` 에 "에디터 창 안에서 사람이 쓰는 물건" 이라고 적어 둔 것은
틀렸다. 그림·**메시**·**소리**·재질·애니메이션이 열리고, **만들기 전에 견적을 주는
문**이 있어서 우리 지출 한도와 같은 규율을 걸었다. 발주서 단위로 넓혀서 유니티를
한 번만 켜게 했고, 예산은 발주서 전체에 붙는다.

**그런데 6.5 에서 유니티 자기 패키지가 컴파일되지 않는다.** 6.5 가 폐기 API 를
오류로 승격했고 패키지가 안 따라왔다(마지막 갱신 2026-02-23, 올릴 버전도 없다).
그래서 **Unity 6000.0.82f1 설치가 관문**이고, 지금 돌고 있다.

**새로 나온 것**: `ai-workforce` 에 git 원격이 없었다. 부트스트랩이 아무리 잘
돌아도 **새 기계가 코드를 받을 데가 없으면 그 앞에서 막힌다.** 세어 보기 전에는
아무도 몰랐다. 지금은 GitHub 에 올라가 있다.

## 7. 내가 틀린 것 (오늘만 여섯)

1. **`-nographics` 를 빼면 렌더러를 못 잰다** — 틀렸고 그것 때문에 25분을 멈췄다.
   우리가 보는 것은 그려진 그림이 아니라 씬 안에 무엇이 있는가다.
2. **프로토타입 계약을 2D 모양으로 줬다** — 3D 판에서 무시당했다. 문구는 그대로
   실려 갔고 모델이 안 썼다. **틀린 것은 답이 아니라 계약이었다.**
3. **3D 는 그림 목록을 비운다** — 고리가 바로 그리던 시절의 이유였는데 순서가
   바뀐 뒤에도 코드가 안 따라갔다.
4. **라이선스 자리를 틀리게 봤다** — 사장님은 로그인하셨는데 "없음" 이라고 했다.
   게다가 검사를 `if ($hasEditor)` 안에 넣어서 **에디터가 없으면 보지도 않았다.**
5. **설치 출력을 `Out-Null` 로 버렸다** — 에디터가 왜 안 깔리는지 이유를 내가
   없앴다. UAC 승격 요구였다.
6. **`unity.com` 링크를 확인 없이 드릴 뻔했다** — 이 기계에서 막혀 있어서 확인
   불가였고, 그래서 안 드렸다.

1·4·5 는 전부 **못 본 것을 없는 것으로 읽은 것**이다. 이 도구들이 하지 말라고
만든 바로 그 짓을 도구가 했다. **세는 도구가 틀리면 세는 일 자체가 소용없다.**
