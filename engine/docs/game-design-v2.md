# 게임 설계 v2 — 생활 시뮬레이션(모동숲 계열) · 초안

2026-09-03. **v1(Ethra 룩 소울류)을 대체한다.** v1 은 기록으로 보존 —
[game-design-v1.md](game-design-v1.md). v0(2D 마을 RPG)는 v1 이 이미 대체했다.

> 한 줄: **오늘 한 일이 내일의 마을을 바꾼다.** 압박도 실패도 없고,
> 쌓이는 것과 기다리는 것만 있다.

**이 문서는 초안이다.** 창작 방향은 사장님 것이라, 사장님이 정하실 자리는
`[정하실 것]` 으로 비워 두었다. 비운 자리를 내가 채우면 그건 사장님 게임이
아니게 된다.

---

## 0. 왜 v1 을 접는가

v1(소울류)은 문서로 확정된 설계였고 수직 슬라이스까지 정해져 있었다
("섬 하나, 화톳불 하나, 보스 하나"). 그것을 접는 이유는 하나다 — **09-01 에
사장님이 종류를 모동숲으로 정하셨고, 09-03 에 그 방향으로 자세히 짜라고
하셨다.**

접는 값도 적어 둔다. v1 에 있던 것 중 이 설계에서 **못 쓰는 것**: 스태미나·
구르기·록온·화톳불·죽음 루프·보스 패턴. **그대로 쓰는 것**: Ethra 룩 3D 도트
렌더링 경로(`poc3d/`), Mixamo 애니메이션 경로, PixelLab UI·아이콘.

---

## 1. 모동숲을 모동숲으로 만드는 것

기능 목록이 아니라 성질이다. 이 다섯이 없으면 열매를 아무리 떨어뜨려도
모동숲이 아니다.

1. **시간이 내 편이 아니다.** 오늘 못 한 것은 내일 온다. 서두를 방법이 없다.
2. **매일 조금씩 달라진다.** 어제와 다른 것이 하나는 있다.
3. **압박이 없다.** 실패·죽음·제한시간이 없다. 안 하면 그냥 안 될 뿐이다.
4. **내 것이 쌓인다.** 모으고 꾸민다.
5. **누가 나를 알아본다.** 주민이 나를 기억한다.

**1번이 등뼈다.** 나머지 넷은 1번이 있어야 뜻이 생긴다 — 내일이 오지 않으면
쌓일 것도, 달라질 것도 없다.

---

## 2. 우리 엔진이 이 설계에 거는 제약

설계를 엔진에 맞추는 것이 아니라, **엔진이 못 재는 자리를 알고 짓는다.**

### 2.1 하루를 기다릴 수 없다

판정기는 배치모드로 몇 분 안에 끝난다. 실시간 하루는 못 잰다. 그래서
**하루를 넘기는 동작이 게임 안에 있어야 한다** — 그것이 있으면 사람도 기다리지
않고 기계도 잴 수 있다. `[정하실 것 ①]`

### 2.2 숫자는 못 재고 물체는 잰다

판정기가 아는 말은 이것뿐이다: 움직인다 · 그대로다 · 생긴다 · 없어진다 ·
개수가 는다/준다 · 빛이 바뀐다.

09-03 에 이걸로 데였다. 모델이 "Carry 가 1 증가한다"를 `countUp target=Readout`
으로 옮겼는데, `Readout` 은 글자를 보여 주는 물체 **하나**라 숫자가 바뀌어도
개수는 그대로다. 그 줄들은 무조건 어김으로 찍혔다 — 게임이 아니라 표가 틀렸는데
판정문은 게임을 가리켰다.

그래서 설계 원칙 하나가 나온다:

> **상태를 숫자가 아니라 물체로 드러내라.**

주운 열매가 HUD 숫자로만 올라가면 못 잰다. **바구니에 실제로 쌓이면** 잰다.
이건 판정 편의만이 아니다 — 모동숲의 "쌓인다"는 원래 눈에 보이는 것이었다.

### 2.3 한 판에 만들 수 있는 양이 정해져 있다

파일 몇 개, 몇 분. 그래서 **수직 슬라이스 하나부터** 간다 — v1 에서 이미 정한
규칙을 그대로 잇는다: *"이것이 나올 때까지 다른 콘텐츠 금지."*

---

## 3. 축과, 기계가 잴 수 있는 정도

사장님이 물으신 "농사 같은 걸 추가할지"가 여기다.

| 축 | 기계가 잴 수 있는가 | 비고 |
|---|---|---|
| **농사·원예** | **높음** — 심으면 생기고, 하루 뒤 바뀌고, 거두면 없어진다 | 시간축과 직결 |
| **채집**(흔들기·삽질) | 높음 — 물체가 생긴다 | 지금 절반 있음 |
| **낚시·곤충** | 중간 — 타이밍은 사람 몫 | 손맛이 본체라 뒤로 |
| **상점·경제** | 낮음 — 돈이 숫자다 | §2.2 로 물체화하면 오름 |
| **주민 NPC** | 낮음 — 대화가 본체 | "말 걸면 반응한다"까지는 잼 |
| **꾸미기** | 중간 — 놓으면 생긴다. 예쁜가는 사람 | |
| **도감·수집** | 중간 — 항목이 생긴다 | |
| **계절·날씨** | 높음 — 빛과 물체가 바뀐다 | |

**왼쪽이 높은 축이 많을수록 로키가 혼자 오래 굴러간다.** 낮은 축만 넣으면 매 판
사장님 눈이 심판이 되고, 그건 나쁜 게 아니라 **속도가 사장님에게 묶인다**는
뜻이다.

---

## 4. 수직 슬라이스 — 밭 한 뙈기

**P0 하나만 만든다. 나올 때까지 나머지 전부 금지.**

가장 작으면서 §1의 등뼈(시간)를 담는 고리:

```
씨를 심는다 → 물을 준다 → 하루를 넘긴다 → 자라 있다 → 거둔다 → 쌓인다
```

이게 왜 최소인가: **"내가 어제 한 일 때문에 오늘이 다르다"** 를 담는 가장 작은
것이다. 물을 준 것만 자라므로, 자란 것과 안 자란 것의 **차이**가 인과의 증거가
된다. 그리고 그 차이는 기계가 볼 수 있다.

압박이 없어야 하므로: **물을 안 줘도 죽지 않는다.** 그냥 안 자란다.

### P0 합격 판정

**기계가 재는 것** (`unity_checks.py`):

| | 하면 | 되어야 |
|---|---|---|
| 1 | 빈 밭에서 심기 | 밭에 물체가 **생긴다** |
| 2 | 하루를 넘긴다 | 물 준 것이 **바뀐다**(자람) |
| 3 | 하루를 넘긴다 | 물 안 준 것은 **그대로다** ← 인과의 증거 |
| 4 | 다 자란 것에서 거두기 | 밭에서 **없어지고** 바구니에 **생긴다** |
| 5 | 아무것도 안 하고 하루를 넘긴다 | 사라지는 것이 **없다**(실패 없음) |

**사람만 볼 수 있는 것**:
- 자라는 것을 기다릴 만한가
- 하루가 지루한가, 조급한가
- 밭에 서 있는 것이 보기 좋은가

3번이 이 판의 핵심이다. 1·2·4는 "기능이 있다"를 재고, **3번만이 "이 게임이
모동숲인가"를 잰다.**

---

## 5. 그 다음 (P0 합격 전에는 손대지 않는다)

| 단계 | 내용 | 합격 판정 |
|---|---|---|
| P0 | 밭 한 뙈기 (4절) | 기계 5줄 + 사람 "기다릴 만한가" |
| P1 | 마을과 이동 — 걷기·카메라·집 | 사람: "돌아다니는 게 편한가" |
| P2 | 주민 하나 — 말 걸면 반응, 부탁 하나 | 사람: "다시 말 걸고 싶은가" |
| P3 | 상점·도감 — 팔고 채운다 | 기계: 물체가 오가고 항목이 는다 |
| P4 | 꾸미기 — 놓고 옮긴다 | 사람: "내 마을 같은가" |

**P2 가 Genesis 자리다.** [[game-design-v0]] 의 "학습하는 주민"이 여기 붙는다 —
다만 주민이 하나 서서 반응부터 한 다음이다.

자산(그림·메시·소리)은 09-01 규칙대로 **프로토타입이 승인된 뒤에** 들어간다.
P0 는 도형으로 만든다.

## 6. 사장님이 정하실 것

**① 하루를 어떻게 넘기는가 — 정해졌다(09-03 사장님).**

> "템포 빠르게 가져와야 해. 여기서 하루가 현실보다 더 빠르게."

**게임 하루 = 실제 3분.** 그리고 집에서 자면 즉시 다음 날. 진짜 실시간은 안 쓴다.

무엇을 얻고 무엇을 잃는지 적어 둔다.

| | |
|---|---|
| 얻는 것 | 한 자리에서 여러 날을 본다. 심고 자라는 것을 **한 판에** 확인한다 |
| 얻는 것 | 판정기가 하루를 넘길 수 있다 — 이게 없으면 농사를 기계로 못 잰다 |
| 잃는 것 | 모동숲의 **"오늘은 여기까지"** 가 약해진다. 서두를 수 있게 된다 |

잃는 쪽이 §1의 3번(압박이 없다)과 부딪힌다. 하루가 3분이면 "내일 하지" 가
"3분 뒤에 하지" 가 되고, 그건 기다림이 아니라 대기다. **그래도 사장님이 템포를
고르셨으므로 그대로 간다** — 다만 P0 를 켜 보시고 "너무 급하다" 싶으면 3분은
숫자 하나만 바꾸면 된다.

**플레이어는 집 앞에서 시작한다.** 이건 판정 때문이기도 하다 — 판정기는
플레이어를 걸어서 침대까지 데려갈 수 없다. 다만 모동숲도 집에서 시작하므로
**시험을 위해 게임을 비틀지는 않았다.** 그 둘이 갈렸으면 게임 쪽을 택했을 것이다.

**② 첫 작물이 무엇인가** — 창작이라 비워 둔다. 이름·모양·자라는 단계 수.

**③ 마을의 크기** — 한 화면인가, 걸어서 몇 분인가.

**④ 실패가 정말 없는가** — 모동숲은 없다. 확인만 받고 싶다.

**⑤ 3절의 축 중 무엇을 P3 이후에 넣을 것인가** — 낚시·곤충·계절·이벤트.

---

## 7. 안 하는 것

- **P0 전에 다른 축을 건드리지 않는다.** v1 에서 정한 규칙을 잇는다.
- **자산을 먼저 만들지 않는다.** 도형으로 굴리고, 승인 뒤에 넣는다.
- **주민 대화를 P2 전에 만들지 않는다.** 대화는 재기 어려운 축이라, 재기 쉬운
  것들이 먼저 서 있어야 한다.
