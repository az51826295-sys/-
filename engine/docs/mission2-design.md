# 실험 2 설계 — 분산 단서 추리 (협력이 구조적으로 필요한 과제)

작성일: 2026-07-30. 상태: 사전 등록 완료, 구현 진행.
배경: 실험 1([mission-design.md](mission-design.md))에서 상호작용 C군은
독립 B군을 이기지 못했고 단일 A가 최강이었다 (progress.md Findings).
사용자 방향: 실패를 패치하지 말고, **혼자서는 정보가 부족해서 여러
개체의 결과를 제대로 합쳐야만 풀 수 있는 과제**로 전환한다.

## 1. 과제 선택: 분산 단서 추리 (후보 3안 중)

| 후보 | 판정 |
|---|---|
| **분산 단서 추리** | **채택** — LLM 없이 결정론 구현 가능, hidden-profile 문헌과 직접 비교 가능, "협력 필요"를 생성 시점에 기계 보장 |
| 복잡 시스템 설계 | 평가자가 실험 1과 같은 판정 노이즈 문제를 그대로 가짐 — 보류 |
| 다조건 최적화 | 정보 분산의 자연스러운 이유가 없음(제약을 나눠 갖는 건 인위적) — 보류 |

**과제**: 숨은 정답 튜플(4속성 × 5값 = 후보 625개)을 단서(술어)들로
추리한다. 단서 전체를 합치면 정답이 **유일**하게 결정되고, 어떤 개체의
부분집합만으로는 후보가 **최소 20개 이상** 남도록 생성기가 보장한다.
→ "B(소통 없음)는 구조적으로 풀 수 없다"가 가정이 아니라 구성이다.

## 2. 비교 4군 (사용자 확정)

| 군 | 정보 | 소통 |
|---|---|---|
| A | 전체 단서를 한 개체가 봄 | 불필요 |
| B | 6개체가 분할 소유 | 없음 |
| C | 6개체가 분할 소유 | **자유 공유** — 각자 로컬 휴리스틱으로 무엇을 공유할지 선택 |
| D | 6개체가 분할 소유 | **인간 설계 절차** — 순번제로 기계적으로 공유 |

**공유 예산 희소성이 실험의 심장이다**: C·D 모두 총 공유 횟수 =
전체 고유 단서 수의 60%로 고정. 예산이 넉넉하면 D가 자명하게 이기므로
(전부 공유하면 끝), 희소 예산에서 **무엇을 공유할지의 선택**이 성능을
가른다. C의 휴리스틱: 공유 보드+후보 단서로 남는 후보 수를 가장 많이
줄이는 자기 단서(탐욕 정보 이득, 로컬 계산만 사용). D의 절차: 개체
순번제로 아직 안 나온 단서를 생성 순서대로 공유(체계적이지만 정보량에
눈멂). C와 D는 "선택의 지능 vs 절차의 보장" 대결이 된다.

## 3. 데이터 모델·모듈 (genesis/mission2/)

```python
class Clue(BaseModel):
    clue_id: str
    kind: Literal["NOT", "IS_ONE_OF", "PAIR_NOT", "IMPLIES"]
    params: dict          # 속성 인덱스·값 인덱스
    # NOT: attr != v / IS_ONE_OF: attr in {v1,v2}
    # PAIR_NOT: not (a1=v1 and a2=v2) / IMPLIES: a1=v1 -> a2=v2

class Instance(BaseModel):
    seed: int
    truth: tuple[int, ...]            # 정답 (검증 전용, 개체 비공개)
    clues: list[Clue]                 # 전체 집합 (유일해 보장)
    partition: list[list[str]]        # 개체별 clue_id
```

- `clues.py` 생성기: 정답 추첨 → 참 단서 풀 생성 → 후보 1개가 될 때까지
  탐욕 선택 → 잉여 단서 추가 → 분할 → **유효성 검사**(전체=유일해,
  개체별 잔여 후보 ≥ 20). 불충족 시 재생성. 전 과정 seed 결정론.
- `solver.py`: 625개 튜플 전수 필터 — 근사 없는 정확한 CSP.
  `expected_accuracy = 1 / |생존 후보|` (추측 표집 대신 기대값 —
  **판정 노이즈 0**, 실험 1의 교훈).
- `groups.py`: 4군 러너. 매 라운드 공유 1회씩, 예산 소진 시 정지.
  최종 점수 = max over 개체 of 1/|survivors(보드 ∪ 자기 단서)|.
- `report2.py`: 20 seed 집계 + 사전 등록 대조.

## 4. 지표

- **기대 정확도** (1차): 위 정의. 군별 중앙값/평균.
- 유일해 도달률: |생존|=1에 도달한 seed 비율, 도달 라운드.
- **공유 낭비율**: 이미 보드에 있거나 보드 생존 집합을 안 줄인 공유 비율
  (hidden-profile의 "공통 정보 편향"에 해당하는 우리 지표).
- 단서 커버리지: 종료 시 보드에 오른 고유 단서 비율.

## 5. 사전 등록 (실행 전 고정)

- **V1 (과제 유효성 게이트)**: A 기대 정확도 = 1.0, 20/20 seed.
  미달 = 생성기 결함, 실험 무효.
- **V2 (필요성 게이트)**: B 기대 정확도 < 0.2, 20/20 seed.
  미달 = 분할이 헐거움, 실험 무효.
- **P1**: C가 B를 20/20 seed에서 이긴다 (공유가 조금이라도 되면 후보는
  단조 감소하므로 — 미달이면 구현 버그를 의심하라).
- **P2 (핵심 질문 — 예측)**: 희소 예산에서 **C ≥ D가 seed 13/20 이상**.
  근거: C의 정보 이득 선택이 D의 눈먼 순번제보다 예산 효율이 높을
  것이다. **빗나가면**: 로컬 지능이 절차의 보장을 못 이긴다는 결과 —
  "자유 사회의 협업은 인간 설계 절차만 못하다"의 1차 증거로 기록.
- **P3**: D의 유일해 도달률 < 20/20 (예산 60%에서 절차만으로는 부족한
  seed 존재 — 아니면 예산이 아직 헐겁다는 뜻이므로 예산을 낮춰 재등록).
- 해석 규율은 실험 1과 동일 (seed 20 고정, 실행 중 튜닝 금지,
  부정적 결과 동일 형식 기록).

## 5.1 추가 등록 — E군 "똑똑한 D" (2026-07-30, 사용자 지시)

- **E**: 인간 설계 절차 + 지능 — 매 공유마다 각 개체가 자기 미공유 단서
  중 |생존(보드∪단서)| 최소값을 보고, 코디네이터가 전체 최선을 채택
  (중앙 정보 이득 스케줄). 사적 단서 자체는 보지 않음 — 로컬 계산 +
  조정 규칙만이므로 정당한 설계 절차. C와의 유일한 차이 = 선택의 중앙화.
- **P4**: E ≥ D 전 seed (미달이면 구현 버그).
- **P5 (예측)**: E ≥ C가 13/20 이상 — 중앙 선택이 C의 순서 무작위성을
  제거하므로 근소 우위. 빗나가면(C > E) 분산 탐욕이 중앙 탐욕을 이긴다는
  뜻으로, 순서 다양성이 탐욕의 국소최적을 피하는 효과를 시사.

## 6. MVP 제외

가설 공유(단서만 공유), 개체 traits(동질 개체 — 이 실험은 구조 변인만
분리한다; 역할·성향은 실험 3 이후), 거짓말/노이즈 단서, LLM.

## 7. 구현·검증 순서

1. clues+solver — 테스트: 생성 유효성(V1·V2 조건), 결정론, 수제 단서
   정답 검증
2. groups — 테스트: A=1.0, B<0.2, C/D 예산 준수, 결정론, 공유 후
   후보 단조 감소
3. report2 + 20 seed 본실험 → Findings
