# Rookery Reproduce — 제품 북극성 (2026-08-22 확정)

> 솔로 개발자 1명. 완성된 그림대로 만든다. 이 문서가 그 그림의 심장이다.

## 한 문장
**버그 신고문을 읽고 그 버그를 잡아내는 실패하는 테스트를 쓰는 AI —
단, 진짜 실패하는지 기계가 확인하고, 못 쓰면 입을 다무는.**

## 핵심 통찰 (이게 전부다)
**AI를 믿는 게 아니라, AI 뒤에 심판을 세운다.**
- AI는 창의적이지만 틀린다.
- 이 제품은 AI의 출력(재현 테스트)을 **기계가 실제로 돌려서** 검증한다
  (HEAD에서 진짜 실패하는가?).
- AI가 절반을 틀려도 고객은 **검증된 절반만** 받는다.
- 틀린 나머지는 **침묵** — 고객에게 안 간다.
- 그래서 모델이 좋아지면 우리도 공짜로 좋아지고, 모델이 틀려도 우리는 안 망한다.

## AI가 하는 일 (좁다, 그래서 성립한다)
이슈(자연어 버그 신고) → pytest 테스트 하나. 번역 + 추론.
- 읽기: 무엇이 잘못됐나 / 추론: 어떤 호출이 버그를 드러내나 / 작성: assert 한 줄
- 모델: Haiku로 충분. **이슈당 ~$0.002.** 침묵이 대부분이라 API도 거의 안 씀.

## AI가 안 하는 일 (규율 = 제품)
- ❌ 버그를 고치지 않음 (리뷰 부담을 만드는 것 = 우리가 반대하는 슬롭)
- ❌ AI 판단을 안 믿음 (기계 검증이 심판)
- ❌ 못 만들면 침묵 (거짓 양성 비용을 고객에게 안 넘김)

## 왜 이게 팔리는가 — 비대칭 (수율과 무관하게 참)
재현은 실패하면 아무것도 안 보내면 그만. 패치는 실패해도 상대의 리뷰 시간을 태운다.
**재현 상품은 거짓 양성 비용이 고객에게 전가되지 않는 유일한 형태.**
슬롭 금지 정책이 퍼질수록 이게 유일한 차별점.

## 진짜 해자
코드도 아이디어도 아님(둘 다 베낄 수 있음). **실행 + 제도(검증·감사 규율) + 실적.**
"믿을 수 있게 일한 증명된 기록"(감사 로그·머지 실적)은 하루아침에 못 만든다.
→ 거대 기업(OpenAI·Google)이 안 들어오는 골목. 걔네가 커질수록 필요해지는 층.

## 완성된 그림 (솔로 운영)
- 고객: GitHub 앱 설치 한 번 → 이후 재현되는 버그마다 봇 코멘트 + 감사 로그 링크
- 사장님: VPS 한 대, 대시보드 하루 5분 검토 한 명. 나머지는 서버가 조용히.
- 원가 페니, 번레이트 월 $50~100, VC 불필요.
- 백엔드 청사진·빌드 체크리스트: docs/rookery-architecture.md 그림3 (별도)

## 경계 (솔로 생존)
한 루프만 완벽하게: 이슈 → 재현 테스트 or 침묵 → 감사 로그.
팀 기능·권한·SSO·온프렘·설정 UI 없음. 고치지 않음. 기능요청 16% 자동 분리·버림.

## 출시 게이트 (돈 쓰기 전 수요 먼저)
1. 아웃리치 답 = "재현이 병목" → 무료 파일럿 1곳
2. 파일럿 머지율·손질률·재현율(고객 기준) → 첫 진짜 숫자
3. 그다음 MVP 툴(엔진에 GitHub 얼굴 붙이기, 솔로 2~3주) → 유료 1곳 → 출시
**아무도 재현을 병목으로 안 느끼면 여기서 멈춘다. 그 판정은 $0.**
