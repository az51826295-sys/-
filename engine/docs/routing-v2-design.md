# 라우팅 v2 — 기대 비용/해결 (2026-08-22 등록)

## 왜

(b) 원장 이득 재검증(docs/ledger-retest-live.md)의 판정 "원장 손해":
v1 규칙(fast 1차 승률 < 0.5, n≥8 → smart 직행)은 fast가 거의 못
푸는 대역에서 smart 직행을 골랐고, 해결 수는 늘지 않고(3 vs 4)
지출만 56% 늘었다. 원인은 규칙이 **성공 확률만 보고 실패의 가격을
안 본 것** — fast 시도($0.17)는 smart 시도($1.0~1.1)의 ~15%라,
fast 승률이 ~13%만 돼도 fast 선행이 해결당 싸다.

## 규칙 (기계 규칙, 프롬프트 불개입)

2시도 사다리의 두 선행 전략을 **해결 1건당 기대 비용**으로 비교:

- F (fast 선행): 비용 c_f + (1−p_f)·c_s, 해결 p_f + (1−p_f)·p_s
- S (smart 선행): 비용 c_s + (1−p_s)·c_s, 해결 p_s + (1−p_s)·p_s
- S의 해결당 비용 < F의 해결당 비용일 때만 smart 선행.

입력은 전부 원장의 측정값: p_f = fast 1차 승률, p_s = smart 전
시도 승률(1차든 승급이든 smart가 푸는 확률), c_f·c_s = 시도당 평균
실비(이제 `agent_outcome` 이벤트에 `usd` 기록). **증거 게이트**: 두
계층 모두 n≥8이고 가격 표본도 n≥8이어야 기본값(fast 선행)을 바꾼다.
시드 이력은 가격이 없으면 라우팅을 못 바꾼다 — 가격은 측정된 사실만.
명시 tier > 재시도 승급 > 경험 > 기본, 의 우선순위는 v1과 같다.

측정값 대입 (재검증 실측 p_f 1/13, p_s 3/12, c_f 0.17, c_s 1.1):
F ≈ $3.85/해결, S ≈ $4.40/해결 → fast 선행. v1은 smart 선행을 골랐다.

## 다음 측정 (등록만, 실행은 운영자 결정)

같은 두 팔 설계로 "v2 원장 vs 빈 원장"을 재측정하려면 ~$22가 든다.
그러나 현 측정 대역에서 v2는 빈 원장과 **같은 선택**(fast 선행)을
하므로 차이가 0이 예상되고, 실험의 정보 가치가 낮다. v2의 이득은
smart가 실제로 잘 푸는 종류의 일(p_s 높음)이 들어올 때 드러난다 →
코퍼스 종류가 다양해진 뒤 재측정. 판정표(그때 동결): 해결 A≥B &
지출 A<B → 이득, 해결 A<B → 손해, 그 외 미정 — (b)와 동일.
