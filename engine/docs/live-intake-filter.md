# 실전 투입 (a) — 이슈 선별 필터 (사전 등록, 2026-08-15 동결)

> 남의 열린 이슈에는 정답이 없다. 기존 테스트 통과만으로 받으면
> §8.3의 비대칭 — 망가뜨린 건 잡히고 못 끝낸 건 안 잡힘 — 이
> 그대로 노출된다. 판정이 예측이 아니라 **실행**에서 나오게 하는
> 수용 조건을 지금 정한다. 필터 없이 가면 측정이 아니라 시연이다.

## 수용 규칙 (둘 중 하나, 기계 확인 필수)

1. **재현 테스트 동봉형**: 이슈(또는 연결 PR·재현 스니펫)에 실패
   테스트가 딸려 있고, 그 테스트가 현행 HEAD에서 **실제로 실패**
   함을 기계 확인.
2. **유도 가능형**: 이슈 본문의 재현 절차에서 실패 테스트를
   기계적으로 유도할 수 있고, 유도된 테스트가 현행 HEAD에서
   실패함을 확인. 유도 테스트는 루키의 수정 금지 대상(테스트
   파일 불변)에 편입된다.

어느 쪽도 안 되면 **수용 거부** — 거부도 기록한다.

## 첫 관측치 = 필터 통과 수율

(a)의 1차 산출물은 "고쳤는가"가 아니라 **열린 이슈 중 몇 %가
실행-판정 가능한 형태인가**다. 이 수율이 낮으면 그것이 시장
관측이고(무인 판정 가능한 일감의 밀도), 높으면 루키의 실전
코퍼스가 생긴다. 어느 쪽이든 측정이다.

## 판정 연결

- 수용된 이슈의 성공 판정: 유도/동봉 재현 테스트 fail→pass +
  스모크·회귀 불변 (엔진 기존 오라클 그대로).
- 천장 대비: 이 코퍼스는 주입 버그보다 어려울 것으로 예상되나,
  그 예상 자체는 판정에 쓰지 않는다 — 원샷 해결률을 관측치로
  기록만 한다 (30~60% 목표 대역은 코퍼스 v2 시절의 참고치).
- (b) 장부 재검정은 이 코퍼스가 쌓인 뒤 그 위에 등록한다 —
  보드게임 숫자 이식 금지 원칙 유지.

배수·비율에 **분모 병기**. env 수리 후 verify-정의 수율 배수는 셋이다 —
**v2 7.6배(61/85 vs 8/85) · v1 2.3배(35/61 vs 15/61) · 합계 4.2배(96/146 vs
23/146)**. 그리고 이 수율은 위 오염률로 다시 할인된다.

### 흡수 범주 = 대기열, 계측기 사고 5호 (사장님 1번)

세 저장소가 통째로 버려지는 동안 계측기는 정상으로 보였다(v2 invalid 73/85=86%가
표에 아무 이상 없이 앉아 있었다). **교훈(계측기 사고 계보 5호): 흡수 범주
(invalid·env·기타)는 결론이 아니라 대기열이다. 정기적으로 재실행해 비우지 않으면
그 안에서 수율이 7배 눌려 있어도 표에는 안 나타난다.** 처방(등록): selfcheck에
"흡수 범주 비율 > 40% → 경보" 규칙(dryrun48의 rising 감시와 같은 꼴; 인테이크
보고에도 invalid율 상시 산출).

### 기능 요청은 실행 신호로 분류 (v1.3 대안, 사장님 부수 지적)

v1.3 본문 어휘는 정밀도 3/6·재현율 3/11로 기각됐지만, **실행 기반 신호**가 더
정확하다: `cannot import <요청 함수>` / `assert hasattr(...)==False`가 이번에
기능 요청 17건(v2 9+v1 8)을 잡았고 표본에서도 위양성이 안 보였다. 등록: 유도
테스트의 실패가 (없는 이름 import 오류) 또는 (없는 속성 hasattr 단언)이면
`feature_request`로 분류. 이미 있는 로그로 사전 등록 후 재집계 = $0. 모델 1회
분류보다 이걸 먼저.

### 수리 안건 (등록, 드라이런 후 — intake 파일은 드라이런이 매시간 import)

1. **워크트리 import 프리플라이트 + src 경로**: 저장소별로 유도 테스트를 돌리기
   전에 `python -c "import <pkg>"`를 워크트리에서 확인. 실패하면 그 저장소는
   `env_blocked`로 표시하고 후보를 무효로 세지 않는다(62건이 유도 실패로
   위장하는 것을 차단). 수리는 **`PYTHONPATH=<wt>/src`**(워크트리 범위) —
   **전역 `pip install -e` 아님**: 후자는 공유 site-packages를 오염시켜 드라이런
   인터프리터·genesis 스위트까지 바꾼다. **실증 완료(08-22 밤, 격리 워크트리,
   $0)**: marshmallow는 PYTHONPATH=src로 import되고(의존성 packaging 기존재),
   env-invalid였던 #1971이 수집오류→FAILED(재현)로 전환. 배선(harness 편집,
   head_worktree에 env 주입)만 드라이런 후 — 편집 대상 live_intake_verify.py를
   드라이런이 매시간 import하기 때문. **설치 자체는 애초에 필요 없다.**
2. **기능 요청 기계 신호(v1.3 재설계)**: 본문 어휘(정밀도 0.5로 기각)가 아니라
   **유도 테스트가 import하는 이름이 HEAD에 없다**로 판별 — triage에서 8/8이
   기능 요청이었다(정밀도 높음). verify 후처리로 `cannot import <name>`이면
   `feature_request` 별도 큐. 측정: 같은 25건 라벨과 대조(등록).
