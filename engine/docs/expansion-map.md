# 확장 지도 — 우리 상품은 "검증 가능한 일들의 공장" (2026-08-24)

**논의 종결 (2026-08-24, docs/conversation-kit.md §0)**: 대화는 ① 버그 재현
단독으로 나간다. ②·③ 언급 금지. 확장 순서는 09-05 두 판정(대화 5건 + 메인테이너
반응 5건) 뒤 결정. 이 지도는 그때 **우선순위 필터**로 다시 쓴다.

## 한 문장
우리가 파는 건 "AI"가 아니라 **"AI + 심판"**이다. 심판(기계 검증)이 있는 일이면
무엇이든 상품이 될 수 있다. 그래서 확장 = **새 AI가 아니라, 심판이 있는 새 일**.

## 규칙 (3항 — 2026-08-24 개정)
```
상품 = (심판 있음) × (고객이 지금 아파함) × (판정이 고객 눈에 증거로 보임)
```
아래 4층 표는 **1항(심판 있음)만** 채점한 것이다. 09-05 이후 3항 전부로 다시
채점하면 "확장 지도"가 아니라 "우선순위 필터"가 된다. 2·3항은 대화 5건이 채운다.
- 코드 버그 재현 → 테스트 돌려서 "진짜 실패" 확인 → 심판 있음 ✓
- 풍경 그림 → "맞다/틀리다" 기계가 못 잼 → 심판 없음 ✗ (AI가 없어서가 아니라)

| ① 출시 준비 | **버그 재현** (테스트가 HEAD에서 실패하나) | 오늘 만듦·라이브 증명 |
| ② 코드·테스트만 있음 | 버그 수정·문서화·테스트 추가·데이터 변환 | **합성/로컬에서만 돎 — 외부 저장소 끝까지 런 0건(원장 확인 08-24). "엔진에 있습니다"는 못 쓰는 문장** |
| ③ 후보 | **데이터 정합성(1순위)**·설정 오류·보안 취약점 재현(후순위) | 심판이 있을 법함, 미착수. 보안은 오탐 1건이 신뢰를 통째로 날리는 비대칭·격리 미비라 뒤로 |

| ④ 범위 밖 | **주관적** 이미지·글쓰기(자유 풍경·그림) | 심판 없음(취향). 단 스펙으로 조이면 ③으로 승격 가능(아이콘이 예) |

**정직 정정(08-24 원장 확인)**: ②는 **코드·합성 테스트만** 있다. 외부 저장소에서
끝까지 돈 건 agent_fix(버그 수정/재현 경로)뿐이고 doc·test_add·data는 외부 0건.
그래서 대화에서 "엔진에 있습니다"라고 말하지 않는다(금지 문장, kit §5).

## 논의할 열린 질문 (이게 이 글의 진짜 목적)
**"확장 먼저냐, 검증 먼저냐."** 두 입장이 팽팽하다:

- **확장 먼저 (플랫폼론)**: 단일 작업(버그 재현)만으론 "제품"이 아니라 "기능"이다.
  고객이 지갑을 여는 건 "여러 검증된 일을 해주는 플랫폼"이지 한 가지 트릭이 아니다.
  ②가 이미 있으니 몇 개 더 꺼내 "묶음"으로 내놔야 팔린다.
- **검증 먼저 (규율론)**: 고객 0명일 때 상품 5개 = 공급이 수요 공백을 가리는 함정
  (오늘 하루 종일 경계한 것). ① 하나로 고객 1명 얻어 "이게 팔리나"부터 확인하고,
  ②는 그 뒤 일주일이면 나온다.

**둘 다 맞는 부분이 있다**: 플랫폼론은 "얇은 단일 기능은 약하다"가 옳고, 규율론은
"검증 안 된 다섯 개는 검증 안 된 한 개보다 다섯 배 위험"이 옳다.

**타협 후보** (논의 씨앗):
- 첫 대화에서 "버그 재현 + 테스트 추가 + 설정 검증" **셋을 묶어** 제안하되,
  실제로 **깊게 만든 건 ①만**. 나머지는 "됩니다"가 아니라 "엔진에 있습니다"로.
- 즉 **말은 플랫폼, 손은 한 개** — 파일럿이 어느 일을 제일 원하는지 그때 ②에서
  꺼낸다. 확장의 순서를 우리가 아니라 고객이 정하게.
