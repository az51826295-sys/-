# Rookery 실험 1 설계 — 코드 수정에서의 제도형 vs 단일 에이전트 (사전 등록)

작성: 2026-08-02. 상태: 동결 (2026-08-02, 자체검증·목 파일럿 통과). 근거: 사용자 결정
(2026-08-02) + 실험 6~7D 교훈.

핵심 질문:

> 동일 예산에서 단일 패치 생성 방식보다, **다양한 후보 생성 + 기계적
> 중복 제거 + 블라인드 테스트 + champion–challenger 선택** 구조가 더
> 높은 숨겨진 테스트 통과율과 낮은 회귀율을 만드는가?

7D 교훈의 제품 반영 (아키텍처 원칙):
- proposer에는 **현재 상태와 직접 실패 관측만** 제공 (과거 패치
  이력은 프롬프트에 넣지 않음 — Registry에만 저장)
- 중복 회피는 LLM이 아니라 **구조 비교(정규화 코드 동치)**로 처리
- 다양성은 온도(1.0)와 다중 제안으로 확보
- 유효성은 공개 테스트(Validator)가, 최종 성적은 숨겨진 테스트가 판단
- 악화 시 champion 롤백 (실험 4 원리: 복구 공간)

## 1. 과제 도메인

자체 제작 파이썬 버그 수정 코퍼스 16문제. 각 문제 = 결함 있는 함수
1개 + **공개 테스트**(proposer·selector가 사용) + **숨겨진 테스트**
(최종 평가 전용, 선택에 불사용 — 유출 시 무효). 버그 유형: 경계
오류, 잘못된 연산자, 초기값 오류, 누락된 기저 사례, 상태 오염 등.
숨겨진 테스트는 공개 테스트가 놓치는 모서리를 포함하도록 설계 —
"공개만 통과, 숨김 실패"가 회귀(과적합)의 조작적 정의.

안전 규약: 생성된 패치는 실행 전 정적 검사(import·파일·네트워크·
프로세스 호출 금지, 함수 본문 화이트리스트)를 통과해야 하며,
테스트는 타임아웃 있는 격리 서브프로세스에서 실행한다. 검사 실패
패치는 무효 처리(예산 차감).

## 2. 비교군 (문제마다 양군 실행, 쌍대 비교)

**A — 단일 제안 (통상적 코드 에이전트)**: 호출 1회당 패치 1개.
실패하면 같은 에이전트가 직전 실패 관측(테스트 출력)을 받아 수정.
예산 = 문제당 LLM 호출 6회 순차.

**B — Rookery 제도형**: 라운드당 후보 3개 생성(동일 프롬프트, 온도
1.0) → 정규화 중복 제거 → 공개 테스트로 채점 → champion보다 나은
후보만 채택, 아니면 롤백 → 실패 관측을 다음 라운드의 **현재 관측**
으로 제공 (과거 후보 프롬프트 미포함). 예산 = 2라운드 × 3후보 =
호출 6회 (A와 동일).

동일 통제: 모델(claude-haiku-4-5), temperature 1.0, 호출 수 6,
프롬프트 기본 구조, 테스트 실행 상한, 문제 순서.

## 3. 지표 (사전 등록)

주 지표: ① 숨겨진 테스트 통과율(최종 champion 기준), ② 회귀율
(공개 통과·숨김 실패 비율). 부 지표: 해결까지 후보 수, 토큰 비용,
중복 패치율(B), 롤백 횟수(B), 실패 후 회복률(첫 시도 실패 문제 중
최종 해결 비율).

## 4. 가설 (동결 예정)

- **R1**: B의 숨겨진 테스트 통과율 ≥ A + 10%p (16문제 쌍대).
- **R2**: B의 회귀율 ≤ A (공개-과적합을 제도가 걸러냄).
- **R3**: B의 실패 후 회복률 > A (다양한 후보 + 롤백 = 복구 공간).
- **R4 (정직 조항)**: A가 동등 이상이면 — 이 난이도의 단일 함수
  수정에서는 제도 오버헤드가 이득을 상쇄한다고 기록하고, 난이도
  축(다중 파일·상호작용 버그)을 후속 등록한다.

## 5. 절차

1. 코퍼스 16문제 작성 + 자체 검증 (정답 구현이 공개+숨김 전부 통과,
   버그 구현이 공개 테스트 ≥1개 실패)
2. 목 제공자 파일럿 (파이프라인 기계 검증 — 결과 아님)
3. 등록 동결 → 본실험 (예상: 16문제 × 2군 × 6호출 ≈ 200호출 ≈ $0.5~1)
4. 판정 → 브리프

## 6. 보조 레인 (후순위, 별도)

7E: Sonnet에서 TP vs TS 재실행 (판별력 최고 2군만). 해석 등록:
TS>TP = 큰 모델의 구조 기억 활용 가능성 / TS≈TP = 크기 무관 무가치 /
TS<TP = 모방 문제 지속. n=5 한정, 방향성 탐색으로만 기록.
