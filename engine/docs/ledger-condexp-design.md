# 조건 실험 사전 등록 — 장부는 실제로 이득인가 (동결안)

> 3개월차 1주차 등록. 숫자 확인 전 동결. 진입 근거:
> [ledger-boardgame-rules.md](ledger-boardgame-rules.md) 5.1 진입
> 판정 표 (U_calls 전 해상도 10~24배, 균형점 후보 local) — 이
> 표의 인용이 등록 요건이다. 이번 달은 호출 예산 피크: 다른
> 실험을 병행하지 않는다.

## 총호출 산술 (먼저)

풀설계 4조건 × 20런 × 8라운드 × 8호출 = **5,120 > 3,000 예산 초과.**
축소 우선순위(유지 순서 2 → 2.5 → 3, 조건 1은 기준선 필수):

- 조건 {1, 2}: 2 × 20 × 8 × 8 = **2,560 ✓** (진입 판정의 T_exp와
  동일 — 소급 위반 없음)
- 조건 {1, 2, 2.5}: 3,840 ✗

**이번 주기 실행 = 조건 1·2만, 20런씩.** 조건 2.5(장부+중앙 확정)
·3(장부+프로토콜 채택·롤백)은 다음 예산 주기로 이월 — 런 수는
줄이지 않는다 (실험 1의 σ 교훈: 런이 적으면 분산에 묻힌다).
파일럿 192호출 포함 총 2,752 ≤ 3,000.

## 과제와 런

- 과제: 닫힌 DSL(GameSpec)로 2인 GRID 게임 설계. 판정은 실험 1과
  동일한 결정론 battery (`static_issues` + `evaluate_spec` +
  `objective`, judge seed = `judge:{seed}` — 역사 수치와 비교
  가능).
- 런 = seed 1개의 설계 세션: 최대 8라운드 × 라운드당 8호출
  (후보 8개, temp 1.0). 후보는 파싱·검증 통과 시 판정되고
  champion = objective argmax.
- **성공 = champion objective ≥ 0.78** (역사 분포 근거: 유효
  무작위 ~0.7+, A 중앙값 0.814, 상한 ~0.85). 도달 즉시 런 종료
  (조기 종료가 호출 절약을 지표에 반영).
- seed: 본실험 1~20, 파일럿 901~903 (불혼합).

## 조건 정의

- **조건 1 (요약만)**: 프롬프트 = DSL 스키마 + 현재 champion 스펙
  +champion objective + 요약 통계(라운드, 후보 수, 최고/평균).
- **조건 2 (장부)**: 조건 1과 프롬프트 동일. 차이는 **선택 측**
  뿐 — 장부(local 해상도, 규칙 문서 disposition)가 ① BLOCK 키
  후보의 champion 자격을 박탈하고 ② 감점 키 후보는 동점 시
  후순위. 실패 기록 verifier = "judge" (confidence medium).
  **계약 8항: 장부 내용은 프롬프트에 주입하지 않는다** — 기각된
  기억 기능과의 경계.
- 조건 2.5·3: 정의만 등록(이월) — 2.5 = 장부 + 확정(BLOCK 승격)
  권한을 중앙 판정기가 보유, 3 = 장부 + 프로토콜 채택·롤백
  (mission6 계열 채택 제도). **2→2.5가 장부 효과, 2.5→3이 권한
  분리 효과 — 실행 시 분리 보고, 합산 금지.**

## 지표 (동결)

- **1차: 성공당 총호출** = 조건별 총호출(실패 런 포함) / 성공 런
  수. 성공 0이면 미정의 — 파일럿 게이트가 선차단.
- 2차: 실패 원형 반복 횟수(같은 local 키의 검증 실패 재시도),
  잘못 확정된 판단 수(조건 2 오차단 — BLOCK이 박탈한 후보가
  실제 최고 objective였던 수), 상태 복구 호출 수(champion 하락
  후 재상승까지의 호출), 최종 성공률.
- 동시 집계: 후보 중복률(정규화 스펙 해시 동일), 고유 서명 수
  (local).
- 신뢰구간: 런 단위 부트스트랩 1,000회.

## 파일럿 (조건 1만, 등록 직후)

seed 901~903 × 8라운드 = **최대 192호출**. 판정: **성공률 > 0**
이면 본실험 진행. 0이면 1차 지표를 실패 원형 반복 횟수로 교체
하고 그 결정을 본실험 전에 문서화한다 (성공당 총호출이 미정의
되는 설계로 본실험 진입 금지). 목 파일럿(지출 0)이 실 파일럿에
선행한다 — 검증 순서 표준.

## 계측기 사고 기록 1 (2026-08-08, 1차 파일럿 무효)

1차 파일럿(seed 901~903, 192호출) 성공 0/3. 채널 점검 결과 —
파싱 191/192 정상인데 **objective > 0이 단 1건**: 프롬프트의
스키마 힌트가 실제 게이트와 달랐다 (보드 "3~8"로 오기 — 실제
3~5, scoring 1~2개 제한·SCORE_REACH k 3~12 누락 → 진단 표본
60/60 게이트 차단). 기준선 무능이 아니라 **계측기가 모델을
게이트 밖으로 유도**한 것 (시리즈 6건째, 파일럿이 설계 목적대로
본실험 전에 적발). 조치: 힌트를 check_constraints와 1:1 일치로
수정, 1차 파일럿 원자료는 `data/condexp_pilot_invalid_schemahint/`
격리, **재파일럿 (같은 seed, 태그 condexp_pilot2, ≤192호출)**.
예산 갱신: 192(무효) + 192(재) + 2,560(본) = 2,944 ≤ 3,000 —
재파일럿 실패 시 본실험 예산이 깨지므로 3차 파일럿은 없다
(그 경우 등록 분기대로 1차 지표 교체로 간다).

## 재파일럿 결과와 게이트 판정 (2026-08-08, 본실험 데이터 관측 전)

condexp_pilot2: **성공 3/3, 전부 1라운드** (champion 0.781/0.805/
0.817, 24호출). **게이트 통과 — 1차 지표 = 성공당 총호출 유지,
본실험 진행.**

**사전 예측 기록 (천장 위험, Rookery exp1 R4 계열)**: 파일럿
셋 다 1라운드 성공은 과제가 이 모델에 쉬울 가능성을 시사한다.
본실험에서 성공이 1라운드에 집중되면 두 조건의 성공당 총호출이
동률에 수렴하고 장부는 개입 기회(반복 실패) 자체를 얻지 못한다
— 그 경우는 판정 3분법의 "개선 없음"이 아니라 **"분별 불가
(천장)"로 기록**하며, 등록 문턱 0.78의 상향 재실험은 새 등록을
요한다 (이번 실험 내 변경 금지). 지금 이 문단은 본실험 숫자를
보기 전에 쓰였다.

## 실행 규율

- 조건 교차 배치: seed 순회하며 1↔2 교대 (시간 교란 방지).
- 실행 중 지표·프롬프트·규칙 변경 금지. 필요 시 그 시점까지 폐기.
- 중단 규칙: 예산 60%(1,800호출) 소진 시점에 완료 런 절반 미만
  → 중단, 사례 수 축소 재등록. 반쯤 돈 데이터 집계 금지.
- 가동 직후 채널 점검(스펙 파싱 성공률·판정 실행)을 표준 절차로.
- 주중 1회 계측기 점검: stale률·unknown률.
- 러너: 공통 resume (원자적 런 단위, 조건·seed 키).

## 판정 3분법

- 조건 2의 성공당 총호출이 유의 개선(부트스트랩 CI 비겹침) →
  장부는 닫힌 항목 (양의 판정).
- 개선 없음 → 장부는 기록 도구일 뿐 성능 장치 아님 — 이것도
  닫힌 항목 (음의 판정).
- 분산에 묻힘 → 아무것도 닫히지 않음. 해석하지 않고 설계 결함
  으로 기록, 재실행 전 검정력 분석 선행.

## 판정 (2026-08-09, 본실험 완주 — 40/40런, 840호출/상한 2,560)

집계: 골든 통과 `condexp_agg.py`, 원자료 `data/condexp_verdict.json`.

| 지표 | C1 (요약만) | C2 (장부) |
|---|---|---|
| 성공률 | 0.80 | 0.80 |
| 성공당 총호출 | 27.5 [CI 13.1, 54.0] | 25.0 [CI 11.4, 50.7] |
| 성공 라운드 분포 | 1R×14, 3R×1, 6R×1 | 1R×15, 3R×1 |
| 실패 원형 반복 | 24 | 24 |
| 잘못 확정된 판단 | 0 | 0 |
| 후보 중복률 | 0.060 | 0.032 |

**판정: 분별 불가 — 천장.** 사전 등록된 천장 분기(재파일럿 후,
본실험 데이터 관측 전 기입)가 그대로 발동했다: 성공의 90%가
1라운드에 몰려 두 조건이 수렴했고, **장부는 개입 기회(같은 키의
반복 실패 3회) 자체를 얻지 못했다** — BLOCK 발동 0, 오차단 0.
"개선 없음"이 아니다: 장부가 시험대에 오르지 못한 것이다.

**검정력 부족의 원인 (재등록 전 필수 기술)**: 문턱 0.78은 Haiku
가 라운드당 8후보로 즉시 넘는 높이다 (파일럿 3/3 1라운드가 이미
경고했다). 시리즈 세 번째 천장 사례 (Rookery exp1 R4, 코퍼스
v1 → 이번) — **제도의 가치는 모델이 한 번에 못 푸는 지점부터
나타난다**는 교훈의 재확인. 재실험 등록 지침: 문턱 ≥ 0.82
(역사 상한 ~0.85 근접) 또는 라운드당 후보 1개(탐색 폭 축소)
— 어느 쪽이든 새 등록·새 예산 주기를 요한다.

**닫힌 것**: "이 문턱·이 탐색 폭에서 장부 개입 사건은 발생하지
않는다" (실측). **열린 채 남는 것**: 장부의 이득 여부 — 단,
이번에는 판정식 누락이 아니라 사전 등록된 분기로 도달한 미결이다.
