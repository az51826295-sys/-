# shading 파라미터 실험 사전 등록 v0

작성 2026-08-27 15:0x. **그림 보기 전 등록.** PixelLab 무료 생성 **2회** 소모.

## 1. 무엇을 묻나

사장님 질문(2026-08-27): *"퀄리티가 부족한 게 무료 옵션이라서인가, 니가 프롬프트를
못 넣은 건가, 우리 엔진이 잘못된 건가? 그림자 표현도 없고…"*

**내 답은 "내 프롬프트"다.** 근거는 API 명세다 — `/create-tileset` 은 파라미터가
26개인데 우리는 3개만 보냈고, 그중 `shading`(5단계)·`detail`(3단계)·`outline`
(4단계)은 **한 번도 안 보냈다.** 하지만 명세에 있다는 것과 실제로 그림이 달라지는
것은 다른 이야기다. 그래서 잰다.

## 2. 판정식 (동결 — 그림 보기 전)

같은 `seed`, 같은 설명, 같은 크기로 두 번 주문한다. **`shading` 만 다르다.**

| 갈래 | shading | detail | outline |
|---|---|---|---|
| A (지금까지의 우리) | 보내지 않음 | 보내지 않음 | 보내지 않음 |
| B | `highly detailed shading` | `highly detailed` | `selective outline` |

**측정**(기계가 재는 것, 사람 눈이 아니다):

| 측정 | 왜 이게 음영인가 |
|---|---|
| `색 수` | 음영은 중간톤을 요구한다. 없으면 색이 적다 |
| `명도 계단 수` | 타일 안에서 서로 다른 밝기 값의 개수 |
| `명도 범위` | 가장 밝은 픽셀과 가장 어두운 픽셀의 차 |

**판정** (셋 다 미리 정한다):

- **shading_helps** — B가 세 측정 **전부**에서 A보다 크다.
- **shading_no_effect** — B가 세 측정 전부에서 A와 같거나 작다.
- **undefined** — 섞여 나오거나, 주문이 실패하거나, 씨앗이 안 먹는다.

## 3. 미리 적어 두는 약점

- **표본 1 대 1이다.** 씨앗을 고정해도 파라미터가 바뀌면 생성 경로가 달라질 수
  있다. 그러므로 이 실험은 **"이 파라미터가 그림을 바꾸는가"** 까지만 말한다.
  "얼마나 좋아지는가"는 말하지 않는다.
- **좋아졌는지는 사람이 정한다.** 위 세 측정은 "음영이 들어갔나"를 재지
  "예쁜가"를 재지 않는다. 예쁨은 08-27에 **영구 human_gate** 로 선언했다.
- 무료 잔량이 21회다. 이 실험이 2회를 쓴다. 남는 19회.

## 4. 안 하는 것

- 그림을 보고 판정식을 고치는 것.
- B가 좋아 보인다고 "우리 엔진 문제였다"로 결론을 미루는 것 — 엔진은 그림을
  그리지 않는다. 엔진의 오늘 결함(24색 상한·스모크 구멍)은 별개로 이미 고쳤다.
