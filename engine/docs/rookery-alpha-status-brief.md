## 1. 이 프로젝트가 무엇인가

**Genesis / Rookery**: "검증 제도를 갖춘 LLM 루프가 스스로 코드를
개선할 수 있는가"를 실험으로 검정해 온 프로젝트. 2026년 7~8월에
실험 6 → 7A → 7B → 7C → 7D → Rookery 1~3a → §6.9~§9.4까지 진행.

2026-08-03에 **주 레인을 연구에서 제품화로 전환**. 목표는
"스스로 진화하는 두뇌"가 아니라 **"사람 없이 일하고 실패를 안전하게
기록하며 스스로 멈출 줄 아는 신뢰 가능한 몸"**(Rookery Alpha).

## 2. 연구 단계에서 확정된 것 (제품 설계의 근거)

### 2.1 살아남은 결론

- **검증 제도는 작동한다.** 블라인드 평가 + 롤백이면 무작위 변이로도
  프로토콜이 개선된다 (실험 6).
- **관측을 받은 LLM 제안자는 표본 효율 20배**, 끌개 탈출 10/10 vs
  무작위 0/5 (7A·7B).
- **구조적 단계 분리만 실코드 고착을 열었다** — 탐색→가설→기계 검증→
  분화 배정 (§6.11). 이것이 현재 **유일하게 살아남은 기제 후보**.

### 2.2 기각·미입증된 것

| 대상 | 결과 | 근거 |
|---|---|---|
| 누적 기억(프롬프트 이력) | **3회 기각** | P36, P38(패딩 통제), P39b |
| 무의미 패딩 vs 점수 이력 | 패딩이 더 나음 (돌파 4/5 vs 2/5) | 7C |
| 부정 증거 레지스트리 | 독립 기여 없음 | §6.12 |
| proposer-측 IA | 위치·품질 모두 미입증, 소표본 방향이 확증에서 **반전** | §6.14, §6.18 |
| 온도 조작 | API 상한 1.0으로 검정 불가 | P40 |

> **인용 시 주의(사양 §0)**: "기억이 실패했다"로 일반화 금지.
> 정확한 범위는 **"Haiku 4.5 · 이 과제군 · 프롬프트에 누적 이력·점수·
> 서명을 추가하는 방식"**. 레지스트리·구조화 상태·외부 DB·검색 기반
> 기억은 **검정된 바 없음**.

### 2.3 제품 경계를 정한 발견: 검증의 비대칭

- 기존 동작 파손(**회귀**) = 기존 테스트로 **잡기 쉬움**
- 새 요구사항 미구현(**불완전**) = 기존 테스트로 **원리적으로 못 잡음**
  (판별 테스트가 hidden이므로 selector에 노출 불가)

§8.3 실증: 회귀형 표적 후보 **4/4 배제 성공**, 불완전형 9건은
**전부 매핑 성공했으나 전부 통과**(못 잡음). 이는 selector 결함이
아니라 **정보 경계**.

→ **Alpha는 명세가 명확하고 기계 판정 가능한 작업만 자동화한다.**

### 2.4 계측기 사고 4건 (제품 설계에 가장 큰 영향)

연구 중 **결론을 바꿀 뻔한 계측기 오류가 4건**, 전부 발표 직전에 잡힘:

1. **§8.3** 사건 정의에 fail→fail 테스트 포함 (판별력 0인 것을 사건으로)
2. **§9.1** Windows pytest 역슬래시 노드 ID → 모든 집합 교집합이 공집합.
   **버그가 낸 답(0/9)과 정답(0/9)이 같은 숫자**였고, 역검증만이 갈랐다.
3. **§9.2** stale 소진 목록 → 이미 5개 실험에 쓴 과제가 신규로 잡힘
   (3/4로 보고할 뻔 → 2/4로 정정)
4. **§9.3** 전 저장소 0건 → 이번엔 **진짜**였으나, 앞의 3건 때문에
   4개 저장소 깔때기를 추적해 검증 후에야 기록

**교훈**: 잘못된 숫자를 그럴듯한 결과로 만드는 버그가 일반 실행
오류보다 위험하다. → Alpha에 **Validator Auditor** 계층 신설.

### 2.5 연구 레인 종결 상태

- selector-측 IA 트랙: **종결** (§8.5) — 회귀 보호는 제품 계층으로 이관
- 불완전형(INC) 코퍼스: **부족으로 종결** (§9.4, 유효 2/4)
  - 구조적 원인: **신형 커밋은 거의 단일 함수 수정 / 다중 함수 수정은
    구형이라 py3.12 미가동** — 이중 구속
- 신규 대규모 코퍼스 채굴 **중단**. 연구는 Alpha 가동 후 저비용 보조
  레인으로만.

## 3. Alpha 사양 요약 (동결됨)

### 3.1 합격 기준

**필수 (하나라도 미달 시 불합격)**
1. 7일 연속 무인 실행
2. 서버 재시작 후 자동 복구
3. 완료 작업 재실행 **0건**
4. 예산 초과 **0건**
5. 격리 밖 파일 수정 **0건**
6. 위험 명령 실행 **0건**
7. 판정기 불일치 시 자동 정지 **100%**
8. 일일 보고 누락 **0건**

**성능**: 검증 가능한 실제 작업 ≥20건, 자동 완전 처리 ≥5건,
회귀 유발 패치 자동 채택 0건, 실패 이유 분류율 ≥90%

**"스스로 진화"는 합격 조건에서 제외, 관찰 지표로만.**

### 3.2 예산

- 월 총 6만 원 (서버 1~2만 + API 3만)
- 단계: **35k 경고 / 40k 고비용·후보3 차단 / 45k 신규 외부 API 중지**
- 50k는 어떤 경로로도 도달 불가
- 로컬 작업(테스트·로그 정리·일일 보고)은 전 단계에서 계속 허용

**실측 단가**: §6.18에서 351호출 ≈ $2.5 → 호출당 약 $0.007
→ API 3만 원 ≈ **월 3,000호출 = 하루 약 100호출**.
이 제약이 "탐색형이 아니라 신중형" 설계의 근거.

### 3.3 자동화 범위

- 격리 브랜치 **내부**의 수정·실험·채택·롤백은 사람 승인 없이 자동
- 검증된 결과는 **자동 PR 생성**
- **운영 브랜치 자동 머지는 Alpha에서 비활성화**
- 차단: 위험 명령, 비밀정보 접근, 외부 배포, 결제·권한 변경

### 4.2 각 모듈의 핵심 설계 결정

**store.py** — SQLite. 이유: 다중 worker(조건 5)와 하드 킬 복구(조건 11).
`claim`이 단일 `BEGIN IMMEDIATE` 트랜잭션이라 두 worker가 같은 작업을
못 집는다. **종료 훅에 의존하지 않음** — 정전 시엔 훅이 안 돌기 때문에
**리스(lease) 만료로만** 복구. 연결은 **스레드별로 분리**(공유 연결은
동시에 두 트랜잭션을 못 가짐 — 다중 worker에서 발견된 실제 버그).

**budget.py** — 누적 합계가 아니라 **예약 원장**. 단순 합계는 경쟁
조건이 있음(두 worker가 44,000원을 동시에 읽고 둘 다 진행).
`reserve → settle/release/expire` 생명주기, 한도 검사와 INSERT가 **같은
트랜잭션**. 내부 통화 KRW 통일, 각 행에 원본 USD·환산율 저장.
failure code 분리(`api_credit_exhausted` ≠ `budget_exceeded_internal`).
실제>예상이면 delta 기록 + **다음 호출 1회 차단**(원샷 차단기).

**safety.py** — **허용 목록 방식**. 차단 목록은 첫 미지의 철자에 짐.
셸 메타문자(`|`, `&&`, `;`, backtick, `>`) 차단이 중요 — 파이프로 두
번째 명령을 밀어넣는 우회를 막음. push는 `rookery/*` 브랜치만,
강제·삭제 금지. **auto_merge는 상수 False**.

**isolation.py** — 작업당 워크트리 + 임시 브랜치. 모든 쓰기가
`resolve()`를 거쳐 **심볼릭 링크 해석 후** 격리 이탈 여부 판정.
`.git` 내부도 차단(`.git/hooks`에 쓰면 다음 git 명령에 실행 = 한 단계
거친 탈출). 정리는 멱등, task id로만 식별 → 크래시 잔재 자동 회수.

**auditor.py** — **같은 계산을 반복하지 않고 다른 불변식 5종**:
① 증거 테스트가 패치 전에 실제 실패했는가 (§8.3 사고)
② 정답 패치는 통과하는가 (아니면 테스트가 무효)
③ 이미 소진된 과제인가 (§9.2 사고)
④ 전부 0인가 → 경로·파싱부터 의심 (§9.1 사고)
⑤ 갑자기 완벽한가 → 천장·누출, 먼저 "패치가 테스트를 고쳤나"
채택은 **validator 승인 ∧ auditor 동의** 둘 다 필요. 불일치 시 정지는
**내구적**(재부팅으로 안 풀림, 사람이 `resume()`해야 함).

**intake.py** — 실패 로그를 그대로 과제화하면 **자기 계측기 버그를
학습**함. 5게이트: 범주(일시 API 오류·잔액·감사 불일치·환경 실패는
**과제가 될 수 없음**) → 재현(flaky 거부) → 평가기 정상 → 중복(노이즈
정규화 지문) → 가치(파일·테스트 특정 못 하면 패치 대상 없음).

**risk.py** — 위험도는 **모델 의견이 아니라 기계 신호**(재현 테스트
유무, 위치 특정, 커버리지, 파일 수, 이전 실패, 변경 유형).
low 1 / medium 2 / high 3 후보, 40k 이후 전부 1. 고위험은 40k 이후
**축소가 아니라 보류**(후보 1개 고위험은 §6.9~6.11에서 3번 실패한
첫 가설 고착 상황).

**report.py** — "누락 0건"은 잊지 않아서가 아니라 **누락을 탐지·백필**
할 수 있어서 달성. 날짜 키 행 + `missing_days()` + `ensure()` 백필
(꺼져 있던 날은 "지연 생성" 표시). 합격 조건을 **원장에서 채점**.

**worker.py** — 게이트 순서가 곧 설계:
```
startup recovery → halt 확인 → 예산 확인(외부만) → 원자적 claim
→ 격리 → 후보 계획 → handler → validator → auditor
→ 채택/롤백 → 완료/실패
```
크래시 경로에 **별도 코드 없음** — 리스 만료 경로와 동일.

### 4.3 구현 중 발견된 실제 결함 (전부 테스트가 잡음)

1. **SQLite 스레드 귀속** — 공유 연결로는 다중 worker 불가 →
   스레드별 연결로 수정
2. **일일 보고 비일관** — 저장은 멱등인데 반환값은 매번 재계산 →
   전달된 보고서와 다른 텍스트를 받을 수 있었음 → 저장본이 정본
3. **로컬 작업 부당 보류** — 예산 기반 보류가 비용 0인 로컬 작업에도
   적용돼 엔진이 무의미하게 정지
4. **빈 큐에서 무한 대기** — 배치 실행이 종료 안 됨 →
