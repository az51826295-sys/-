# 두근도트 업로드 키 재설정 — 앱 아이콘을 바꾸려면 이게 먼저다 (10-24)

## 왜 필요한가 (실측)

| | |
|---|---|
| **스토어 아이콘** (Play Console 에 따로 올리는 그림) | **새것** ✅ — 실제로 받아서 눈으로 확인함 |
| **앱 런처 아이콘** (AAB 안에 들어감) | **1.0.7 의 옛것** ❌ |

사장님이 "지우고 다시 깔아도 똑같다" 고 하신 것이 맞다. 다시 깔면 스토어의 **1.0.7** 이 오고,
런처 아이콘은 **그 안에** 들어 있다. 아이콘 파일은 09-29 에 새것으로 바뀌었고 **1.0.8 은
10-18 에 이미 빌드까지 돼 있다**(`app/build/outputs/bundle/release/app-release.aab`).
못 올리는 이유는 하나 — **서명 열쇠 비밀번호를 모른다**(`android.keystore` 파일은 있다).

사장님 선택(10-24): **업로드 키 재설정**.

## 순서

### ① 새 업로드 열쇠 만들기 (사장님이 비밀번호를 정한다)

`keytool` 은 여기 있다(실측): `C:\Users\az518\AppData\Local\rookery-android\jdk\bin\keytool.exe`

```
cd C:\Users\az518\Desktop\dot-android
& "C:\Users\az518\AppData\Local\rookery-android\jdk\bin\keytool.exe" -genkeypair -v -keystore upload-new.keystore -alias upload -keyalg RSA -keysize 2048 -validity 9125
```

- 묻는 비밀번호는 **사장님이 새로 정하고 적어 두신다.** 이번엔 꼭 어딘가에 남긴다
- 이름·조직 같은 것은 아무렇게나 적어도 된다(구글이 안 본다)
- 만들어진 `upload-new.keystore` 는 **절대 지우지 않는다** — 앞으로 모든 업데이트에 쓴다

### ② 구글에 낼 증명서 뽑기

```
& "C:\Users\az518\AppData\Local\rookery-android\jdk\bin\keytool.exe" -export -rfc -keystore upload-new.keystore -alias upload -file upload_certificate.pem
```

### ③ Play Console 에 요청

`Play Console → 두근도트 → 테스트 및 출시 → 앱 무결성 → 앱 서명`
→ **업로드 키 재설정 요청** → 위 `upload_certificate.pem` 올리기

- 구글 처리에 **1~2일** 걸린다
- 기존 사용자는 영향 없다. 앱 서명 키는 구글이 들고 있고 **업로드 열쇠만** 바뀐다

### ④ 승인된 뒤 — 1.0.8 올리기

새 열쇠로 다시 서명해서 올린다. 그 시점에 명령은 내가 만들어 드린다.
올라가면 **런처 아이콘이 새것으로 바뀐다.**

## 내가 못 하는 자리

열쇠를 만들고·드러내고·입력하는 동작은 전부 내 안전장치가 막는다(10-24 에 세 번 걸렸다).
그래서 ①②는 사장님 손이고, 나는 명령과 확인만 맡는다.

## 교훈

**업로드 열쇠 비밀번호는 잃으면 1~2일이 날아간다.** 이번엔 만들자마자 적어 둘 것.

## 결과 (10-24 밤 / 10-25)

- 새 업로드 열쇠 `dot-android/upload-new.keystore` 생성 — **비밀번호는 사장님만 안다**
- 증명서 `dot-android/upload_certificate.pem` 뽑음

  화면 글: *"이 앱의 업로드 키 재설정 요청이 대기 중입니다."*
- 사유는 "키 저장소의 비밀번호를 잊어버림" 으로 냈다(사실 그대로)

### 승인 뒤 할 일
1. `dot-android` 에서 1.0.8 을 **새 열쇠로 서명**해 AAB 생성
2. Play Console 에 업로드 → 출시
3. 그러면 **런처 아이콘이 새것으로 바뀐다**

### 콘솔이 안 열리던 진짜 까닭 (10-24)
내가 들고 있던 **개발자 ID 가 틀렸다**. 모든 Play Console 주소가 `/developers` 로 튕겼고
나는 "콘솔이 자동 조작을 막는다" 고 잘못 적었다.

- 틀림: `5668267133392661954`
- **맞음: `6421367471604909029`**

앱 ID 는 맞았다(두근도트 `4975959971490762808`). 계정 고르는 화면에서 한 번 고르면 들어가진다.
**주소가 홈으로 튕기면 사이트 탓하기 전에 ID 부터 의심할 것.**

### 내 손이 막히는 자리
`.pem` 같은 열쇠 파일 **업로드**는 내가 못 한다(안전장치). 양식 작성·사유 선택까지는 내가 하고,
파일 고르기와 마지막 제출만 사장님이 누르신다.
