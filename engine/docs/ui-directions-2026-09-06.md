## 공통 패턴 다섯

1. **결과가 대화 옆에 늘 있다.** Rosebud 는 게임 화면, Bezi 는 Scene/Game 탭, Meshy 는 모델 뷰어. 대화만 있는 곳은 없다.
2. **빈 화면으로 시작시키지 않는다.** 템플릿(Rosebud), 리믹스(Astrocade), 남의 갤러리(Meshy).
3. **만들기 전에 계획을 보여 준다.** Bezi 의 Plan 은 요약 세 줄 + 할 일 목록이고, 사람이 보고 나서 Thread 가 돈다.
4. **단계가 버튼이다.** Meshy: 만들기 → 텍스처 → 리깅 → 동작. 한 번에 다 하지 않고 한 칸씩 사람이 누른다.
5. **AI 가 한 일을 표시하고 되돌린다.** Unity 는 AI 에셋에 태그, 되돌리기, 자율성 권한. 크레딧 잔량은 다들 상시 노출.

## 로키의 지금

- 대화창 하나. 결과는 유니티 창으로 가고, 웹에서는 사진 셋(화면·얼굴·걷기)이 턴에 붙는다.
- 계획은 없다. 시키면 바로 만든다(콘셉트 → 30 크레딧 → 리깅 → 판정). 되묻기는 오늘 콘셉트 검수에 처음 들어갔다.
- 판(버전) 개념이 없다. "고쳐 줘" 가 지난 판 위에 덮어쓰고, 되돌리기는 없다.
- 크레딧·비용은 화면 위 한 줄(라우팅 알림)뿐이다.

## 제안: UI 방향 셋

### A. 사진 대화형 (지금 것 다듬기)
지금 대화창을 유지하고, 턴마다 **판 카드**(사진 셋 + 판정 + 되돌리기 버튼 + 비용)를 붙인다. 만들기 전에
**계획 카드**(무엇을, 몇 크레딧, 예상 시간)를 먼저 내고 "진행" 을 누르면 돈다.
- 장점: 바꾸는 양이 적다(하루). 지금 배관 그대로.
- 단점: 결과가 흘러 내려간다. 지금 판이 어느 것인지 스크롤해야 안다.

### B. 두 칸: 대화 + 현재 판 (Rosebud·Bezi 식) — **추천**
왼쪽 대화, 오른쪽 **현재 판 패널**: 사진 셋 크게, 판정표(통과/떨어짐 줄), 파일 목록, 판 목록(1판·2판·3판 —
클릭하면 그 판으로 되돌림), 크레딧 잔량. 만들기 전에는 같은 자리에 **계획**(할 일 목록 + 비용)이 뜨고
"진행/고쳐 말하기" 두 버튼. 첫 화면은 빈 칸 대신 **시작 카드 넷**(지금도 있음) + **지난 판 갤러리**.
- 장점: 사장님이 말한 "보여 주고 되묻기" 가 화면 구조 그 자체가 된다. 판을 고르는 것이 클릭 하나.
- 단점: 이틀. 판 저장(버전) 배관이 필요하다 — 지금은 덮어쓴다.

### C. 유니티 안으로 (Bezi·Unity 식)
로키 창을 유니티 안에서 넓혀 대화·판·되돌리기를 전부 에디터 안에 둔다. 웹은 접수와 결제만.
- 장점: 결과가 바로 옆에 살아 있다(게임 화면이 진짜다). 되돌리기는 유니티 것을 쓴다.
- 단점: 유니티를 깐 사람만 쓴다. 웹 사용자(첫 방문)는 아무것도 못 본다. 로키가 "뭐든 다 하는 회사" 라면 웹이 앞문이어야 한다.

## 왜 B 인가

사장님이 말한 세 방향(입력을 좋게 / 보여 주고 되묻기 / 잘 나오는 종류로 이끌기)은 전부 **오른쪽 칸**에서
일어난다. 계획 카드가 "이 주문은 이렇게 나옵니다(사진 두 장), 이쪽이면 확실합니다" 하고 되묻는 자리이고,
판 목록이 사용자가 고르는 자리다. A 는 그것을 대화 흐름에 묻고, C 는 웹 사용자를 잃는다.
그리고 B 는 C 로 가는 길이다 — 오른쪽 칸을 그대로 유니티 창에 옮기면 C 가 된다.

## 방향 실험과 잇기

내일 첫 회차 "방향 실험" 은 같은 주문 하나로 세 방향을 돌리고 사진을 나란히 놓는 것이다. 그 결과를 보여 주는
화면이 곧 B 의 오른쪽 칸이다. 실험이 UI 를 만들고, UI 가 실험을 보여 준다.

## 내일 순서 (사장님 결정 뒤)

1. B 확정이면: 판 저장(버전) 배관 — 산출물에 `판 번호` 와 `이전 판`, 되돌리기 = 이전 판을 현재로.
2. 오른쪽 칸 첫 판: 사진 셋 + 판정표 + 판 목록 + 크레딧. 계획 카드는 그다음.
3. 방향 실험 등록: 주문 하나(사장님이 고름), 세 방향, 판정식은 돌리기 전에 얼림.
