# 고사양 — WebGL 3D (228회차 10-01)

사장님 "다른 고사양 게임 만들어봐".

## 왜 WebGL 인가

브라우저에서 "고사양" 은 **2D 캔버스를 벗어나는 것**이다. 지금까지 만든 것은 전부 `getContext('2d')` 였다 —
벽돌깨기·두더지·플랫포머·타워 디펜스 24판이 다 그랬다. 3D 는 **한 번도 없다.**

게다가 **라이브러리를 못 쓴다.** 판은 바깥 요청이 막힌 창에서 돌아서 three.js 를 불러올 수 없다
(꾸러미로 넣을 수도 있지만 600KB 라 프롬프트가 터진다). 그러니 **셰이더와 행렬을 직접 짜야 한다** —
여태 시킨 것 중 가장 어려운 일이다.

## 배운 것

1. **로키는 WebGL 로 갔다.** 2D 로 도망가지 않고 `webgl2` 를 켜고 셰이더를 썼다 — 거기까진 됐다.
2. **그런데 까맣다.** 60장/초로 "잘 돌면서" 아무것도 안 보인다. 3D 는 행렬 한 칸이 틀리면 전부 사라진다.
3. **고리는 8바퀴를 돌고도 못 고쳤다.** 심판이 본 것은 `C05 화면이 안 바뀐다` 하나뿐이고 나머지 12개는 모름이었다.
   까만 화면에서는 **무엇이 틀렸는지 알 길이 없다** — 사진에도 안 보이고 숫자에도 안 잡힌다.
   2D 는 틀려도 뭔가 보여서 심판이 짚을 수 있었는데, 3D 는 그 실마리가 통째로 없다.
4. 그래서 다음에 3D 를 시킨다면 **고리에 눈을 하나 더 달아야 한다** — 예: 캔버스 픽셀의 색 가짓수·밝은 점 수
   (내가 이 자에서 쓴 것). "까만가" 는 한 줄이면 재는데, 지금 고리에는 그 한 줄이 없다.
