# 유니티에서 로키 자산 가져오기

1. `unity/Editor/RookeryImporter.cs` 를 유니티 프로젝트의 `Assets/Editor/` 로 복사
2. 유니티 메뉴 → **Window → Rookery → 자산 가져오기**
3. 주소와 열쇠를 넣고 **가져오기**

**열쇠**는 회사마다 하나입니다. 읽기 전용이라 이걸로는 아무것도 만들거나
지울 수 없습니다.

## 무엇이 오는가

**승인된 산출물의 통과 후보만** 옵니다. 검토 중이거나 심판이 떨어뜨린 것은
서버가 보내지 않습니다 — 게임에 들어가는 것과 매니저가 승인한 것이 같아야
하고, 그 둘이 어긋나면 승인이 절차가 아니게 됩니다.

파일마다 `.rookery.json` 이 같이 저장됩니다. 어느 산출물에서 왔고 무엇으로
통과했는지가 거기 있습니다 — 반년 뒤에 "이 그림이 어느 판정을 통과한 것인지"
를 물을 사람은 반드시 생깁니다.

## 픽셀 아트 주의

가져온 뒤 Import 설정에서:
- **Filter Mode: Point (no filter)** — 안 그러면 흐려집니다
- **Compression: None** — 안 그러면 색이 뭉갭니다
- **Pixels Per Unit** — 타일 크기에 맞춰서

# 컴파일 오류 고치기

`RookeryFixer.cs` 도 같이 `Assets/Editor/` 에 넣으십시오.

메뉴 → **Window → Rookery → 컴파일 오류 고치기**

## 왜 이 방향인가

로키는 **생성한 코드를 실행하지 않습니다.** 서버에서 남의 코드를 돌리면 그건
임의 코드 실행이고, 그 문을 열면 회사의 모든 열쇠가 그 코드 안에 놓입니다.
그래서 로키가 낸 코드는 지금까지 *"파싱은 됩니다"* 까지만 말할 수 있었습니다.

**유니티는 자기 프로젝트를 자기가 컴파일합니다.** 그 오류를 보내 주면 로키는
아무것도 실행하지 않고 진짜 오류를 알게 됩니다 — 실행의 위험은 원래 있던 자리에
그대로 있고, 고치는 일만 넘어옵니다.

## 무엇을 하고 무엇을 안 하는가

- 오류가 **가리키는 파일만** 보냅니다. 프로젝트 전체를 보내면 느리고 비싸고,
  상관없는 코드가 답을 흐립니다.
- 받은 수정을 **자동으로 덮어쓰지 않습니다.** 무엇이 어떻게 바뀌는지 보여 주고
  파일마다 따로 누릅니다 — 한 번에 다 적용하는 버튼을 두면 확인하지 않고
  누르게 되고, 그러면 보여 준 의미가 없습니다.
- 적용하면 원본이 `*.before-rookery` 로 남습니다. 고침이 더 나빴을 때 되돌릴
  수 있어야 합니다.
- 원인이 우리가 못 보는 곳(빠진 패키지, 유니티 버전, 다른 파일)에 있으면
  **고치지 않고 "못 고침"으로 적습니다.** 짐작으로 고친 코드는 오류를 다음
  자리로 옮길 뿐입니다.
