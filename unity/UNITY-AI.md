# 유니티 안의 AI — 무엇을 할 수 있고, 우리와 어떻게 나눌 것인가

**정직 조항 먼저.** 아래는 유니티가 발표한 기능 목록에서 온 것이고, 나는 이
프로젝트에서 **직접 돌려 본 적이 없다.** 특히 픽셀 아트에 대한 품질은 확인되지
않았다 — 유니티의 생성기는 3D PBR 텍스처를 겨냥해 만들어졌고, 도트는 그 도구가
잘하는 일이 아닐 가능성이 높다. 쓰기 전에 한 번 뽑아 보고 우리 판정기에 넣어
보는 것이 순서다.

---

## 1. Unity AI Assistant (에디터 안의 대화)

에디터에 붙어 있는 대화창이다. 할 수 있는 것:

- **에디터 사용법 질문** — "이 컴포넌트 어떻게 쓰나", 문서를 뒤져서 답한다
- **C# 코드 생성·설명·수정** — 스크립트를 만들거나, 있는 것을 읽고 왜 안 되는지 말한다
- **프로젝트 안에서 찾기** — 에셋·설정·오브젝트를 말로 찾는다
- **에디터 조작** — 메뉴를 대신 눌러 준다

**우리와 겹치지 않는다.** 이건 *에디터를 쓰는 일*을 돕고, 로키는 *무엇을 만들지
정하고 나온 것을 판정한다*.

## 2. Unity AI Generators (에디터 안의 생성)

에디터 안에서 자산을 만든다:

- **Sprite** — 2D 이미지
- **Texture / Material** — 3D 표면 (여기가 이 도구의 본령이다)
- **Animation** — 캐릭터 동작
- **Sound** — 효과음
- **Behavior** — 상태 기계 초안

**비용:** 유니티의 AI Points 를 쓴다. 무료가 아니고, 구독 등급에 따라 배분된다.
**요구:** Unity 6.2 이상.

## 3. Unity Inference Engine (게임 안에서 도는 AI)

예전 이름 Sentis. **ONNX 모델을 게임 런타임에서 돌린다.** 서버를 안 거치고
플레이어 기기에서 돈다.

이게 우리 게임 계획과 직접 닿는 자리다 — 메모리에 적힌 *"Genesis 루프로 배우는
NPC"* 는 결국 게임 안에서 무언가가 돌아야 하고, 그 자리가 여기다.

할 수 있는 것: 분류·예측·간단한 정책. 큰 언어 모델을 통째로 돌리는 것은 아니다.

---

## 우리와 어떻게 나눌 것인가

각자 잘하는 것만 시킨다. 겹치는 데서 둘 다 하면 **계측기가 두 벌이 되고, 두 벌은
언젠가 서로 다른 답을 낸다.**

| 일 | 누가 | 왜 |
|---|---|---|
| 무엇을 만들지 정한다 | **로키** | 설계도·능력 매칭·고용이 여기 있다 |
| 그림을 만든다 | **양쪽 다 가능** | 유니티 생성기 / GPT 이미지 |
| **설계도에 맞는지 판정한다** | **로키(genesis)** | 계측기는 한 곳에만 있어야 한다 |
| 여러 개 중 고른다 | **사람** | 영구 human_gate |
| 에디터 안에서 손보기 | **유니티 Assistant** | 우리가 할 일이 아니다 |
| 게임 런타임 AI | **Unity Inference Engine** | 우리 서버가 프레임마다 돌 수 없다 |

### 그래서 협업은 이 모양이다

```
유니티 AI 가 에디터에서 스프라이트를 뽑는다
        ↓  (Rookery 창에서 "판정하기")
로키가 색·채도·명암폭·게임 바닥 대비로 잰다
        ↓
통과 / 탈락 + 왜 떨어졌는지
        ↓
사람이 고른다
```

**유니티가 만든 것도 우리 판정을 받는다.** 그게 협업의 요점이다 — 어디서
나왔든 같은 자로 재야 화면이 한 세계가 된다. 지금까지 그 게임의 자산이 제각각이던
이유가 정확히 그것이었다: 저마다 다른 경로로 들어왔고 아무도 같은 자로 재지 않았다.
